# v1.36 / Issue #137 #23 PRN-005 — 80mmレイアウト

## 仕様対応

初版完成チェックリスト #23 `PRN-005 80mmレイアウト` を、詳細仕様書 v2.5 の80mmレシート要件および受入 AT-022 と突合する。

- 80mmロール紙は `ReceiptPaper.MM80` = 48論理桁。
- 58mm / 80mm は同一の構造化 `ReceiptData`、税計算結果、支払内訳を使用し、紙幅によって業務データや計算結果を分岐しない。
- 紙幅差は折返し・右寄せ・区切り線等の表示レイアウトだけに反映する。
- 同一取引を58mm / 80mmで描画した場合、商品名、税区分記号、商品金額、合計、支払、釣銭等の業務内容が一致することを回帰テストで固定する。

## 実装

- `ReceiptPaper.MM80`: 80mm / 48桁。
- `ReceiptRenderer`: 58mm / 80mmで共通。紙幅は `paper.charsPerLine` のみから取得する。
- `ReceiptLineWrapV136`: 全角=2、ASCII=1の共通論理幅で、48桁を超える長商品名や備考を欠落させず折り返す。
- 金額行は既存 `amountLine()` を共通利用し、右側の金額表示を優先する。
- 税計算、売上、支払、釣銭に紙幅条件を持たせない。

## 自動テスト

`V136Receipt80mmLayoutTest.kt` で以下を確認する。

1. 80mmが48論理桁であること。
2. 長商品名と税記号を欠落させず48桁以内で折り返すこと。
3. 大きな商品金額を右端まで完全表示すること。
4. 同一の `ReceiptData` を58mm / 80mmで描画し、商品・税記号・金額・合計・支払・釣銭の内容が双方に存在すること。
5. 58mmは32桁、80mmは48桁を超える行を生成しないこと。
6. ASCII / 日本語混在文字列を折り返しても全文字を保持すること。

## 実機確認

コード・自動テストとは別に、最終統合受入で80mm実プリンターによる印字を確認する。

- 長商品名の折返し位置と実プリンター字幅。
- 大きな数量・単価・金額の右寄せと欠落有無。
- 58mm / 80mmで同一取引の金額・税・支払・釣銭が一致すること。
- 日本語全角 / ASCII混在時の実印字幅。

実機未確認の段階ではIssue #137の完了条件を満たしたとは扱わない。
