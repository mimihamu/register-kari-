# v0.96 保留伝票フロー レスポンシブ仕様

## 目的

販売中に使用する SCR-200「伝票一覧」と SCR-201「伝票分割」を、800×480級の小画面およびAndroidフォント倍率を上げた環境でも操作可能な構成へ改善する。

## SCR-200 伝票一覧

### Compact

- 共通 `rememberRegisterResponsiveMetrics()` を使用する。
- 作業中取引の退避案内、結合中案内、メッセージ、伝票一覧の左右余白を共通Compact余白へ合わせる。
- 伝票名・作成日時・担当・点数・金額を情報行として表示する。
- `名称変更` / `削除` / `呼出` を独立した操作行へ分離する。
- `結合` / `分割` および結合確定系操作を別行として表示し、横方向の見切れを防ぐ。
- 名称変更時は伝票名入力欄を全幅、その下に `取消` / `保存` を配置する。
- 結合元案内は本文と取消ボタンを縦配置する。

### 通常画面

- 従来の横並び操作を維持する。
- 呼出ボタン幅 `105dp`、退避付き呼出 `145dp` を維持する。
- 名称変更時の保存ボタン `100dp` を維持する。

## SCR-201 伝票分割

### Compact

- 共通レスポンシブ余白・パネル間隔を使用する。
- 分割元 `1.2`、分割先 `0.8` の比率で2ペインを確保する。
- 移動数量入力幅を `108dp` とする。
- 分割先サマリを縦スクロール可能にする。
- タイトル、補足文、明細文字サイズと余白をCompact向けに縮小する。

### 通常画面

- 分割先固定幅 `350dp` を維持する。
- 移動数量入力幅 `130dp` を維持する。

## 変更しない業務仕様

- 現在のカートがある状態で別伝票を呼び出す際の安全退避処理。
- 伝票名称変更の最大文字数制限。
- 伝票削除の2段階確認。
- 伝票結合時の元伝票削除条件。
- 伝票分割時の数量検証。
- 行値引の数量比按分。
- 税スナップショットの双方維持。
- `HeldTicketOperationsUiPolicy.validateSplit` による確定可否。

## データ保護

本対応はUIレイアウト変更のみで、売上SQLite、Sales Journal、Drive JSON、Outbox、バックアップDB、ロールバックDB等の削除・上書き処理を追加しない。
