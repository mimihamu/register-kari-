# v1.15 バックエンド／データ原子性強化

## 目的
画面仕様を増やさず、SQLiteを正本とする業務データの競合耐性をまとめて強化する。

## 印刷キュー
- 売上レシートは PENDING/RETRY から PRINTING への遷移を状態・試行回数付きCASでclaimする。
- 自動印刷と手動印刷は送信前に同じclaim APIを通る。
- 完了は PRINTING からだけ確定し、既にCOMPLETEDならno-opとする。`sales.print_count` は完了CAS成功後だけ1回加算する。
- 業務帳票も同じく状態・試行回数付きCASで送信開始／完了／失敗を更新する。
- 業務帳票でWRITE_STARTED以降の通信失敗は送信結果不明としてFAILEDへ止め、自動再送による二重印刷を避ける。
- retry/discardの対象取得は500件一覧経由をやめ、主キーによる正確な1件取得にする。
- プロセス異常終了時のPRINTING→FAILED回収は従来どおり維持し、自動再送による二重印刷を避ける。

## 返品・取消
- 画面表示時に取得した返品済数量・値引返金額のスナップショットを、書込みトランザクション内でも再検証する。
- 別処理が先に返品を確定していた場合は、返品行を1件も追加せず全体をロールバックして再読込を要求する。
- これにより同じ元売上への同時返品で返品可能数量を超えて返金する競合を防止する。

## 営業セッション
- 入出金と返品・取消は、書込みトランザクション内で営業セッションがまだOPENであることを再確認する。
- 同時にZ精算が完了した場合、終了済み営業へ後続データを追加しない。
- X/Z精算は集計スナップショット作成を精算保存トランザクション内で再実行し、Zの営業終了と同一スナップショットで確定する。

## 正本
売上・支払・税・印刷キュー・返品・営業セッションはSQLiteを正本とし、状態遷移はDB条件付き更新で競合を拒否する。
