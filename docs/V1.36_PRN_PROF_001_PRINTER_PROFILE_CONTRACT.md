# v1.36 PRN-PROF-001 プリンタプロファイル

## 正式仕様との対応

正式仕様 v2.5 §16.10 の `PrinterProfile` は以下の主要項目を持つ。

`printerId, name, connectionType, address, paperWidthMm, printableDotWidth, logicalColumns, encoding, supportsCut, cutMode, feedLines, drawerPort, statusCapability`

正式仕様 v2.5 §16.9 では紙幅振替時に対象プリンタの `paperWidthMm` と `dotWidth` で再レンダリングするため、紙幅だけでなく有効印字dot幅もプリンター設定の一部として保持する。

## v1.36 実装

`PrinterConfiguration` / `printer_settings` / `PrinterProfileContractV136` を同期し、正式仕様の有効プロファイルを保存・再読込・印刷へ反映する。

- `printerId`: 初版1台構成の安定ID `printer-1`
- `name`: 永続プリンター名
- `connectionType`: 現行初版実装のTCP 9100
- `address`: host:port。未設定時は空欄のまま保持し、架空アドレスを作らない
- `paperWidthMm`: 58 / 80
- `printableDotWidth`: `printer_settings.printable_dot_width` に永続化
  - 58mm = 384dot
  - 80mm = 576dot
  - 初版では根拠のない機種固有値を作らず、紙幅選択と標準dot幅を連動させる
- `logicalColumns`: 58mm=32 / 80mm=48
- `encoding`: 既存機種プロファイルのcharset
- `supportsCut` / `cutMode`: 現在の有効カット設定を明示
- `feedLines`: `printer_settings.feed_lines` に永続化し、3〜7行、既定5行
- `drawerPort`: ドロア有効時のみDK1/DK2を保持
- `statusCapability`: 既存 `PrinterStatusProtocol`

### 既存DB migration

既存 `printer_settings` に対して `ALTER TABLE` 相当の互換追加を行う。

- `printable_dot_width` がない旧DBは一旦0で追加し、既存 `paper_width_mm` から58mm→384dot / 80mm→576dotへ補完する
- `feed_lines` がない旧DBは既定5で追加する
- 不正な旧値は初版安全値へ正規化する
- 既存のhost、port、profile、cut、drawer、自動レシート設定は変更しない

### 設定UI

SCR-762で以下を表示・保存する。

- 58mm / 80mm選択時に `printableDotWidth` を384 / 576へ同期
- 印字可能幅dotを用紙幅連動の読取専用項目として表示
- カット前紙送り行数を3〜7行で入力
- 保存直後にDBを再読込し、新フィールドが一致することを確認してからRegistryへ反映

### 実印刷への反映

`PrinterCommandEncoder.encodeText()` は従来の固定3改行を廃止し、保存済み `feedLines` 行だけLFを送ってからカットコマンドを送る。これにより売上レシート、業務帳票、テスト印刷など同Encoderを通る経路に設定が反映される。

テスト印刷本文にも紙幅、印字可能dot幅、紙送り行数を出し、現在選択中のProfile内容を紙面で照合できるようにした。

## Validation

- 用紙幅は58 / 80のみ
- 58mmは384dot、80mmは576dotのみを初版で許可し、紙幅とdot幅の矛盾を保存拒否
- `feedLines` は3〜7のみ
- プロファイルsnapshotはDBから再読込した `printableDotWidth` / `feedLines` をそのまま使用

## テスト

`V136PrinterProfileContractTest.kt` と `V136PrinterProfilePersistenceTest.kt` で以下を確認する。

- 58mm / 80mmの標準dot幅と既定紙送り
- 正式全項目snapshot
- 保存値の `printableDotWidth` / `feedLines` がsnapshotへ反映されること
- 紙幅とdot幅矛盾の拒否
- 紙送り範囲外の拒否
- `PrinterCommandEncoder` が設定された紙送り行数を出力すること
- schema / migration / load / save / UI / 保存後再読込経路が新フィールドを含むこと

## 実機確認

ソフトウェア上のDB migration、保存・再読込、ESC/POS payload生成までは自動検証する。

以下は実プリンターでのみ確定できるため未確認のまま分離する。

- 58mm実機で384dotが採用機の物理印字領域と一致すること
- 80mm実機で576dotが採用機の物理印字領域と一致すること
- 3〜7行の紙送り量とカット位置
- 実カッター、ドロア、状態取得能力
- 機種固有dot幅が必要な採用機の有無

実プリンタに対する印字可能性の能動確認は後続 `PRN-PROF-002` と最終総合実機試験へ繰越す。
