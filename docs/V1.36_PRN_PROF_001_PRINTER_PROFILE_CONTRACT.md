# v1.36 PRN-PROF-001 プリンタプロファイル

## 正式仕様との対応

正式仕様 v2.5 §16.10 の `PrinterProfile` は以下の主要項目を持つ。

`printerId, name, connectionType, address, paperWidthMm, printableDotWidth, logicalColumns, encoding, supportsCut, cutMode, feedLines, drawerPort, statusCapability`

従来実装には、`PrinterProfile` enum による文字コード・漢字コード体系・状態取得方式の差分と、`PrinterConfiguration` による名称、TCP 9100接続先、58/80mm、カット、ドロア設定が存在していた。しかし、正式仕様の一体的なプロファイルスナップショットは存在しなかった。

## v1.36 実装

`PrinterProfileContractV136.kt` を追加し、既存の永続設定を正式仕様の有効プロファイルへ投影する。

- `printerId`: 初版1台構成の安定ID `printer-1`
- `name`: 永続プリンター名
- `connectionType`: 現行初版実装のTCP 9100
- `address`: host:port。未設定時は空欄のまま保持し、架空アドレスを作らない
- `paperWidthMm`: 58 / 80
- `printableDotWidth`: 現行DBに独立overrideがないため正式標準値 384 / 576 dot
- `logicalColumns`: 58mm=32 / 80mm=48
- `encoding`: 既存機種プロファイルのcharset
- `supportsCut` / `cutMode`: 現在の有効カット設定を明示
- `feedLines`: 正式範囲3〜7の既定5
- `drawerPort`: ドロア有効時のみDK1/DK2を保持
- `statusCapability`: 既存 `PrinterStatusProtocol`

## 境界

この項目では正式 `PrinterProfile` モデルを欠落なく扱う基盤を作る。機種固有の印字可能dot幅を数値で永続overrideするUI、および実プリンタに対する印字可能性の能動検査は後続 `PRN-PROF-002` で監査・実装する。

現在の3プロファイルに根拠のない機種別dot幅を捏造せず、正式仕様の標準 384/576 dotを使用する。

## テスト

`V136PrinterProfileContractTest.kt` で以下を確認する。

- 58mmの正式全項目投影
- 80mm 576dot / 48列
- 文字コードと状態取得能力の引継ぎ
- カットなし・ドロアなしの明示
- 未設定接続先を架空値で補完しない
- profile内部整合性

## 実機確認

プロファイルモデル自体はJVMテスト可能だが、機種固有dot幅・カッター・ドロア・状態取得能力の実在性は実機確認が必要。`PRN-PROF-002` と最終総合実機試験へ繰越す。
