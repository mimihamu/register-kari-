# v0.87 復元ロールバック運用可視化

## 目的

v0.86で、復元前の現在DBをWAL checkpoint・SQLite整合性・外部キー・SHA-256確認済みの `rollback-register-<timestamp>.db` として保存するようにした。

ただし、ロールバックDBは端末内部ファイルであり、従来の「データ保全・バックアップ・復元」画面からは、現在もファイルが存在するか、最新ファイルが正常かを確認できなかった。

v0.87では、復元用ロールバックを自動復元機能へ拡張せず、**責任者が保管状態と最新ファイルの検証結果を確認できる読み取り専用表示**を追加する。

## 対象画面

- SCR-767 データ保全・バックアップ・復元

## 表示内容

「復元前ロールバック」欄で以下を表示する。

### ロールバックなし

- `保管なし。まだ復元を適用していない端末では正常です。`

ロールバックがないこと自体を異常とは扱わない。

### 最新ロールバック正常

- 保管ファイル数
- `最新ロールバック検証OK`
- ファイル名
- 作成時刻
- ファイルサイズ
- SHA-256先頭16文字
- `ロールバックDBは自動削除しません。`

OK表示は、`RestoreRollbackSafetyV086.inventory()` が最新ロールバックを実際に再オープンし、以下を確認できた場合だけ表示する。

- `PRAGMA integrity_check = ok`
- `PRAGMA foreign_key_check = 0件`
- SHA-256算出成功

### 最新ロールバック異常

ロールバックファイルが存在しても最新ファイルを検証できない場合は、

- 保管ファイル数
- `最新ロールバック検証NG`
- 検証エラー内容

を赤系の警告表示にする。

未検証ファイルを正常とは表示しない。

## 再検証

「ロールバック再検証」ボタンを追加する。

このボタンは読み取り専用であり、以下を行わない。

- ロールバックファイル削除
- ロールバックからの手動復元
- 現在DBの置換
- sales等の業務データ更新

## 実行スレッド

SQLiteファイル検証とSHA-256計算は `Dispatchers.IO` で実行する。

以下のタイミングでロールバック保管状態を再取得する。

- SCR-767初回表示時
- SCR-767への復帰時
- バックアップ/復元関連タスク完了後
- 「ロールバック再検証」操作時

## データ保護方針

v0.87ではロールバックの保持ポリシーを変更しない。

- 自動削除しない
- 自動上書きしない
- 最新ファイル以外も勝手に消さない
- ロールバックを通常バックアップ一覧へ混在させない

これは、復元トラブル時の救済データをUI追加によって失わせないためである。

## 実機確認事項

- v0.86で復元成功後、SCR-767にロールバックが1件以上表示される
- 表示ファイル名が実際に生成された `rollback-register-*.db` と一致する
- 作成時刻・サイズ・SHA表示が妥当
- 正常なロールバックで「検証OK」になる
- ロールバック破損時に「検証NG」となり、アプリが落ちない
- ロールバックなし端末で正常に「保管なし」と表示される
- 再検証中のUI応答
- 横画面タブレットでレイアウトが崩れない

実機未確認事項を確認済みとは扱わない。
