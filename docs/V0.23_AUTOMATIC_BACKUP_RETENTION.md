# v0.23 Z精算後の自動バックアップ・保存世代管理

## 目的

v0.21の安全な内部バックアップ・復元と、v0.22のStorage Access Frameworkによる外部保存・取込を維持したまま、Z精算が正常確定した後の内部自動バックアップ、保存世代管理、容量不足時の安全な中止を追加する。

## Z精算との接続

- Z精算は`OperationsStore.recordSettlement()`のSQLiteトランザクション内で、精算レコード、営業セッション状態、監査ログ、操作キーを一括確定する。
- `SecureOperationsCoordinator.recordSettlement()`へ正常復帰した時点をDBコミット完了後とみなし、その後にWorkManagerへ自動バックアップを要求する。
- X点検、Z精算失敗、例外発生時には要求しない。
- WorkManagerのユニーク名は`tsuguregi-auto-backup-z-{settlementId}`とし、`ExistingWorkPolicy.KEEP`を使用する。
- バックアップ失敗は完了済みZ精算を巻き戻さない。

## バックアップ形式とメタデータ

既存`.tgbak`のZIP構造と`TSUGUREGI_BACKUP_V1`マニフェストは変更しない。v0.21/v0.22で作成したバックアップの検証、外部取込、復元互換性を維持する。

自動バックアップ固有情報は内部バックアップライブラリの`.metadata`サイドカーファイルへ保存する。

- 作成理由：`MANUAL`、`MANUAL_AUTO`、`Z_SETTLEMENT`、`PERIODIC`
- 営業日
- 営業セッションID
- Z精算ID
- 作成日時
- アプリバージョン
- DB SHA-256
- 外部書き出し済みフラグ
- 最終検証日時
- 状態：`VERIFYING`、`READY`、`CORRUPT`

サイドカーが存在しないv0.21/v0.22バックアップ、手動バックアップ、外部取込バックアップは保守的に手動扱いとし、自動削除しない。

## 保存世代管理

v0.23では設定値の誤入力や0件保持による全削除を避けるため、固定安全値で開始する。

- 手動・外部取込・「自動バックアップを今すぐ実行」：自動削除しない
- Z精算バックアップ：直近14営業日分
- 定期バックアップ：直近12か月、各月の最新1件
- 最新の正常なバックアップ：必ず保護
- 復元待機中：保護
- 検証中、破損判定、マニフェスト不明：保護
- ロールバックDB：`data_restore`配下であり、世代整理の対象外

削除処理は、最初に全候補を確定し、その後で1件ずつ削除する。アーカイブ削除成功後にサイドカーを削除する。開始、成功、失敗は監査ログへ残す。

## 空き容量対策

- DB本体、WAL、SHMの合計サイズを基準に作業容量を概算する。
- スナップショットDBとZIPを同時保持できる作業容量に加え、最低128MiBの安全マージンを残す。
- 容量不足時は先に安全な世代整理を実行し、空き容量を再判定する。
- それでも不足する場合はバックアップを開始しない。
- DataProtectionManagerの既存`finally`処理に加え、1時間以上残存した`.tmp`とバックアップ用キャッシュを清掃する。
- 容量不足は`DATA_BACKUP_SKIPPED_LOW_STORAGE`とデータ保全画面へ記録する。

## データ保全画面

以下を追加する。

- 自動バックアップ有効状態
- 最終要求・最終完了・最終結果
- 発生条件
- 最終作成理由
- 自動整理結果
- エラー詳細
- 一覧ごとの作成理由
- 営業日、営業セッションID、Z精算ID
- 保持対象または削除候補
- 外部保存済み状態
- 最終検証日時と状態
- 通常バックアップと区別した「自動バックアップを今すぐ実行」

## 監査ログ

- `DATA_BACKUP_AUTO_REQUESTED`
- `DATA_BACKUP_AUTO_CREATED`
- `DATA_BACKUP_AUTO_FAILED`
- `DATA_BACKUP_RETENTION_STARTED`
- `DATA_BACKUP_RETENTION_DELETED`
- `DATA_BACKUP_RETENTION_FAILED`
- `DATA_BACKUP_SKIPPED_LOW_STORAGE`
- `DATA_BACKUP_SKIPPED_DUPLICATE`

既存の`DATA_BACKUP_CREATED`、`DATA_BACKUP_EXPORTED`、`DATA_BACKUP_IMPORTED`、復元監査ログは維持する。

## 外部保存の制限

- 自動バックアップはアプリ内部保存のみ。
- Google Drive API、OAuth、自動アップロードは実装しない。
- Google Drive、USB、端末フォルダへの保存はv0.22と同様、ユーザーがStorage Access Frameworkのシステムピッカーで操作する。
- `BusinessSyncFoundation.kt`のローカルJSONアウトボックスをクラウド同期完了とは扱わない。

## 実機確認項目

- Z精算成功後にWorkManagerが起動し、内部`.tgbak`とサイドカーが生成されること
- Z精算画面を閉じた場合、アプリをバックグラウンドにした場合にも処理されること
- バックアップ失敗後もZ精算済み状態が維持されること
- 容量不足端末でZ精算を壊さず警告が残ること
- 14営業日境界で意図したファイルだけ削除されること
- 復元予約中のバックアップが削除されないこと
- 外部保存後に「外部保存済み」と表示されること
- v0.21/v0.22バックアップの検証、取込、復元が継続して動作すること
