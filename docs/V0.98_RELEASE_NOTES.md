## 今回の変更

実プリンター運用へ進む前段として、自動印刷Workerの送信順序と障害時動作を安全側へ統一した。

### 売上・業務帳票の古い順統合

従来は売上レシートを先に処理し、その後に返品・取消、点検・精算、領収書などの業務帳票を処理していた。

v0.98では両キューを横断し、`PENDING` / `RETRY`のうち`createdAt`が古いジョブから送信する。

### Worker全体で最大20件

従来の20件制限は売上と業務帳票へ別々に適用され、1回で最大40件を試行し得た。

v0.98ではWorker全体で最大20件とした。20件到達時に残件がある場合は継続実行対象とする。

### 1件失敗で後続送信を停止

売上・業務帳票の種別に関係なく、1件でも送信失敗したrunでは後続ジョブへ進まない。

既存の送信安全仕様は維持する。

- `CONNECTING` / `CONNECTED`失敗は再試行可能
- `WRITE_STARTED` / `FLUSHED`以降は送信結果不明として自動再送しない
- `FAILED`は紙確認後の手動対応

### 自動Worker単一実行

periodicとimmediateの自動印刷要求が重なった場合に備え、プロセス内の単一実行ゲートを追加した。後から開始したWorkerは送信を開始せず再試行へ回す。

## 変更していないもの

- TCP 9100 / ESC/POS送信方式
- EPSON DLE EOT状態確認
- STAR / 汎用ESC/POSの未検証状態方式に対する制限
- 58mm / 80mm、カット、ドロア設定
- 売上確定、税計算、インボイス表記
- レシート再印字・領収書・返品取消の既存業務ロジック
- Google Drive
- つぐレジ CD
- データ保護、バックアップ、ロールバック

## テスト

v0.98専用JUnitで以下を検証する。

- 売上と業務帳票を横断した古い順選択
- 業務帳票一覧が新しい順でも最古ジョブを選択
- COMPLETED / FAILED / DISCARDEDを自動候補にしない
- RETRYを候補に含める
- Worker全体20件上限
- 最初の送信失敗で停止
- 20件到達後に残件があれば再実行対象
- 自動Worker単一実行ゲート
- 既存の送信結果不明・EPSON状態取得安全仕様の保持

通常の累積unit test、Kotlin compile、3アプリdebug APK build、APK identity/integrity gateも継続する。

## 実機確認

本版単独では実プリンターを接続していない。CI成功は実紙印刷成功を意味しない。

EPSON実機の印字、58/80mm、カット、ドロア、DLE EOT、紙切れ、カバー開、LAN切断、送信途中切断、20件超バックログ、periodic/immediate重複条件は**最終総合実機試験へ繰越**する。
