# v1.89 会計確定済みの支払内訳を完全照合

## 発見した問題
従来は売上復旧・冪等再試行で同じ会計キー、カート指紋、売上合計だけを確認していた。例えば同じ合計1000円でも「現金1000円」と「カード400円＋現金600円」では決済結果が異なる。合計一致のみで保存済み未確定配分を消すと決済調査の証跡を失うおそれがある。

## 変更
- `SaleCommitIdempotencySchema.recordedPaymentsMatch()`：確定済み `sale_payments` を実際に読み、配分の**順序・支払方法・充当金額・受取金額**と、連番の整合性を確認。欠損・破損・読込失敗は不一致扱い。
- `PaymentDraftStore.load()` と `clear()`：売上確定を確認できても、保存済み支払配分と実際の売上支払明細が完全一致するまで自動削除を禁止。
- `RegisterDatabase.saveSale()`：同じ会計キーの再試行でも、実際の売上支払明細と一致しない場合は同一取引として扱わずエラー。成功済み売上の重複登録は引き続き回避。
- 新しい `V189SaleTenderReplayMatchingTest.kt`：同額異種支払、現金の受取額差、配分順序変更、連番欠損、削除前検証を確認。

## 注意
既存の売上・支払レコードは移行しない。従来から支払内訳に欠落や破損があった場合は自動復旧を停止し、売上履歴や決済端末の確認が必要。実機での障害復旧・再印刷・外部決済照合は未受入。
