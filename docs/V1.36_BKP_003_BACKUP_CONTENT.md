# v1.36 BKP-003 バックアップ内容

正式仕様 `REGISTER（仮）_Androidレジ_詳細仕様書_v2.5.docx` の BKP-003 を正本とする。
Issue #137 #41 の旧ラベルより本仕様を優先する。

## 受入要件

バックアップは、復元後に販売・未送信データ再送・予約適用を継続できる内容を保持する。

### SQLite `register.db` に含まれるもの

- 売上・明細・支払・返品・営業日・精算・監査
- 商品/部門/グループ/税/販売プロファイル等のマスター
- `printer_settings` を含むプリンター接続設定
- `sales_journal` / `sync_outbox` / 同期fingerprint・index・runtime identity
- `sync_runtime_settings` の店舗ID・端末ID
- `menu_revisions` / `menu_revision_products` の予約適用状態
- 印刷ジョブ・文書印刷ジョブ等の永続キュー

`sync_outbox` の送信payloadはDBから `OutboxPayloadAssembler` で再生成可能なため、`filesDir/drive-sync-staging` は一時キャッシュとしてバックアップ対象外とする。
復元起動時は `PROCESSING` を即時再試行可能な `RETRY`、`STAGED` を `PENDING` へ戻し、復元済みDBからpayloadを再生成できる状態にしてから最終整合性検証を行う。

### 暗号化payloadへ追加するDB外状態

以下のSharedPreferencesを明示allowlistで型付き保存する。

- `initial_release_settings_v135` — 店舗基本、販売操作、営業日/精算、端末アプリ設定
- `tax_invoice_settings` — インボイス/税混在/発行者設定
- `document_print_settings_v136` — 文書別自動印刷・部数・ヘッダ・フッタ
- `customer_display_server` — 顧客表示接続/表示設定
- `receipt_stamp_settings_v136` — レシート画像スタンプ設定
- `auto_backup_settings_v2` — 自動バックアップ/保持設定
- `drive_sync_foundation` — 同期ステージング/フォルダー設定
- `outbox_delivery_settings_v1` — 未送信データ外部送信先設定
- `external_backup_settings_v1` — 外部バックアップ先設定

加えて `filesDir/receipt_stamp_v136/source_image.bin` を画像本体として保存する。

### 意図的に含めない端末固有/一時状態

- Google OAuth/接続認証状態 (`tsuguregi_google_drive_account`)。別端末では再認可する。
- 担当者の現在セッション
- クラッシュレポート、診断履歴、プリンターsoak-test等
- Drive/外部送信/外部バックアップの「実行中・最終結果」status
- `drive-sync-staging` 一時JSON。`sync_outbox` とDBから再生成する。

SAF tree URI文字列は接続情報として復元するが、Android OSのpersisted URI permissionはバックアップで移送できない。復元先端末に権限がない場合は該当自動送信をfail-safeでOFFにし、保存先再選択後に再開する。

## bundle / 暗号化

既存 `BackupEnvelopeV136` の AES-256-GCM envelope、device Keystore wrap、portable passphrase wrapは変更しない。DB・設定・画像を含むinner bundle全体が暗号化される。

inner bundleは従来の

- `manifest.properties`
- `register.db`

に加え、

- `content/manifest.properties`
- `content/settings/*.pref`
- `content/files/receipt_stamp_v136/source_image.bin`（画像設定時のみ）

を持つ。content manifestは各設定/画像のsizeとSHA-256を保持し、未知entry、重複key、型不正、size/hash不一致をfail-closedにする。

旧DB-only暗号化バックアップは `LEGACY_DB_ONLY` として引き続き復元可能。ただしBKP-003完全内容を持つのは本実装以降に作成したバックアップである。

## 復元安全性

1. 暗号化envelopeを復号し、DBとBKP-003 contentを検証する。
2. DBとcontentを `data_restore` に予約する。
3. 次回起動時、既存のDB rollback snapshotを作成する。
4. DB置換、migration、SQLite/外部キー/schema最終検証を完了する。
5. その後に設定/画像を適用する。適用前の設定/画像もrollback snapshotとして保持する。
6. content適用または後続処理が失敗した場合、DBと設定/画像の双方を元へ戻す。
7. 全工程成功後だけ復元予約を削除し成功確定する。

## 実機未確認

- 実データ量での別端末portable restore後、販売を継続できること
- 未送信 `sync_outbox` を復元後に再生成・再送できること
- 予約済みメニュー改定が復元後も適用されること
- 画像スタンプ・印刷設定・顧客表示設定が実機UI/印刷へ反映されること
- SAF保存先を同一端末/別端末で復元した際の権限再選択導線
