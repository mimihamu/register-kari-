# v1.46 つぐレジ 3アプリ連動 APK 配信更新

## 目的とURL
既存v1.45のXServer配信パッケージと連動し、以下3アプリに「アプリの更新を確認」を追加する。配信先は `https://tenpos.jp/support2/update/tsuguregi/` 固定。

| 対象 | アプリID（dev） | 旧版 | 新版 |
|---|---|---|---|
| つぐレジ | jp.co.tenposinfo.register.dev | 168 / 1.34.4-dev.1 | 169 / 1.34.5-dev.1 |
| つぐレジ＋ | jp.co.tenposinfo.register.plus.dev | 36 / 0.33.3-dev.1 | 37 / 0.33.4-dev.1 |
| つぐレジ CD | jp.co.tenposinfo.register.cd.dev | 14 / 0.15.6-dev.1 | 15 / 0.15.7-dev.1 |

各 `AppDistributionUpdateActivityV146` は `api/latest.php?app=pos|plus|cd&track=dev|stable` を使用し、各自のAPKへアクセスする。プライベート署名鍵をHTTPサーバへ配置しない。

## 端末内の処理
- 設定から明示操作で更新確認。配信元HTTPSを限定し、リダイレクト・別ホスト・ファイルサイズ超過を拒否。
- 公開バージョンコードが現行より大きい場合だけ更新候補表示。ダウンロードはキャンセル可能。
- HTTPSで取得したAPKのバイト数とSHA-256をAPIと照合。Android PackageManagerでパッケージ名、versionCode、既存アプリと署名者が同じことを検証。
- 検証したAPKだけアプリキャッシュ内 `tsugu-updates/update.apk` に保存。Android FileProviderで権限を制限したURIを渡し、最終インストールはAndroidの確認画面でユーザーが実行する。
- 初回は「このアプリからのインストール」をAndroid設定で許可する必要がある。権限なしで自動インストールしない。
- 内部データや業務DBはダウンロード・検証時に変更せず、Android通常の上書きインストールと既存更新初回起動トラッカーに委ねる。

## 更新入口
- つぐレジ：各種設定 → 端末・アプリ → 「アプリの更新を確認」
- つぐレジ＋：フォルダ取込／集計画面の上部「アプリの更新を確認」
- つぐレジ CD：接続設定画面の「アプリ更新」

## サーバ登録手順
1. v1.0配信サイト一式をXServerの `/support2/update/tsuguregi/` に設置して管理画面を初期設定する。
2. 新APKをdevのpos/plus/cdにそれぞれアップロードし、ハッシュ・パッケージ・versionCodeを管理画面で確認して公開する。
3. 既存v1.45アプリには更新機能がないため、**v1.46への初回更新のみWebページからの手動上書き**が必要。
4. v1.46導入後、将来v1.47でversionCodeを増分するとアプリ内更新画面で検出できる。

## 検証と非対象
- CI：累積ソースゲート、JUnit、3 Kotlin compile、3 APK build、署名・バージョン・SHA256独立検証。
- XServerへの実際の配置、ブラウザ公開、TLS取得、端末でのインストール許可と更新完了、業務データ非破壊の実機確認は未実施。
- 自動更新や無人インストールは実装しない。「更新確認を有効」という既存設定は本機能への自動定期ポーリングとしてはまだ連動していない。将来対応課題。
- 次版のビルド時はCIの期待versionCode/versionNameも必ず増分し、同じ版番号で配信しない。
