# v0.84 レガシーDB上書き更新 非破壊マイグレーション

## 目的

つぐレジを古い開発版から上書き更新した場合でも、SQLiteに保存済みの業務データを自動削除しないことを保証する。

従来の `RegisterDatabase.onUpgrade()` には、`oldVersion < 2` の場合に主要テーブルをDROPして新規作成する旧処理が残っていた。v0.2時点ですでに商品、作業中カート、保留伝票、売上ヘッダ、売上明細がSQLiteへ保存されていたため、この経路は現在のデータ保全方針と整合しない。

## v0.84の変更

### 1. 破壊的な旧アップグレード経路を廃止

`RegisterDatabase.onUpgrade()` は `LegacyDatabaseMigrationV084` のみを呼び出す。

自動アップグレードでは以下の業務テーブルをDROPしない。

- `products`
- `cart_items`
- `held_tickets`
- `held_ticket_items`
- `sales`
- `sale_items`
- `sale_payments`
- `print_jobs`

### 2. 不足したテーブルだけ作成

v0.2より古いDBに対しては、`sqlite_master` でテーブル存在を確認し、存在しない基礎テーブルだけ `CREATE TABLE IF NOT EXISTS` で作成する。

商品マスターの初期データは `products` テーブル自体が存在しなかった場合だけ投入する。既存の商品マスターを初期値で上書きしない。

### 3. 不足した列だけ追加

`PRAGMA table_info` で列存在を確認し、必要な列が無い場合だけ `ALTER TABLE ... ADD COLUMN` を実行する。

対象:

- `cart_items.discount_amount`
- `cart_items.note`
- `held_ticket_items.discount_amount`
- `held_ticket_items.note`
- `sale_items.discount_amount`
- `sale_items.note`
- `sales.print_count`

途中のスキーマ版から更新した場合でも、既に追加済みの列を二重追加しない。

### 4. 作業中カートのline_no移行

旧 `cart_items` に `line_no` が無い場合だけ、一時テーブルへ名称変更して現在形式へコピーする。

- 旧行は `rowid` 順で `line_no` を付与
- 全行コピー後にだけ一時テーブルをDROP
- 一時テーブルが異常残存している場合は自動削除せず更新を中止

業務テーブルを空にして作り直す処理にはしない。

## 変更しないもの

- 税計算・インボイス計算
- 支払計算
- 売上確定ロジック
- Sales Journal / Drive JSON
- 同期fingerprint
- SENT Outbox
- 隔離・同期履歴
- 点検・精算snapshot
- レシート再印字監査
- バックアップ形式

## 自動検査

`V084LegacyDatabaseMigrationSafetyTest` で以下を回帰検査する。

- `onUpgrade()` が非破壊マイグレーターを使用すること
- `dropAllTables` が存在しないこと
- 主要業務テーブルをDROPしないこと
- テーブル・列の存在確認を行うこと
- `cart_items` の行をコピーして保持すること
- DROPを許すのはコピー済み一時テーブルだけであること
- 既存商品マスターへ初期商品を再投入しないこと

## 実機確認が必要な項目

CIは実際のAndroidパッケージ上書き更新そのものを代替しない。以下は実機で確認する。

- v0.2相当DBを保持した端末へのv0.84上書き更新
- v0.3相当DBからの更新
- v0.4以降のDBからの更新
- 商品件数・内容が維持されること
- 作業中カートが維持されること
- 保留伝票・明細が維持されること
- 売上・売上明細が維持されること
- 更新後の売上参照、保留呼出、会計、印刷
- 更新途中の強制終了・ストレージ不足等の異常系

**実機未確認のため、上記を確認済みとは扱わない。**
