# v1.35 COR-005 元取引なし返品（レシートなし返品）

## 対象仕様

詳細仕様書 v2.5 の COR-005 返品登録要件を対象とする。

- 返品モードでは、返品数量・返品金額を負数取引として記録する。
- 元レシート／元取引を特定できない返品は責任者権限を必須とする。
- 返品理由の必須／任意を設定可能とする。

## 実装方針

既存の通常返品は `reversal_transactions.original_sale_id` と `reversal_items.sale_item_id` を必須としており、元取引あり返品の整合性を保っている。

COR-005 のために既存外部キーを nullable 化したり、架空の元売上を作成したりしない。元取引不明返品は専用の追記専用台帳へ保存する。

### 専用テーブル

- `manual_return_transactions`
  - `gross_amount < 0`
  - 理由
  - 返金方法
  - 操作者
  - 承認責任者
  - 承認要求ID
  - 実行時営業セッション／営業日
  - 実行日時
- `manual_return_items`
  - `quantity < 0`
  - `line_amount <= 0`
  - 商品名・単価・税区分／税率／内外税／税記号のスナップショット
- `manual_return_payments`
  - `amount < 0`
  - 返金方法

通常アプリ経路からこれらの確定データを物理削除しない。COR-010 の削除禁止テスト対象にも追加する。

## 権限・責任者承認

`ManualReturnCoordinatorV135` で書込直前に次を検証する。

1. 有効な担当者ログインセッションが存在する。
2. 担当者が `RegisterPermission.REVERSAL` を持つ。
3. 責任者PINが入力されている。
4. `AdminSettingsStore.managerNameForPin()` で責任者PINを再検証する。

画面入口自体も `REVERSAL` 権限で制御するが、UI表示制御だけには依存しない。

## 返品理由設定

`ManualReturnSettingsV135` で「返品理由を必須にする」を保持する。

- 初期値: 必須
- ON: 空欄では返品確定不可
- OFF: 空欄でも返品確定可
- 設定変更時も REVERSAL 権限 + 責任者PINを要求する

## 返金方法

元決済を特定できないため、自動推定せず責任者操作で返金方法を明示選択する。

- 現金
- カード
- 商品券
- 掛売
- その他

カードを選択した場合、POS側には返金記録を残すが、決済端末側の返金完了は別途確認が必要である。外部決済端末の自動返金API実行は本差分の対象外。

## 営業日・精算への反映

COR-009 に合わせ、元取引の営業日ではなく返品を実行した時点の OPEN 営業セッションへ記録する。

`OperationsStore.summaryForSession()` は以下を通常返品と合算する。

- 元取引なし返品件数
- 元取引なし返品の絶対返金額
- 負数の返金方法別支払額

そのため同じ集計を利用する以下へ一貫して反映される。

- レジ管理メニューの純売上
- 支払方法別集計
- 現金返金時の現金理論残高
- X点検
- Z精算
- 精算保存スナップショット
- 精算票

旧営業日の売上や過去のZ精算を更新しない。

## 印刷・監査

返品確定と同じDBトランザクションで以下を追記する。

- `operation_audit`: `MANUAL_RETURN`
- `document_print_jobs`: 返品票印刷データ

返品票には次を表示する。

- `返品（元取引不明）`
- 返品No.
- 営業日／日時
- 商品・税記号・負数量・負金額
- 税率別負金額／税額
- 返金合計
- 返金方法
- 返品理由
- 担当者／責任者
- カード返金時の決済端末確認注意

既存の返品票印刷設定を共有するため `REVERSAL_RECEIPT` を利用し、通常返品の参照No.と衝突しないよう元取引なし返品は負の `reference_id` を使用する。

統合印刷キューおよび自動印刷Workerは `reference_id` から返品データを再検索せず、`document_print_jobs.payload_text` を印刷する。そのため負の参照IDは表示・検索用の識別情報としてのみ扱われ、送信処理を阻害しない。

## 二重確定防止

`ManualReturnSubmissionGateV135` を画面確定操作の単一実行ゲートとして使用する。

- 確定開始時に原子的にロックする。
- ロック取得後は確定ボタンを無効化する。
- 成功時は完了ダイアログをキャンセル不可とし、利用者が `OK` を押して入力をクリアするまでロックを維持する。
- 失敗時はロックを解放し、確定ボタンを再度有効化する。
- 連打やキュー済みクリックによって同一画面操作から複数の `approval_request_id` が発行され、返品が二重登録される経路を防ぐ。

DBの `approval_request_id UNIQUE` 制約は監査IDの一意性を保証するが、画面操作ごとにUUIDを生成する設計のため、それ単独では連打による二重返品防止には使用しない。

## 自動検証項目

- 負数量／負金額変換
- 理由必須 ON/OFF
- 空明細／0以下数量拒否
- REVERSAL 権限 + 責任者PIN
- 架空の元売上を生成しないこと
- 専用追記テーブルを使用すること
- 現在の OPEN 営業セッションへ計上すること
- 返金方法の明示保存
- 日計・X/Z精算へ1回だけ合算されること
- 管理メニュー入口の権限制御
- 非exported／横画面固定
- 確定業務テーブルへの物理DELETE禁止
- 確定操作の単一実行ゲート
- 成功確認まで確定ボタンを再有効化しないこと
- `REVERSAL_RECEIPT` の元取引なし返品票が統合印刷キュー／自動印刷Workerで保存済みpayloadを使用すること

## 実機確認が必要な項目

自動テスト／CI成功だけでは以下を確認済みとしない。

1. REVERSAL 権限がない担当者には入口が利用不可となる。
2. 責任者PIN未入力／誤入力では確定できない。
3. 理由必須ONでは空欄を拒否し、OFFでは空欄を許可する。
4. 複数商品・複数量を登録し、画面上の返金合計が負表示になる。
5. DB上で取引金額・数量・返金支払が負数で保存される。
6. 現金返品で純売上と現金理論残高が返金額分減少する。
7. X点検／Z精算の返品件数・返品額・支払内訳へ1回だけ反映される。
8. カード返品で警告を確認し、実決済端末側の返金結果とPOS記録を照合する。
9. 返品票が実プリンタで正常印字され、通常返品の印刷キュー処理に悪影響がない。
10. アプリ再起動後も確定返品データと理由必須設定が保持される。
11. 既存DBから更新した端末で専用テーブルが安全に追加される。
12. 確定ボタンを連打しても返品取引・返金支払・印刷ジョブが1件だけ作成される。
