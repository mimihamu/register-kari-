## 主な変更

### SAF送信先の実保存名を完全一致確認

Android Storage Access FrameworkのDocumentsProviderでは、作成・rename要求時の表示名がprovider側事情で変更される場合がある。

v1.06は外部送信先の既存JSONを非破壊化し、サイズとSHA-256を検証していたが、新規作成・rename後の返却URIについて実際の `COLUMN_DISPLAY_NAME` が要求したobject key名と完全一致することまでは確認していなかった。

v1.07では、SAFで今回作成・renameした対象について返却URIの表示名を再取得し、要求名と完全一致した場合だけ送信確定処理へ進む。

- 要求 `sale.json` / 実保存 `sale.json`: 継続
- 要求 `sale.json` / 実保存 `sale (1).json`: 拒否
- 大文字小文字差: 拒否
- 表示名取得不可: 拒否

### provider自動変名を送信成功扱いにしない

保存名不一致は `OutboxProviderNameMismatchException` とし、v1.06の衝突安全経路へ合流する。

- 即時FAILED
- 自動再試行しない
- SQLite売上を保持
- Sales Journal / sync_outboxを保持
- ローカルstaging JSONを保持
- 監査 `SYNC_OUTBOX_EXTERNAL_COLLISION` を維持
- 外部で原因解消後の手動retryを維持

変名された今回処理由来の未確定対象だけをcleanupする。処理開始前から存在する確定JSONは削除・上書きしない。

### renameフォールバックの安全化

通常のrename失敗は従来どおりcopy-to-finalへフォールバックする。

一方、renameがURIを返した後に表示名不一致を検出した場合は通常失敗として握りつぶさず、変名エラーを上位へ送出する。これにより、providerが別名へrenameした状態から別経路で成功扱いになることを防ぐ。

copy-to-finalで作成するfinal JSONにも同じ表示名完全一致検査を適用する。
