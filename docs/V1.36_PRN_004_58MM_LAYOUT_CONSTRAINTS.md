# v1.36 PRN-004 / 58mm レイアウト制約

## 対応関係

Issue #137 #22 `PRN-004 58mmレイアウト制約` は、正式仕様 v2.5 **16.1 ロール紙幅・プリンタプロファイル** および受入条件 **AT-021 / AT-026** を実装基準として監査する。

正式仕様では58mmについて次を要求する。

- 半角32論理桁 / 全角16文字相当。
- 商品明細は商品名行と数量・単価・金額行の原則2行構成。
- 商品名が長い場合は折返し、文字を欠落させない。
- 金額は右寄せし、桁欠落を禁止する。
- 商品名や金額が収まらないことを理由に文書全体を一律縮小しない。
- 通常売上、混在税率、値引、複合支払でも商品名・数量・単価・金額・税・支払を欠落させない。
- 長い商品名と最大桁金額を含む受入試験を行う。

## 監査結果

既存 `ReceiptRenderer` は以下を既に満たしていた。

- `ReceiptPaper.MM58` = 32論理桁。
- 商品名と数量・単価・金額を別行で出力する2行構成。
- `amountLine()` により金額領域を先に確保し、金額を行右端へ配置する。
- 税内訳、合計、支払、釣銭を紙幅に応じて同じ構造化データから描画する。

一方、商品名行は従来 `fit("商品名 [税記号]", width)` を使用しており、32論理桁を超える文字を**切り捨てていた**。このため正式仕様 AT-021 / AT-026 の「商品名が規則通り折返され、欠落しない」を満たさず、末尾の `内 / 外 / 内※ / 外※ / 非` 税記号も欠落し得た。

## v1.36 補修

`ReceiptLineWrapV136` を追加した。

- ASCII / 半角相当は1論理桁、それ以外は2論理桁として既存 `ReceiptRenderer` と同じ幅モデルを使用。
- CRLF / CR をLFへ正規化してから行単位で処理。
- 指定論理幅を超える直前で折返す。
- `fit()` のように末尾文字を捨てず、入力文字をすべて次行へ継続する。

販売レシートの商品名行を `ReceiptLineWrapV136.wrap("商品名 [税記号]", width)` へ変更した。これにより長商品名と税記号を欠落させず、58mmでは各行32論理桁以内へ折返す。

商品備考も同じlossless wrapへ変更し、長い備考が途中で消える既存挙動を解消した。

数量・単価・金額行は既存 `amountLine()` を維持し、58mmの原則2行構成と金額右寄せを崩さない。

## 自動テスト

`V136Receipt58mmLayoutTest.kt` で以下を固定する。

- 長い全角商品名 + `内※` が58mmで複数行へ折返され、改行を除けば元文字列が完全復元できること。
- 58mm描画の各行が32論理桁以内であること。
- 8桁単価 × 数量の金額文字列が欠落せず、金額行末に残ること。
- 通常商品でも商品名行の直後に数量・単価・金額行が来ること。
- wrap単体でも入力文字列と税記号が欠落しないこと。

## 80mmとの境界

今回の #22 は58mm制約を対象とし、80mm固有の「商品名 / 数量 / 単価 / 金額の1行構成を優先」は次項 #23 `PRN-005 80mmレイアウト` で別途監査・実装する。58mm補修のために80mm仕様を先取りして混在させない。

## 実機確認へ残す項目

- 58mm実紙で32論理桁相当になること。
- 長商品名がプリンタ実機でも意図した位置で折返すこと。
- 最大運用金額、混在税率、値引、複合支払の実印字で欠落がないこと。
- 全角/半角混在時の実ドット幅、フォント幅、物理余白。
- カット位置と末尾送り。

コード、自動テスト、APK検証が完了しても、上記は最終統合実機受入まで未確認として扱う。
