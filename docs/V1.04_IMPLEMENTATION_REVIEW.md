# v1.04 実装レビュー記録

## 初期リリース阻害要因再スキャン結果

v1.04開始時に、起動・DB・会計確定・バックアップ/復元を再確認した。

### 会計二重登録

既存実装で以下を確認したため、v1.04では変更しない。

- `PaymentDraftStore` がSQLiteへ支払途中状態とcommit keyを永続化する。
- cart fingerprint不一致時は古いdraftを復元しない。
- `SaleCommitIdempotencySchema` がcommit keyを永続化する。
- 既存commit key再利用時はcart fingerprintとtotalを照合する。
- `RegisterDatabase.saveSale()` は売上・明細・支払・印刷job・commit keyを同一SQLite transactionで確定する。

### 復元ロールバック

v0.86以降の起動時復元で、復元前DBをWAL checkpoint後に検証済みrollback snapshotとして確定していることを確認した。復元失敗時はこのsnapshotから戻すため、同じ仕組みを重複実装しない。

### v1.04で修正する問題

1. `VACUUM INTO` 失敗時のraw DB fallbackがWAL checkpoint結果を確認していなかった。
2. 共通 `atomicReplace()` が既存targetを先にdeleteしていたため、process crashの時間窓があった。

この2点だけを最小範囲で修正する。

## 非変更範囲

販売・税・値引・支払・印刷・Drive・CDの業務仕様は変更しない。

## 実機

process kill / reboot / 並行write / 実SQLite version差を含む確認は最終総合実機試験へ繰越する。
