# v0.86.0-dev.1 リリースノート

## 概要

復元前の元DBロールバックをWAL-safe・検証済みにし、ロールバック作成失敗時に元DBを触らず復元を中止するよう起動時復元を安全化した。

## 主な変更

- `DataRestoreBootstrapProviderV086` を追加し、AndroidManifestの復元Providerを切替
- v0.83の `initOrder=1000` を維持
- 復元前に `PRAGMA wal_checkpoint(FULL)` を必須化
- checkpointのbusy / frame完了状態を検証
- 元DBのSQLite integrity / foreign keyを検証
- ロールバックを一時コピー→検証→SHA-256→atomic replaceで確定
- ロールバック確定前は元DB / WAL / SHMを削除しない
- ロールバック作成失敗時は復元を中止し、元DBを保持
- 復元失敗時は検証済みロールバックから一時コピー経由で元DBを復旧
- 復旧前後でSHA-256一致を確認
- 復元成功結果にロールバックファイル名とSHA-256を記録
- 復元前ロールバックDBは自動削除しない
- v0.83回帰テストを新しい安全Providerへ追従
- v0.86専用回帰テストを追加

## データ保護

以下の業務データに対するDELETE/DROP/一括書換えは追加していない。

- sales / sale_items / sale_payments
- products
- held_tickets / held_ticket_items
- Sales Journal
- Drive JSON
- sync fingerprint
- SENT Outbox
- 隔離・同期履歴

本DBの置換は、責任者が正式に復元予約した場合だけ実行する。
