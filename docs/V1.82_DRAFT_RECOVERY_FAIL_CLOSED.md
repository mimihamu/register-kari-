# v1.82 中断会計・支払データのフェイルクローズ強化

v1.81では、小数数量や同額の別伝票行を区別し、同じカートに見える旧形式ドラフトを復元拒否した。一方、**完全に別のカートの指紋で保存済みの支払割当があると `clear()` により証跡が消える**経路が残っていた。

## 修正
- 新旧形式を問わず、カート指紋不一致で支払割当が**1件以上**残る場合は、データを削除・再使用せず支払画面への進行を止める。
- metadata行が失われていても支払割当行が残る場合、無支払と誤認せず、確認案内を表示。
- metadata欠損時のSQL照会自体に失敗した場合も、安全側で復元拒否する。
- `PaymentDraftStore.loadOrCreate` がDBの故障等で例外になっても、レジの販売画面で案内ダイアログを表示し、自動再決済やアプリの無制御終了を避ける。
- 支払配分が **0件** で指紋だけ古い場合のみ、従来通り空のドラフトを破棄可能。
- 残った記録の削除・復元許可はこのUIからは行わない。決済の二重実行を防ぐため、責任者の売上履歴・外部決済照合が必要。
