# v1.35 UC-10 取消 仕様監査

## 対象

詳細仕様書 v2.5 の UC-10 / COR-007 / COR-010 を、`develop/v1.35` の取消実装と突合した。

## v1.35で確認した実装

- 確定済み売上を元売上として選択し、`ReversalType.CANCEL` で全量取消する。
- 取消時の数量は画面入力値に依存せず、未返品数量の全量を対象にする。
- 1点でも返品済みの売上は全量取消を拒否し、残数量の返品へ分離する。
- 確定売上・売上明細・支払明細は更新/削除せず、`reversal_transactions` / `reversal_items` / `reversal_payments` に反対取引を追記する。
- `original_sale_id` で元売上と取消を関連付ける。
- 操作担当者に `REVERSAL` 権限を要求し、確定直前に責任者PINを再検証する。
- 取消理由を必須とする。
- OPEN営業セッション中のみ実行し、実行時営業日/営業セッションへ計上する。Z精算後のセッションでは実行しない。
- 永続 `operation_keys` を確保してから反対取引を保存し、成功後に取消IDをbindする。同じ元売上に対する取消キーはリクエストIDによらず固定し、再取消/再送を拒否する。
- 元売上の支払内訳と既返金額から、未返金残高を超えない返金配賦を作成する。
- 売上時の税スナップショットを再利用して取消金額・税額を計算する。
- 取消票は `【取消レシート】`、元売上No.、負数量、負金額、返金合計、返金手段を表示する。
- 通常売上照会は全量取消済み売上を `取消済（VOIDED）` として扱い、反対取引No.を追跡できる。
- 当日集計/X点検/Z精算では取消額を純売上から控除し、反対支払を支払別集計から控除する。現金返金は現金理論残高にも反映する。
- 確定後は取消票の自動印刷キューとDrive Outboxを起動する。

## 自動テスト

`V135Uc10CancelAuditTest` で以下を固定する。

1. 取消は指定数量にかかわらず未返品全数量を対象にする。
2. 一部返品済み売上の全量取消を拒否する。
3. CANCELの永続重複防止キーが `CANCEL:<originalSaleId>` で安定し、RETURNはrequestId単位で分離される。
4. 取消保存が追記方式であり、確定売上系テーブルをDELETEしない。
5. 取消票が元売上を関連付け、数量/金額を負数表示する。
6. REVERSAL権限・責任者PIN・理由・OPEN営業セッションを要求する。
7. 純売上、支払別、現金理論残高、印刷/Drive連携への反映経路を保持する。

既存の `V135OriginalSaleReturnSafetyTest`、`V135SaleReversalTracePolicyTest`、COR-007/COR-008/COR-010系テストも取消基盤の回帰を継続して検証する。

## v1.38へ持ち越す範囲

- クレジット/電子決済等の実端末に対する取消・返金API実行。
- 決済結果UNKNOWN時の照会・参照番号運用と実端末照合。

DB上の取消・返金記録だけをもって外部決済端末上の取消完了とは扱わない。

## 実機確認残り

1. 通常売上を全量取消し、元売上が消えず `取消済（VOIDED）` となること。
2. 複数商品/複数量の売上で全数量が自動対象になること。
3. 一部返品後に全量取消を実行し、明示エラーで拒否されること。
4. 取消確定ボタン連打・画面再操作・アプリ再起動後の再取消でも反対取引が1件だけであること。
5. 現金単独/複合支払売上で返金内訳と現金理論残高が一致すること。
6. 58mm/80mm実プリンタで `取消レシート`、元売上No.、負数量/負金額、返金手段が読めること。
7. 通常売上照会から元売上→取消の追跡ができること。
8. X点検/Z精算へ取消が1回だけ反映されること。
9. クレジット等はv1.38の実決済端末返金結果とDB記録が一致すること。
10. 既存DBからアップデートした端末で操作キー/反対取引/印刷キューのスキーマが正常に利用できること。

## 判定

UC-10は **コード監査・自動検証対象をv1.35で閉じる**。実機確認およびv1.38の外部決済端末連携が残るため、マスターIssueの「完全完了」判定は実機確認後とする。
