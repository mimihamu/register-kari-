# v1.35 PERIOD-001 主要帳票の期間指定

## マスター台帳との対応

Issue #137 の #36 `PERIOD-001 主要帳票の期間指定` を、詳細仕様書 v2.5 の売上ダッシュボード／売上分析にある期間指定要件と突合した。

Issue #137 の受入観点は `from/to集計確認`。v2.5では、つぐレジ＋の売上ダッシュボードで期間を変更すると集計対象を切り替えられることが要求されている。

## 監査結果

### つぐレジ

既存実装に、営業日・取引履歴・レシート再印字の期間指定経路が存在する。

- `BusinessDateSalesLookupActivity.kt`
- `SalesHistoryLookup.kt`
- `SaleReceiptReprintStablePaging.kt`
- `V071SaleReceiptReprintPeriodIndexTest.kt`
- `V072SaleReceiptReprintCustomRangeTest.kt`

このためv1.35では、つぐレジ本体の既存期間検索を作り直さず、退行させないことを累積テストで確認する。

### つぐレジ＋

監査前の `SalesReportFilter` は `businessDate` 1日だけを持ち、`SalesReportCalculator` も営業日完全一致でしか集計できなかった。ここをPERIOD-001の実装差分とした。

## v1.35実装

### 期間集計コア

`SalesReporting.kt`

- `SalesReportFilter.businessDateFrom`
- `SalesReportFilter.businessDateTo`
- `SalesReportPeriodPolicy`

を追加した。

期間は営業日 `YYYY-MM-DD` を基準に、開始日・終了日の両端を含めて集計する。

- 単日 `businessDate` は既存互換のため維持し、指定時は単日を優先する。
- from/toは必ず両方指定する。
- from > to は不正条件として集計しない。
- 任意期間は最大31日（両端を含む）。
- 32日以上は不正条件として集計しない。
- 不正条件で全期間集計へフォールバックしない（fail-closed）。
- 店舗・端末フィルタは期間指定とAND条件で従来どおり適用する。

### つぐレジ＋ UI

`SalesReportPeriodFilterBarV135.kt` を追加し、開始日／終了日を選択できるようにした。

- 開始日は取込済み営業日から選択する。
- 終了日は開始日以降かつ31日以内の候補だけを表示する。
- 期間指定を開始したときは既存の単日指定を解除する。
- 「全期間」で単日・from・toをまとめて解除する。
- 既存の売上画面「営業日」で単日を選択した場合は単日指定を優先する。

`ManagementPeriodWrapperV135.kt` は `MainActivity` が保持する `MutableState<ManagementUiState>` に対するより具体的なComposable overloadとして期間バーを接続し、既存のフォルダ同期／スマホ画面は `State<ManagementUiState>` overloadへそのまま委譲する。既存画面を複製・削除しない。

## 自動テスト

`V135Period001SalesReportRangeTest`

1. from/toの両端を含む売上だけが集計される。
2. 既存の単日指定が期間指定より優先される。
3. 31日間は許可される。
4. 32日以上はfail-closedとなる。
5. from > to と片側だけの期間指定はfail-closedとなる。
6. 終了日候補が開始日以降・31日以内に制限される。

`V135Period001SourceContractTest`

- 期間フィルタのフィールド、31日上限、UI接続、既存つぐレジ期間テスト、本文書をソース契約として固定する。

## v2.5の広い売上分析要件との境界

PERIOD-001は「主要帳票の期間指定」を対象とする。v2.5のMGR-100/MGR-110には、期間プリセット、比較期間、日別・時間帯推移、商品・部門ランキング、客数など、期間指定以外の分析機能も含まれる。

それらをPERIOD-001だけで完成扱いにはしない。特に現在の取込データから客数を正確に取得できない場合、取引件数を客数と偽装しない。各機能はIssue #137の後続監査／同期・分析実装で個別に扱う。

## 実機確認へ繰り越す項目

- つぐレジ＋縦画面で開始日・終了日が選択しやすいこと。
- from/toの両端日の売上が画面値へ反映されること。
- 店舗・端末フィルタとの組合せで正しい集計になること。
- 単日選択後に単日が優先され、期間を選び直すと期間へ戻ること。
- 31日上限の終了日候補が実画面で正しいこと。
- 期間変更後、取引確認画面にも同じ集計条件が反映されること。

**実機未確認のため、Issue #137 の完了件数にはまだ加算しない。**
