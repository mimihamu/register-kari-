# つぐレジ 累積開発リリースノート

## v1.15.0-dev.1 バックエンド／データまとめ強化
- 売上印刷キューに原子的claimを追加。
- 売上印刷完了を冪等化し、`print_count`の二重加算を防止。
- 業務帳票印刷を状態・試行回数CASへ統一し、送信結果不明時の自動再送を停止。
- 500件一覧経由のジョブ特定を廃止し、主キー直接取得へ変更。
- 返品・取消をトランザクション内スナップショット再検証で同時実行から保護。
- 入出金・返品を営業セッションOPEN再確認でZ精算との競合から保護。
- 精算集計を精算保存トランザクション内で再生成し、Z締め直前の売上・返品・入出金を取りこぼさない。
- v1.14までのOutbox外部配送lease／Drive JSON安全策を維持。

## v1.16.0-dev.1 DB整合性・バックアップ／復旧まとめ強化
- 復元前の現行DBを `PRAGMA wal_checkpoint(TRUNCATE)` で確定し、WALが0 byteになったことを確認してからrollbackスナップショットを作成。
- rollbackスナップショットのSQLite整合性、外部キー、SHA-256検査を継続。
- 復元候補を正本へ配置した直後には成功確定せず、legacy migrationと後付けschema bootstrapを同じrollback境界の中で実行。
- migration後に既存health checkを再利用し、SQLite整合性、外部キー、主要テーブル・列を再確認。
- DB `user_version == 4` と、印刷・営業・返品・精算等に必要な主要indexを確認。
- 復元監査を書き込んだ後にも最終health gateを再実行し、問題があれば元DBへrollback。
- 復元予約成立前に現在DBへINSERT/UPDATE/DELETE禁止triggerを設定し、復元予約中に追加された業務データが次回起動時の復元で消失する競合を防止。
- 予約失敗・予約取消・正常復元・復元失敗rollback・不完全な予約ファイルの各経路で書込みフェンスを解除し、最終health gateでもtrigger残存を拒否。
- 既存のSHA-256、必須テーブル検査、rollback実装は重複実装せず再利用。
