# v1.35 UC-08 会計 仕様監査・実装確認

## 対象

初版完成マスター Issue #137 の UC-08「会計」と、詳細仕様書 v2.5 第13章（PAY-001〜PAY-020）のうち、v1.35 で担当するPOS内会計フローを対象とする。

## v1.35 で実装・自動検証する範囲

- 支払手段: 現金 / クレジット / 商品券 / 掛売 / その他
- 分割・混在支払
- 現金の預り額入力、適用額、釣銭
- 非現金支払の過入金拒否
- 不足額が残る状態では会計未完了
- 直前支払の取消
- 支払ドラフト保存・復元
- 会計確定の二重登録防止
- 顧客表示への PAYMENT / COMPLETE 状態送信
- 会計確定後の売上・支払明細永続化

## 支払計算

`PaymentEngine` は売上対象額に対して支払を順次適用する。

- 現金は入力した預り額が残額を超えてよい。売上への適用額は残額までとし、超過分を釣銭とする。
- クレジット、商品券、掛売、その他は釣銭を出さない支払として扱い、残額を超える入力を拒否する。
- `paidTotal` は各支払の適用額の合計で、対象額を超えない。
- `shortage = targetAmount - paidTotal`。不足額が0になるまでは会計確定不可。
- 現金と非現金を組み合わせた分割・混在支払を許可する。

## 支払手段

`PaymentMethod` は以下を内部標準として扱う。

| 内部値 | 表示名 | v1.35の扱い |
|---|---|---|
| CASH | 現金 | 預り・釣銭あり |
| CARD | クレジット | 非現金、過入金不可 |
| GIFT_CERTIFICATE | 商品券 | 非現金、過入金不可 |
| ACCOUNT_RECEIVABLE | 掛売 | 非現金、過入金不可 |
| OTHER | その他 | 汎用非現金、過入金不可 |

PAY-013の支払手段マスタ拡張および E_MONEY / QR 等の外部決済種別は、外部端末連携を実装する v1.38 側で扱う。v1.35 の「その他」は未定義の外部決済を自動送信する意味ではなく、POS内部の汎用非現金支払である。

## 支払ドラフト復元

会計途中の支払状態は `PaymentDraftStore` へ保存し、会計画面再入場・プロセス再生成後の復元対象とする。ドラフトには会計を識別する `cartId` と `commitToken` を保持し、復元時に同一会計の確定キーを継続利用する。

## PAY-020 会計確定の永続冪等性

会計確定はUIの二度押し防止だけに依存しない。DB側の `SaleCommitIdempotencySchema` を用い、`cartId × commitToken` を永続的な確定単位として扱う。

状態遷移は以下を使用する。

`DRAFT → COMMITTING → COMMITTED / FAILED / UNKNOWN`

- 既に `COMMITTED` の同一キーは既存売上を返し、重複売上を作らない。
- `COMMITTING` / `UNKNOWN` は別の会計として再送せず、無条件の二重確定を防ぐ。
- SQLite例外等で確定結果を断定できない場合は `UNKNOWN` とし、盲目的な再実行を行わない。
- 一意制約をDBで持たせ、アプリ再起動を跨いだ二重登録も防止する。

## 支払明細の永続化

v1.35 の内部支払は `sale_payments` に、売上番号・支払順序・支払方法・適用額・預り額を保存し、売上照会時に `PaymentEntry` として復元する。現金の釣銭は `receivedAmount - appliedAmount` から決定可能である。

詳細仕様書 v2.5 にある外部決済監査項目（gatewayTransactionId、slipNo、acquirer、brand、外部端末のUNKNOWN照会・取消参照等）は、実際の外部端末連携と一体で v1.38 に実装する。v1.35 ではこれらを取得したふりはせず、外部端末送信も行わない。

## 顧客表示

会計画面では支払状態を `PAYMENT` として送信し、会計確定後は `COMPLETE` を送信する。専用表示側の最終UI整備は v1.37 の担当範囲だが、POS側の送信契約は v1.35 で維持する。

## 自動テスト

UC-08 の回帰テストでは少なくとも次を確認する。

- 現金 + クレジットの混在支払
- 現金過入金時の適用額と釣銭
- クレジット過入金拒否
- 商品券・掛売支払
- その他支払と過入金拒否
- `paidTotal` が対象額を超えないこと
- 直前支払取消後の再計算
- 既存の支払ドラフト・確定冪等性ソースゲートを維持すること
