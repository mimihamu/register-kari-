# v1.35 TAX-002 税率マスタ監査

対象: 初版完成マスター Issue #137 の #14 `TAX-002 税率マスタ（8/10%初期値・追加可能）`

> 仕様書 v2.5 本文では `TAX-002` が「税率別1回丸め」、動的税区分マスターは `TAX-007`、つぐレジ＋画面は `MGR-270` と表記される。Issue #137 は初版進捗をまとめるため、これらのうち「8/10%固定を除去し、第3税率を扱う」範囲を #14 TAX-002 として追跡する。

## 仕様突合

v2.5 の動的税区分マスターは次を要求する。

- 初期区分: 非課税 / 10%内税 / 10%外税 / 8%内税 / 8%外税
- 将来税率を内税 / 外税として追加可能
- 適用は暦日0時ではなく営業日
- 過去取引は当時の税値を保持
- 第3税率追加後も会計・帳票・CSV・同期で固定8/10列に依存しない
- つぐレジ＋ `MGR-270` で将来税率、適用営業日、使用状態を管理できる

## つぐレジ側

既存実装を監査し、次を確認した。

- `Product` は `taxKey / taxRatePercent / taxIncluded / taxable / reducedTax / taxSymbol` をスナップショットとして保持する。
- `TaxEngine` は `TaxCategory` enum の8/10ではなく `product.taxRatePercent` で税率ごとに集約する。
- `DynamicTaxRule` は0〜100%の任意税率を保持でき、課税区分は `NON_TAXABLE / INCLUDED / EXCLUDED`。
- `DynamicTaxEngineTest` で12%内税 / 12%外税を検証済み。
- `LineTaxSnapshotStore` がカート、保留、確定売上の税区分・率・内外・記号を保存する。
- TAX-001で営業日履歴と物理削除禁止を追加済み。

したがってPOS計算自体に8/10%固定の追加修正は不要だった。

## つぐレジ＋側で今回追加したもの

### `TaxCategoryMasterV135.kt`

- `tax_category_master_v135` を追加。
- `(tax_key, effective_from_business_date)` を一意キーとする追記型revision方式。
- 物理DELETEをDB triggerで拒否。
- 初期5区分を自動seed。
- 任意税率0〜100%を検証し、課税なら1%以上、非課税なら0%に限定。
- 適用開始営業日は必須、終了営業日は任意。
- 同じtax keyを改定すると旧revisionの終了営業日を新revision前日に閉じる。
- 使用停止も削除ではなく `enabled=false` の新revisionとして保存可能。
- `register.tax-categories.v1` の配列snapshotを生成し、税率を固定列化しない。

### `TaxCategoryMasterActivityV135.kt`

- つぐレジ＋に「税区分マスター」画面を追加。
- 初期5区分を確認可能。
- 第3税率を新規追加可能。
- 既存区分は「改定」として営業日を指定して変更。
- 内税 / 外税 / 非課税、税率、軽減、税記号、使用状態、適用開始/終了営業日を編集。

### `ManagementFolderSyncScreen.kt`

- メイン画面上部から「税区分マスター」へ遷移できる入口を追加。

### つぐレジ＋売上集計

既存 `SalesReportCalculator` は `taxTotals[]` を配列で読み、`ratePercent` を動的ラベルとして集計する。8%列 / 10%列の固定構造は使用していない。今回の監査テストでは12%税率の集計を固定した。

## v1.36へ残す範囲

つぐレジ＋で作成した `register.tax-categories.v1` をGoogle Drive経由でPOSへ公開し、ACK・競合・遅延受信・営業開始時原子的適用まで行う配信ワークフローは、ロードマップ上のv1.36「Drive / Plus同期」で実装する。

このためv1.35 TAX-002では「固定8/10%を排除できるPOS計算」「＋側の動的マスター管理・保存」「任意税率を受ける＋集計」を完成範囲とし、端末間配信そのものは完了扱いに含めない。

## 実機確認残り

1. つぐレジ＋初回起動で初期5区分が表示される。
2. 12%内税 / 外税を追加できる。
3. 同一tax keyの将来営業日改定で旧revisionの終了日が自動設定される。
4. 使用停止を新revisionとして登録できる。
5. アプリ再起動後も追加・改定履歴が保持される。
6. 縦画面の小型端末で一覧・編集ダイアログが操作できる。
7. 12%を含むjournal payloadを取り込むと、＋の税率別集計に12%が表示される。
8. v1.36でDrive配信を接続後、POS営業開始時に同じ第3税率が原子的に反映される。

実機未確認のため、Issue #137 の完了件数はまだ増やさない。
