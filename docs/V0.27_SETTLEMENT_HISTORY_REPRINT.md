# v0.27 点検・精算履歴・再印字仕様

## 1. 目的

v0.25で分離したX点検とZ精算、v0.26で追加したZ精算前チェックを、営業セッション単位で後から確認・再印字できるようにする。

同じ営業日に複数回営業した場合でも、点検・精算結果を営業セッションNo.で分離し、別セッションの売上を混ぜない。

## 2. 履歴画面

レジ管理メニューに「点検・精算履歴」を追加する。

画面では次の条件で履歴を絞り込める。

- 営業セッション
- すべて／X点検／Z精算
- レポートNo.
- 発行日時

履歴詳細には次を表示する。

- 営業日
- 営業セッションNo.
- 売上総額
- 返品・取消
- 純売上
- 現金理論額
- 現金実査額
- 過不足
- 売上件数
- 未印刷件数
- 未会計伝票件数
- 担当者
- 発行日時
- 保存明細方式

## 3. 保存スナップショット

v0.27以降の点検・精算時に、次の値をレポート時点の値として固定保存する。

- 開始釣銭
- 入金
- 出金
- 支払方法別金額
- スナップショットバージョン

X点検後に販売を継続しても、過去のX点検票を現在のセッション集計から再計算しない。

## 4. 初回印刷

X点検またはZ精算の保存と同じSQLiteトランザクションで、業務帳票印刷ジョブを作成する。

保存成功後、AutomaticPrintWorkerを即時起動する。プリンター未設定・通信失敗時は既存のdocument_print_jobsに残し、既存の再試行安全方針を使用する。

## 5. 再印字

履歴でレポートを選び、プリンタ設定に保存された58mmまたは80mmの幅で再印字する。再印字操作では幅を指定しない。

- X点検票：X点検権限が必要
- Z精算票：Z精算権限と責任者PINが必要
- 再印字には「再印字」表示、再印字日時、再印字担当者を追加
- 再印字要求は新しいdocument_print_jobsとして追加
- 監査ログSETTLEMENT_REPRINTを保存
- 元の点検・精算データは更新しない

## 6. 旧データ

v0.26以前のレポートは完全スナップショットを持たない。

過去に作成済みの点検・精算票印刷ジョブがある場合は、その保存済みpayload_textを使用して再印字する。保存済みpayload_textもない場合は、不正確な再計算を避けるため再印字を拒否する。

## 7. 実機確認

- 同じ営業日の第1営業・第2営業を別セッションで絞り込めること
- X点検後に売上を追加しても、過去X点検票が変化しないこと
- Z精算票再印字時に責任者PINが必要なこと
- 再印字票に再印字情報が出ること
- 再印字の監査ログが残ること
- プリンタ設定を58mm／80mmへ変更した各状態で欠けずに印字できること
- 通信失敗時に印刷ジョブが保持されること
