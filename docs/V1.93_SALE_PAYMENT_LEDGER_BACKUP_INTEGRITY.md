# v1.93 売上支払台帳の非破壊整合性検査

## 問題
以前の復元前・復元後DB診断（`DataProtectionManager.inspectDatabase`）では売上`sales.total_amount`と`sale_payments.applied_amount`のSUMを照合したが、**合計が同じでも支払明細の順序欠番・重複・受取額逆転・不正な支払方法**を検知できなかった。特に端末移行・バックアップ復元で壊れた明細が有効扱いとなるリスクがある。

## 対応
- `SalePaymentLedgerIntegrityV193.INVALID_ROW_SQL`：`applied_amount > 0`、`received_amount >= applied_amount`、保存済み`payment_method`が`PaymentMethod`の正式な列挙値に含まれることを検査。
- `SalePaymentLedgerIntegrityV193.INVALID_SEQUENCE_SQL`：`sale_id`ごとの`sequence_no`が1始まり・欠番/重複なしであることを`MIN/MAX/COUNT(DISTINCT)`で検査（Android API26のSQLiteでも利用可能）。
- `DataProtectionManager.inspectDatabase`のERROR診断に追加。`inspectDatabaseFile`でバックアップ・復元候補を検査し、`DatabaseRecoveryIntegrityV116.verifyFinal`では復元後DBを再検査。
- `V193SalePaymentLedgerBackupIntegrityTest.kt`追加。異常メソッド、受取金額逆転、欠番・重複・巨大番号、配線の退行を検証。

## 制限
DBの中身は勝手に修正しない。検出時は復元/正常判定を停止し、履歴と実決済を照合する。過去の売上内訳に既存の欠損がある場合は診断失敗になる。実機での復元・端末履歴・印刷/CD接続・正式配信は未受入。
