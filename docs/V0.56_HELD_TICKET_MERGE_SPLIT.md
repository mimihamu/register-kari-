# v0.56 保留伝票 結合・分割 安全基盤

## 目的

v0.14で保留伝票の退避・呼出・名称変更・削除の安全化を行った後も、開発ロードマップに残っていた「伝票結合」「伝票分割」を実装するための安全基盤を追加する。

この版では、保留伝票の結合・数量指定分割をSQLiteトランザクションで実行するドメイン処理と検証テストを追加する。既存の販売・会計・Google Drive同期・印刷・顧客表示の動作は変更しない。

## 結合

- 結合元と結合先は別伝票であることを必須とする。
- 結合先の明細順を維持し、その後ろへ結合元の明細を追加する。
- 商品、数量、単価、値引、備考、税スナップショットを維持する。
- 結合先明細の置換、税スナップショット再保存、結合元削除を1つのSQLiteトランザクションで実行する。
- 途中で例外が発生した場合はトランザクション全体をロールバックし、中途半端な結合状態を残さない。
- 同じ伝票同士の結合は禁止する。

## 分割

- 明細ごとに0～元数量の範囲で移動数量を指定できる基盤とする。
- 数量の一部だけを分割する場合、行値引は数量比で按分する。
- 按分時の端数は元伝票側へ残し、分割前後を合算した値引総額・値引後金額が変化しないようにする。
- 将来税率を含む商品税スナップショットを分割元・分割先の双方へ引き継ぐ。
- 1点も移動しない分割は禁止する。
- 全商品を移動して元伝票を空にする操作は禁止する。全移動相当の場合は名称変更・呼出など既存操作を使用する。
- 元伝票明細の置換、新伝票作成、双方の税スナップショット保存を1つのSQLiteトランザクションで実行する。

## データ保護

この変更は以下を自動削除しない。

- SQLite売上
- Sales Journal
- Drive上JSON
- 同期fingerprint
- 取込済み売上
- SENT済みOutbox
- 隔離履歴
- 同期履歴

結合で削除されるのは、利用者が明示的に結合元として指定した「保留伝票」だけであり、売上確定データには触れない。

## UIについて

v0.56は安全な結合・分割エンジンを先に確定する版とする。販売画面「伝票一覧」からの操作UIは、同エンジンを利用して次の累積版で接続する。UI接続前に、DB処理・税・値引の不変条件をCIで固定する。
