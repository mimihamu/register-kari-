# v0.91 SCR-767 データ保全レスポンシブ対応

## 目的

v0.90で更新状態の現場可視化をSCR-767「データ保全・バックアップ・復元」へ追加した結果、小さい横画面や大きいフォント倍率では、画面下部のバックアップ・復元操作へ到達しづらくなる余地がありました。

v0.91では、既存のバックアップ・復元ロジックを変えず、SCR-767をv0.29で導入済みの共通レスポンシブ基盤へ接続します。

## 対象

- SCR-767 データ保全・バックアップ・復元
- 800×480dp相当から1920×1080dp相当の横画面
- Androidフォント倍率1.30以上を含むCompact判定

## Compact時の動作

`RegisterResponsiveLayoutPolicy`の判定を使用します。

- 幅1000dp未満
- 高さ600dp未満
- フォント倍率1.30以上

上記のいずれかでCompactになります。

Compact時は以下を行います。

- ヘッダー高、画面余白、カード余白、下部バー高を共通レスポンシブ値へ変更
- 左パネル幅を470dpから360dpへ縮小
- 左の「整合性診断／更新状態／自動バックアップ」を独立縦スクロール化
- 右の「バックアップ一覧／ロールバック／外部保存／復元」を独立縦スクロール化
- 右側バックアップ一覧は80〜150dpの範囲に抑え、復元操作領域を画面下へ追い出さない
- 下部メッセージを最大2行に制限し、「設定へ戻る」を常時下部バーへ保持

## 維持する仕様

v0.91はレイアウト対応のみです。以下は変更しません。

- SQLite整合性診断
- 復元前ブロッカー判定
- 通常バックアップ作成
- 自動バックアップ要求
- Google Drive／USB外部保存導線
- バックアップ検証
- 責任者PIN判定
- 復元予約条件
- 復元予約取消
- v0.86ロールバック検証
- v0.90アプリ更新状態表示
- 売上、税、支払、印刷、Drive、CDの業務ロジック

## データ保護

今回のUI変更から、売上・履歴・同期・バックアップ内容を変更する処理は追加しません。

- `sales` / `sale_items` / `sale_payments` の削除・更新なし
- Sales Journal削除なし
- Drive JSON / fingerprint / SENT Outbox / quarantine / sync history削除なし
- ロールバックDB削除なし
- 復元条件緩和なし

## ソフトウェア検証

- 800×480 / fontScale 1.0 がCompact判定になること
- 1280×720 / fontScale 1.30 がCompact判定になること
- Compact時のみ左右パネルを独立スクロールすること
- 復元PIN、検証、復元予約、取消、ロールバック再検証がソース上維持されること
- 累積unit test / Kotlin compile / APK build

## 最終総合実機試験

ユーザー方針により、v0.91単体での実機確認は行わず、開発終盤の**最終総合実機試験**へ繰り越します。

最終確認項目:

- 800×480〜1920×1080横画面
- Android表示サイズ変更
- フォント倍率1.0 / 1.3 / 1.5 / 2.0相当
- 左右パネルのスクロール到達性
- ソフトキーボード表示中の復元操作到達性
- 実バックアップ作成・検証・復元予約・取消
- v0.86ロールバック表示
- v0.90更新状態表示
