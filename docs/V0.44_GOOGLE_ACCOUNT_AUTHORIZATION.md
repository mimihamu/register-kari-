# v0.44 Googleアカウント認可基盤

## 1. 方針修正

v0.43までのGoogle Drive連携は、AndroidのStorage Access Framework（SAF）からGoogle Driveアプリのフォルダを選択する方式でした。

この方式は選択フォルダの共有には有効ですが、つぐレジ／つぐレジ＋がGoogleアカウントを登録し、Google Drive APIへ直接接続する方式ではありません。

v0.44では、Googleアカウント選択、Drive権限同意、Drive API接続確認、連携解除を行う認可基盤を追加します。v0.43のフォルダ方式はUSB・端末フォルダ・既存運用のための互換機能として残します。

## 2. 対象アプリ

### つぐレジ

- applicationId（本番）：`jp.co.tenposinfo.register`
- applicationId（開発版）：`jp.co.tenposinfo.register.dev`
- 用途：売上ジャーナルJSONをGoogle Driveへ送信するアカウントの登録

### つぐレジ＋

- applicationId（本番）：`jp.co.tenposinfo.register.plus`
- applicationId（開発版）：`jp.co.tenposinfo.register.plus.dev`
- 用途：Google Driveから売上ジャーナルJSONを取得するアカウントの登録

つぐレジとつぐレジ＋は、同一のGoogle CloudプロジェクトとOAuth同意画面を使用し、Android OAuthクライアントはapplicationIdと署名証明書ごとに登録します。

## 3. 認可フロー

1. 利用者が「Googleアカウント連携」を開く
2. Android端末上のGoogleアカウントを選択
3. `drive.file`権限を要求
4. 必要な場合はGoogleの同意画面を表示
5. 一時アクセストークンを取得
6. Drive API `about.get`を呼び出して接続確認
7. メールアドレス、表示名、permissionId、確認日時を端末へ保存
8. 連携解除時はGoogle側の許可を取り消し、端末内の登録情報を削除

## 4. 要求する権限

要求スコープ：

`https://www.googleapis.com/auth/drive.file`

アプリが作成したファイル、または利用者がアプリへ明示的に共有したファイルを扱うための限定スコープです。Drive全体を無条件に読み取る権限は要求しません。

## 5. 保存する情報

端末へ保存する情報：

- Googleアカウントのメールアドレス
- Googleアカウントの表示名
- Drive permissionId
- 最終接続確認日時

保存しない情報：

- Googleアカウントのパスワード
- アクセストークン
- 更新トークン
- OAuthクライアントシークレット

アクセストークンはGoogle Play開発者サービスから必要時に取得し、Drive API接続確認に使用した後、永続保存しません。

## 6. Google Cloudで必要な設定

### 6.1 プロジェクト作成

Google Cloud Consoleで、つぐレジ専用のプロジェクトを作成します。

例：`tsuguregi-production`

### 6.2 Google Drive API有効化

「APIとサービス」からGoogle Drive APIを有効化します。

Drive APIが無効の場合、アプリは「Google Drive APIが無効」と表示します。

### 6.3 OAuth同意画面

アプリ名、サポートメール、連絡先などを登録します。

公開前のテスト運用では、使用するGoogleアカウントをテストユーザーへ追加します。

### 6.4 Android OAuthクライアント

次の組み合わせを登録します。

| アプリ | applicationId | 署名証明書 |
|---|---|---|
| つぐレジ 開発版 | `jp.co.tenposinfo.register.dev` | 開発署名SHA-1 |
| つぐレジ 本番版 | `jp.co.tenposinfo.register` | 本番署名SHA-1 |
| つぐレジ＋ 開発版 | `jp.co.tenposinfo.register.plus.dev` | 開発署名SHA-1 |
| つぐレジ＋ 本番版 | `jp.co.tenposinfo.register.plus` | 本番署名SHA-1 |

v0.44のCI成果物に、開発署名証明書のSHA-1とSHA-256を記録します。本番署名証明書は本番鍵確定後に別途登録します。

applicationIdまたは署名SHA-1がGoogle Cloudの登録内容と一致しない場合、アプリは「Google Cloud設定が必要」と表示します。

## 7. v0.44の実装範囲

実装済み：

- Googleアカウント選択
- `drive.file`権限要求
- 追加同意画面の起動
- Drive API `about.get`接続確認
- 接続アカウント表示
- 別アカウントへの変更
- 接続再確認
- Google側アクセス権限の取消
- Google Cloud設定不足の表示
- Drive API未有効の表示
- SAFフォルダ方式を互換機能として維持

未実装：

- つぐレジからDrive APIへの売上JSON直接アップロード
- つぐレジ＋からDrive APIによる売上JSON一覧取得・ダウンロード
- DriveフォルダのAPI自動作成
- アップロード済みfileIdの管理
- Drive Changes APIによる差分同期
- アプリ終了中のアカウント認可更新を含む完全自動同期

直接アップロード・ダウンロードは、認可基盤を実機確認した後の次段階で実装します。

## 8. エラー表示

- Google Cloud設定が必要
- Google Drive APIが無効
- Googleアカウント認可失敗
- Drive API接続確認失敗
- 利用者によるキャンセル
- 連携解除失敗

フォルダ方式の権限失効・提供元不在・読取失敗は、v0.43の診断表示を継続します。

## 9. 実機確認事項

- 端末上のGoogleアカウント選択画面
- OAuth同意画面
- `drive.file`追加認可
- Google CloudのAndroid OAuthクライアント照合
- Drive API `about.get`成功
- テストユーザーと公開状態の違い
- Google Workspace管理アカウントの制限
- Google Play開発者サービスがない端末
- アカウント変更
- 権限取消後の再接続
- アプリ再起動後の登録表示
- 開発署名と本番署名の切替

実機で確認していない項目を、確認済みとは扱いません。
