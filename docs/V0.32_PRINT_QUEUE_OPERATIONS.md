# v0.32 統合印刷キュー業務運用

## 目的

プリンター停止や通信断が発生しても、未印刷ジョブを二重印刷せずに確認・再送・破棄できる業務運用を完成させる。

## 対象

- 売上レシート
- 返品・取消レシート
- X点検票／Z精算票
- 各帳票の再印字ジョブ

## 状態

- `PENDING`: 自動印刷待ち
- `PRINTING`: 送信処理中
- `RETRY`: 自動再試行待ち
- `FAILED`: 送信結果不明または再試行上限など、人の確認が必要
- `COMPLETED`: 印刷完了
- `DISCARDED`: 責任者承認で破棄済み

`DISCARDED`は完了と同様に終端状態とし、未印刷件数、Z精算前の未印刷警告、バックアップ復元前の未処理印刷件数へ含めない。

## 絞り込み

- 状態: 未完了、要対応、すべて、完了、破棄済み
- 帳票種別: 全種別、売上、返品・取消、点検・精算
- 作成日時: 全期間、本日、7日以内、30日以内
- 試行回数: 全試行回数、未試行、1～2回、3回以上
- Job番号、参照番号、エラー、印字内容による検索

要対応ジョブを優先して並べる。

## 失敗理由分類

接続不可、タイムアウト、用紙、カバー、カッター、送信結果不明、処理中断、設定不備、その他へ分類し、担当者が確認すべき内容を表示する。

## 手動操作

### 再試行待ちへ

`PENDING`、`RETRY`、`FAILED`だけを対象とする。操作担当者と元状態を破棄更新と監査ログを同一SQLiteトランザクションで記録する。

### 安全印刷

印刷前にプリンター状態を確認し、READYまたはWARNINGの場合だけ送信する。成功・失敗を破棄更新と監査ログを同一SQLiteトランザクションで記録する。

### 強制印刷

送信結果不明時などに、紙が出ていないことを目視確認した場合だけ使用する。

- 目視確認チェック必須
- 責任者PIN必須
- 承認責任者名を破棄更新と監査ログを同一SQLiteトランザクションで記録
- 成功・失敗を破棄更新と監査ログを同一SQLiteトランザクションで記録

### ジョブ破棄

- `PENDING`、`RETRY`、`FAILED`だけを対象とする
- 4文字以上の破棄理由必須
- 責任者PIN必須
- 担当者、承認責任者、理由、帳票種別、参照番号を破棄更新と監査ログを同一SQLiteトランザクションで記録
- 完了済み、印刷中、破棄済みジョブは破棄不可

## 印字幅

58mm／80mmはプリンター設定で固定する。印刷キューではジョブ作成時の設定スナップショットを表示するだけで、印刷時には指定・変更しない。

## レスポンシブ

共通レスポンシブポリシーを使用する。十分な幅と高さがある場合は概要・一覧・詳細の3列、小型画面やフォント拡大時は縦積みとスクロールへ切り替える。主要操作は48dp以上を維持する。

## 監査イベント

- `PRINT_JOB_RETRY_REQUESTED`
- `PRINT_JOB_MANUAL_SEND_SUCCEEDED`
- `PRINT_JOB_MANUAL_SEND_FAILED`
- `PRINT_JOB_FORCE_SEND_SUCCEEDED`
- `PRINT_JOB_FORCE_SEND_FAILED`
- `PRINT_JOB_DISCARDED`
