# v0.80 レスポンシブ点検・精算履歴 整合確認接続

## 目的

v0.78で追加した「保存値と現在DBを照合」と、v0.79で追加した追記専用監査を、現在のレジ管理ハブから開くレスポンシブ版 `SCR-520 点検・精算履歴` でも利用できるようにする。

従来は旧管理画面 `OperationsActivity` の点検・精算履歴からのみ整合確認を実行でき、`OperationsHubActivityV030` から開く `SettlementHistoryActivityV030` には同機能が接続されていなかった。

## 画面動作

選択中のX点検またはZ精算に対し「保存値と現在DBを照合」を表示する。

整合確認には以下を両方必要とする。

- `VIEW_SALES`
- 対象レポートに対応する `X_INSPECTION` または `Z_SETTLEMENT`

ボタン表示時の権限だけでは信用せず、実行時に `OperatorSessionRegistry.current()` から現在セッションを再取得し、権限を再確認する。

## 比較

v0.78の `SettlementReconciliationPolicyV078.compare()` をそのまま使用する。

- 保存済み点検・精算snapshot
- 対象営業セッションの現在DB集計

を比較し、結果を `OK / INFO / ALERT` で表示する。

X点検後の営業継続による差異は既存v0.78仕様どおりINFO、Z精算後の差異はALERTとする。税・インボイス計算、保存済みsnapshot、売上、支払、返品・取消の計算ロジックは変更しない。

## 監査

v0.79の `SettlementReconciliationAuditStoreV079` を利用し、照合成功時は既存 `operation_audit` に追記する。

監査INSERTに失敗した場合は整合確認成功として表示しない。監査記録成功後のみ「整合確認を監査履歴へ記録しました。」を結果へ付加する。

`operation_audit`、売上、点検・精算snapshot等に対するUPDATE/DELETEは行わない。

## データ安全

本変更で以下を変更・削除しない。

- 売上SQLite既存行
- Sales Journal
- Google Drive JSON
- sync fingerprint
- imported sales
- SENT Outbox
- quarantine履歴
- sync履歴
- 通常レシート再印字監査履歴
- 点検・精算snapshot
- 税・インボイス計算

Google DriveのOAuth token、Authorization header、content URI、生の売上JSONを診断・監査へ出力する処理は追加しない。
