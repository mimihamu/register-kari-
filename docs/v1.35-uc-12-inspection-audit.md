# v1.35 UC-12「点検」監査

## 仕様基準

仕様書 v2.5 の UC-12 / REP-001 を基準とする。

- X点検は現在の営業セッションを締めず、営業途中に複数回実行できる。
- 点検結果は画面表示・印刷・PDF保存できる。
- 点検前後で営業期間を変更せず、X点検自体で営業終了しない。
- 帳票には売上総額、値引・割引、返品・取消、純売上、件数、客数、点数、客単価、税率別、支払別、開始釣銭、入金、出金、現金理論、任意の現金実査・過不足等を含める。
- 現金実査を入力しない場合、X点検帳票の実査・過不足は空欄とする。
- 印刷/PDF出力失敗によって、保存済みX点検レコードを無効化・巻き戻ししない。
- 権限マトリクス上、点検は `X_INSPECTION` 権限を持つ責任者/管理者相当が実行する。

## 現行実装との突合

### 営業継続・複数回実行

`OperationsStore.recordSettlement` はX/Z共通スナップショットを追記するが、`business_sessions` を終了状態へ更新する分岐は `Z_SETTLEMENT` のみ。

`OperationsIdempotencyPolicy.settlementKey` はZに永続キーを付与し、Xには永続単発キーを付けない。`SecureOperationsCoordinator` のプロセス内排他は同時連打を防ぐだけで、処理完了後の次回X点検は許可される。

### 集計

`summaryForSession` は営業セッションIDを基準に以下を集計する。

- 売上総額 / 売上件数
- 元売上連動の返品・取消
- 元取引なし返品
- 売上支払 / 返金支払 / 元取引なし返品支払
- 入金 / 出金
- 開始釣銭
- 現金理論残高
- 未印刷 / 未会計伝票 / 販売途中 / 未完了決済

`SettlementReportingRuntimeV135` は値引、税、点数、明示保存された客数をX/Z履歴にスナップショットする。客数は取引件数から推測しない。

`SettlementTaxBreakdownRuntimeV135` は税率別対象額・税額に売上および返品/取消を反映する。

### 帳票・履歴・再印字・PDF

`OperationDocumentRenderer.renderSettlement` は58/80mm共通の論理帳票を生成し、Xは `【X点検票】` と `営業日は継続中です` を出力する。

`document_print_jobs` へ点検票を追記し、`SecureOperationsCoordinator` がコミット後に `AutomaticPrintScheduler.enqueueNow` を要求する。再印字も同じ保存済みX履歴から別印刷ジョブとして追記する。

PDFは `SettlementPdfExportV135` が保存済み `reportId` を再読込してStorage Access Frameworkの選択先へ出力する。PDF保存は点検DBトランザクション外なので、PDF保存失敗でX点検レコードは巻き戻らない。

## v1.35で修正した差分: X点検の現金実査未入力

従来は内部互換のため、X点検で現金実査を省略すると `actual_cash` に現金理論値を保存していた。この内部数値互換は維持するが、v2.5帳票仕様では「実在高未入力時は空欄」であるため、表示意思を別管理する。

追加した `SettlementActualCashPresentationV135` は:

- X/Z確定時に「実査を明示入力したか」を `settlement_actual_cash_input_v135` へ保存する。
- 最初の点検票生成中はThreadLocalの確定コンテキストを使い、sidecar確定前でも未入力を空欄でレンダリングする。
- sidecar保存はX/Z本体コミット後の補助メタデータであり、失敗しても確定済み点検を失敗扱いに戻さない。
- sidecar書込前にプロセス停止しても、保存済み `document_print_jobs.payload_text` の現金実査行を復旧ヒントにして、後日のPDF/再印字で架空の実査値を表示しない。
- Z精算は現金実査必須の既存安全ゲートを維持する。

## Google Drive / つぐレジ＋との境界

仕様書v2.5ではX点検・Z精算・期間固定レポートを `sync.saleUpload=SETTLEMENT_ONLY` に関係なくGoogle Drive送信対象とし、管理側で点検スナップショットを参照する要件がある。

ただしプロジェクトロードマップでは、バックアップ/リストア/CSV/Google Drive/つぐレジ＋の同期完成は **v1.36** 対象である。UC-12のv1.35監査ではローカルのX点検・集計・履歴・印刷・PDF・営業継続を固定し、`SETTLEMENT_ONLY` の実送信、ACK、つぐレジ＋取込はv1.36で閉鎖する。これをUC-12で「同期確認済み」とは扱わない。

## 自動確認項目

`V135Uc12InspectionAuditTest` で以下を固定する。

1. Xは永続単発キーを持たず複数回実行可能、Zは二重精算防止キーを持つ。
2. 営業セッション終了UPDATEはZのみ。
3. X点検権限を実行直前に再検証する。
4. 売上・返品取消・元取引なし返品・支払返金・入出金・現金理論を同一営業セッションで集計する。
5. 値引・税・点数・客数・税率別集計の帳票経路が存在する。
6. 印刷キュー登録、監査ログ、印刷Schedulerが存在する。
7. 現金実査未入力Xは帳票/PDF/再印字で実査・過不足を空欄にする。
8. PDFは点検確定トランザクション外で、保存失敗がX点検を巻き戻さない。
9. Google Drive `SETTLEMENT_ONLY` 同期はv1.36依存として明示し、v1.35で確認済みと誤認しない。

## 実機未確認

以下は自動テスト成功後も実機確認が必要。

- 営業中にX点検を連続して複数回実行し、各履歴が別No.で残る。
- X点検後も営業状態がOPENのまま、新規販売・会計を継続できる。
- 売上総額、値引、返品/取消、純売上、税率別、支払別、客数、点数、客単価が手計算と一致する。
- 入金/出金/現金返金を含む現金理論残高が実ドロアー運用と一致する。
- 現金実査未入力Xの58mm/80mm実印字で「現金実査」「過不足」の値部分が空欄になる。
- 現金実査入力済みXでは入力額と過不足が58mm/80mm双方へ印字される。
- X履歴から再印字しても、未入力/入力済み状態が元帳票と一致する。
- Storage Access FrameworkでPDF保存し、帳票内容が印刷プレビューと一致する。
- PDF保存をキャンセル/失敗してもX履歴が残り、営業を継続できる。
- `X_INSPECTION` 権限なし担当者から点検画面/確定が拒否される。
- 実プリンタ紙切れ/通信失敗後もXレコードが残り、同一履歴から再印字できる。
- Google Drive / つぐレジ＋のX点検同期、`SETTLEMENT_IMPORT_ACK` はv1.36実装後に実アカウントで確認する。

実機未確認のため、Issue #137上のUC-12は完了扱いにしない。
