# v1.36 / 正式仕様 v2.5 §16.9 印刷ジョブ不確定送信安全性

- TCP送信前に `SENDING` を永続化する。`PRINTING` は旧DB互換の不確定状態としてのみ扱う。
- `SENDING` / 旧 `PRINTING` は通常の自動印刷候補に含めず、再起動後も自動再送しない。
- WRITE_STARTED以降の通信結果不明は `SENDING` のまま保持する。接続開始前など「未送信が確実」な失敗のみ既存の安全再試行対象とする。
- 統合印刷キューに「印刷済みの可能性」を表示し、担当者が「完了扱い」または「再印刷」を選択する。判断理由は4文字以上必須。
- 再印刷は元ジョブをPENDINGへ戻さず、新しいPrintJobを作成する。新ジョブへ `source_job_id` / `reprint_reason` / `reprint_operator_id` を保存する。
- 元ジョブは再印刷作成後も履歴として残し、新ジョブIDへの引継ぎと解決情報を保存する。
- 完了扱い・再印刷作成は `operation_audit` へ担当者・理由・元/新job IDを記録する。
- 物理プリンターでの電源断・LAN断・WRITE_STARTED後切断・再起動復旧は最終総合実機試験で確認する。
