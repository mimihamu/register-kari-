# v1.21 Google Drive sync single-flight

## 目的

v1.20でGoogle Drive売上JSONの全ページ取得を保証した後に、同期入口の競合を確認した。

現行実装では periodic / startup / manual が別々のWorkManager unique work名を使用し、画面からの直接同期も別経路で実行されるため、同一プロセス内で複数のGoogle Drive同期が同時に走れる状態だった。

同時実行時は、同一fileIdのdownload / import / fingerprint処理が重複し、さらに共通SharedPreferencesの同期状態を複数runが更新するため、先に開始したworkerの遅い失敗通知が、後から開始した正常な同期のrunning状態を上書きできる。

また画面直接同期の失敗時は、repositoryが保存した正しいfailure categoryを画面側の汎用`failed(message)`がUNKNOWNで再保存する経路があり、診断状態を劣化させる実害も確認した。

## v1.21の修正

- `GoogleDriveSyncSingleFlightV121` を追加し、`GoogleDriveDirectSyncRepository.synchronize()` の全処理を公平な `ReentrantLock` で直列化した。
- periodic / startup / manual / 画面直接同期のどの入口でも、Drive list → download → SalesJournal import → fingerprint → 次page、というv1.20の同期本線を同時に2本走らせない。
- startup と manual のone-time WorkManager名を `tsuguregi-plus-drive-api-sync-immediate` に統一した。
  - startupは `KEEP`。
  - manualは `APPEND_OR_REPLACE`。
  - periodic workは周期管理上別名のままだが、repository single-flight境界で必ず直列化される。
- 同期開始時に `run_token` を発行し、成功・失敗の状態更新はそのrun所有者だけが確定できるようにした。
- repository内部の失敗はlock解放前に所有runとして記録する。
- repository外で発生した認可等の失敗通知は、別の同期が `running=true` の間は状態を上書きしない。
- 画面直接同期の失敗通知は分類済みcategoryをそのまま保存し、UNKNOWNへの二重上書きを廃止した。
- stale run修復時は `run_token` も破棄する。

## 維持する既存保証

v1.20までの以下の保証は変更しない。

- Drive server version fingerprintによる差分判定。
- server version欠落時のdownload + SHA-256 fallback。
- `nextPageToken` がなくなるまでの全ページ取得。
- `incompleteSearch=true` のretryable failure化。
- page token循環検出。
- page内の SalesJournal import → fingerprint → 次page の順序。
- duplicateImportKey衝突の隔離・監査と完全一致再送の冪等性。
- Drive上の削除と取込済みローカル売上の自動削除を連動させない既存方針。

## 回帰テスト

`V121GoogleDriveSyncSingleFlightTest` で以下を固定する。

- 2スレッドからsingle-flight境界へ入っても同期本体が同時実行されないこと。
- run ownership tokenが存在すること。
- startup/manualが同じimmediate work chainを使用すること。
- 画面直接同期が分類済みfailure categoryを保持すること。
- v1.20のpage処理順序がsingle-flight境界内で維持されること。

CI cumulative source gateにもv1.21 markerとversion identityを追加する。

## 実機確認へ繰り越す項目

以下はコード・JVM回帰試験・CIで保証する範囲とは分け、最終総合実機試験へ繰り越す。

- 実Google Driveアカウントでperiodic実行中にmanual同期を要求した場合の直列実行。
- アプリ起動直後のstartup同期とperiodic同期が近接した場合のWorkManager実挙動。
- 長時間同期中のプロセス停止・再起動後のstale run修復表示。
- v1.20から継続している5,000件超、ページ途中ネットワーク断、実端末統合確認。

これらは実機未確認であり、「確認済み」とは扱わない。
