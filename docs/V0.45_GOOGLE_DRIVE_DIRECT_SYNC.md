# v0.45 Google Drive API 売上ジャーナル直接同期仕様

## 1. 目的

v0.44で追加したGoogleアカウント認可基盤を、売上ジャーナルJSONの実送受信へ接続する。

- つぐレジ：SQLiteで確定した売上ジャーナルJSONをGoogle Drive APIへ直接アップロードする。
- つぐレジ＋：Google Drive APIから対象JSONを検索・差分取得し、既存の`SalesJournalImportRepository`へ渡す。
- v0.43以前のStorage Access Frameworkによるフォルダ方式は、USB・端末フォルダ・Driveアプリ経由の互換用として維持する。

Google Driveは同期・バックアップ経路であり、唯一の原本ではない。つぐレジではSQLiteとローカルOutbox、つぐレジ＋では取込済みSQLiteを保持する。

## 2. 認可と秘密情報

- Google Play開発者サービスの`AuthorizationClient`を使用する。
- スコープは`https://www.googleapis.com/auth/drive.file`だけを使用する。
- アクセストークンは同期実行時に都度取得する。
- アクセストークン、更新トークン、Googleアカウントのパスワードは永続保存しない。
- 永続保存するアカウント情報は、メールアドレス、表示名、permissionId、最終接続確認日時だけとする。
- 共有ドライブはv0.45対象外とし、`supportsAllDrives=false`を使用する。

## 3. Driveフォルダ構成

```text
つぐレジ/
  stores/
    {storeId}/
      terminals/
        {terminalId}/
          journal/
            {businessDate}/
              {duplicateImportKey}.json
```

フォルダ名だけでは同一性を判断しない。親fileIdと`appProperties`を併用する。

主な`appProperties`：

```text
app = tsuguregi
role = sales-journal-root | stores | store | terminals | terminal | journal | business-date | sales-journal
storeId = ...
terminalId = ...
businessDate = YYYY-MM-DD
duplicateKey = sj1-...
contentSha256 = ...
```

同一Google Cloudプロジェクト・同一利用者認可で、つぐレジが作成したファイルをつぐレジ＋から参照する。`drive.file`でのアプリ間参照可否は実機OAuth環境で確認する。

## 4. つぐレジの直接アップロード

### 4.1 入力

既存の`JournalOutboxStore`が生成したローカルJSONを使用する。

- ローカル格納先：`filesDir/drive-sync-staging`
- 対象Outbox状態：`STAGED`または`SENT`
- `SENT`も対象に含める理由：互換用フォルダ送信が先に完了しても、Drive API直接送信を独立して完了させるため。

### 4.2 重複防止

- 外側エンベロープ契約はschemaVersion 1を維持する。
- 重複キーは既存仕様を維持する。

```text
sj1- + SHA-256("1|storeId|terminalId|businessDate|eventType|eventId")
```

- Drive上では`duplicateKey`と親fileIdを検索条件にする。
- `contentSha256`が一致する場合は既存ファイルとして送信済み扱いにする。
- 同じ重複キーで内容が変わった場合は`files.update`で更新する。

### 4.3 SQLite管理

`drive_api_uploads`を追加する。

- outbox_id
- event_id
- file_id
- content_sha256
- modified_time
- status
- attempt_count
- next_attempt_at
- last_error
- updated_at

Outbox本体を置き換えず、Drive API配送状態を別テーブルで管理する。

### 4.4 Outbox状態との関係

- 互換用フォルダ送信が無効の場合、Drive API送信成功でOutboxを`SENT`にする。
- 互換用フォルダ送信が有効の場合、Drive APIとフォルダ送信を独立管理し、フォルダ送信の既存動作を壊さない。
- 永久失敗時も互換用フォルダ送信が有効なら、Outbox本体を自動で`FAILED`へ変更しない。
- ネットワーク切断時はローカルJSONとOutboxを保持し、WorkManagerで再試行する。

## 5. つぐレジ＋の差分同期

### 5.1 検索

`files.list`で以下を満たすファイルを検索する。

- `spaces=drive`
- `trashed=false`
- MIMEタイプ`application/json`
- `appProperties.app=tsuguregi`
- `appProperties.role=sales-journal`
- 取得fieldsを必要項目へ限定

### 5.2 差分判定

`drive_sync_files`に以下を保存する。

- file_id
- file_name
- modified_time
- content_sha256
- store_id
- terminal_id
- business_date
- last_processed_at

通常同期ではfileIdとmodifiedTimeを比較し、変更候補だけをダウンロードする。ダウンロード後にSHA-256を比較し、内容が同一なら取込を省略する。

### 5.3 取込

取得したJSONは既存の`SalesJournalImportRepository.importDocuments`へ渡す。

- JSON契約検証を再利用する。
- `duplicateImportKey`のUNIQUE制約で二重計上を防ぐ。
- 不正JSONは既存の隔離テーブルへ記録する。
- 強制再取込でも売上が二重計上されない。

### 5.4 実行方法

- Googleアカウント連携画面から手動差分同期
- Googleアカウント連携画面から全件再取込
- アプリ起動時の自動差分同期
- WorkManagerによる1時間ごとの定期差分同期

## 6. エラー分類

### つぐレジ

- 認可切れ
- Google Drive API未有効
- 容量不足
- 権限不足
- レート制限
- 通信失敗
- Drive側一時障害
- 不正データ

### つぐレジ＋

- 認可切れ
- Google Drive API未有効
- 権限不足
- レート制限
- 通信失敗
- Drive側一時障害
- 不正データ／読込失敗

レート制限、通信失敗、Drive側一時障害は再試行対象とする。認可切れ、API未有効、容量不足、権限不足、不正データは利用者または管理者の操作を必要とする状態として表示する。

## 7. 削除と解除

- Googleアカウント連携解除でローカル売上、取込済み売上、Outbox、同期履歴を削除しない。
- Drive上のファイル削除をローカル売上削除へ自動連動しない。
- ローカル売上削除をDrive上のファイル削除へ自動連動しない。
- v0.45では`files.delete`を通常同期処理で使用しない。
