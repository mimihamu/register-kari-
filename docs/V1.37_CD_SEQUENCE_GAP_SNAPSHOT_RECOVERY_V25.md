# v1.37 つぐレジ CD：sessionId・欠番検知・最新snapshot再取得

基準：正式仕様 v2.5 第30章、特に §30.5～30.6、CDP-NET-003/004/007、CDP-AT-05/06。

## 実装

- 既存の `schemaVersion=1`、WebSocket path `/customer-display/v1`、`orderItems`を変更せず、`messageType`（`SNAPSHOT` / `STATE_UPDATE`）と `sessionId` を追加した。古いPOSからの `messageType` 省略は完全 `SNAPSHOT` として後方互換受信する。
- POSの状態発行は同期化済みの全体sequenceを1ずつ採番する。待機⇔会計中のセッション境界でUUIDの `sessionId` を更新する。新セッションの最初の送信を `SNAPSHOT` とし、それ以外を `STATE_UPDATE` とする。旧版互換フィールドは維持。
- WebSocket初回接続・再接続時は、POSが現在の状態から `SNAPSHOT` を作って送信する。
- CDは接続ごとに最後に適用したsnapshotとsessionIdを追跡。未受信状態・sessionId変更・送信元インスタンス変更・sequence欠番の `STATE_UPDATE` を受けた場合、金額を直ちに隠し、マスクしたWebSocketテキストフレームの `{"messageType":"SNAPSHOT_REQUEST"}` を1回送る。返信まで通常更新を表示に適用しない。
- 重複・逆順の `STATE_UPDATE` は無視する。完全 `SNAPSHOT` を受信したときに最新値へ一括復帰し、同期保留を解除する。既存の表示キャッシュを接続直後の正本として用いない。
- POSサーバは `SNAPSHOT_REQUEST` に現在の完全snapshotを返す。遅い端末向けlatest-only送信キューで `SNAPSHOT` が後続の更新に合流しても、書き込み時に完全snapshotを優先するため、再取得要求が通常更新へすり替わらない。
- CDの順序ポリシー、スナップショットJSON往復と旧payload後方互換性、POS実WebSocketサーバへマスクした再取得要求を送るJVMテストを追加。

## 互換性・境界

- 初版の通信路とschema majorを変更しない。新しいPOS → 旧CDは従来フィールドで動作する。新しいCD → 旧POSは省略された `messageType` を `SNAPSHOT` として受信する。
- `sessionId` は表示専用のPOSプロセス内状態で、決済transactionIdや永続売上取引IDを代用しない。サーバ再起動後は新しいIDになる。
- 完全snapshotが遅延した場合に最新変更の取りこぼしを容認せず、CDは次回の受信で再取得する。通信断が長期化した場合は従来の再接続処理に移る。
- 仕様の `mode=CART/PAYMENT/CASH_RECEIVED/CHANGE`、`lineId`、`payment` object、ISO 8601 `sentAt`、`schemaVersion="1.0"` と現在の旧API形式との統合は残作業。旧端末互換を壊す一斉置換はしない。
- 実機間通信・Wi-Fi瞬断・1000更新の遅延/順序検証は未実施。APKのdebug署名は正式リリース署名ではない。
