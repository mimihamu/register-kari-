# v1.36 印刷結果 `PRINTED / ACCEPTED`

正式仕様書 v2.5 §16.9 の印刷結果区分を、既存キュー状態 `COMPLETED` と分離して永続化する。

## 状態と結果

- 既存キュー状態 `COMPLETED` は互換維持のため変更しない。
- `print_jobs.delivery_result` / `document_print_jobs.delivery_result` を既存DBへ冪等に追加し、次を保存する。
  - `PRINTED`: メーカー仕様確認済みの状態取得で、送信後に異常なしを確認した。
  - `ACCEPTED`: TCP送信は成功したが、信頼できる自動状態取得を使用できない。
- 既存 `COMPLETED` 行には結果を推測して補完せず `NULL` のまま残す。
- 結果列の保存が失敗した場合も印刷済みの可能性があるため、自動再送せず `SENDING` として担当者判断へ送る。

## 送信後確認

EPSON TM 日本語プロファイル (`EPSON_DLE_EOT`, メーカー仕様確認済み) のみ、送信成功後にリアルタイムステータスを取得する。プロトコル妥当・オンライン・カバー閉・用紙あり・停止/エラーなしを確認した場合だけ `PRINTED` とする。

STAR / 汎用 ESC/POS の DLE EOT 互換方式は「要実機確認」のため自動照会せず `ACCEPTED` とする。

送信後照会の timeout、通信断、用紙切れ、カバーオープン、エラー等では印刷済みか否かをソフトウェアから確定できない。既存の不確定送信安全策に接続し、ジョブを `SENDING` に保持して「完了扱い」または新規Jobでの「再印刷」を担当者が明示判断する。

## 対象経路

- 自動印刷: 売上レシート / 業務帳票
- 手動印刷: 売上レシート / 業務帳票
- 不確定ジョブを担当者が紙確認して「完了扱い」した場合は `PRINTED`

## 実機確認

以下はソフトウェア検証とは分け、実機確認完了まで **実機未確認** とする。

- EPSON TM-m30 / TM-m30II で送信後 DLE EOT が正常応答し `PRINTED` になること。
- WRITE_STARTED/FLUSHED 後のLAN断・電源断で `SENDING` が維持され二重印刷されないこと。
- 用紙切れ・カバーオープン時に `PRINTED` と誤確定しないこと。
- STAR / 汎用機で `ACCEPTED` と記録され、未検証状態照会を自動実行しないこと。
