# v1.36 RCPT-004 / 正式仕様 v2.5 SCR-720 画像スタンプ濃度・白黒化

Issue #137 #27 の旧名称「RCPT-004 ロゴ濃度（印刷結果で差が確認できる）」は、正式仕様 v2.5 §8.14 `SCR-720 店名スタンプ・印字デザイン設定` の画像スタンプ要件へ読み替えて実装する。

## 正式仕様との対応

- PNG / JPEG画像を読み込む。
- 推奨上限 2MB、2000×2000px を保存時に検証する。
- 透過画素は白背景へアルファ合成してから白黒化する。
- 明るさ、閾値を変更できる。
- 単純閾値、Bayer 4×4、Floyd-Steinberg の白黒化方式を選択できる。
- 縦横比を維持し、58mmは最大384dot、80mmは最大576dotへ縮小する。
- 58mm / 80mmの処理後画像を設定画面でプレビューする。
- 設定変更は次回の売上レシート印刷から使用する。
- 画像取込・設定保存・削除のたびに `stampVersion` を進める。

## v1.36で定義した数値

正式仕様 v2.5 は明るさと閾値の数値レンジ・初期値を定義していないため、次はv1.36の実装値であり正式仕様の固定値ではない。

- 明るさ: -100..100、初期値0
- 閾値: 0..255、初期値128

値はUI保存時に検証し、ラスタ生成時にも正規化する。明るさまたは閾値を変えたときに実際の白黒bit列が変わることをユニットテストする。

## 保存

画像本体はアプリ内部ストレージ `receipt_stamp_v136/source_image.bin` へ保存し、設定値は専用SharedPreferencesへ保存する。URI参照を永続化する方式ではなく、選択時にアプリ領域へコピーするため、元画像の移動・権限失効で次回印刷が壊れない構成とした。

## 印刷経路

`ReceiptStampGatewayV136` が売上レシートの各印刷部の先頭へ `GS v 0` ラスタ画像を付加する。

`EscPosEncoder` は1～3部のレシートを1つのpayloadへ連結するため、単純にpayload全体の先頭へ1回だけスタンプを付けると2部目以降で欠落する。v1.36では `ReceiptStampPayloadComposerV136` が、`PrinterCommandEncoder.beginDocument()` の固定開始列 `ESC @ / ESC t` を部境界として検出し、それぞれの直前へ同じスタンプを差し込む。部境界をカットコマンドに依存させないため、部分カット・フルカット・カットなしのいずれでも同じ扱いになる。

- WorkManagerの自動売上レシート印刷: `AutomaticPrintWorker`
- 統合印刷キューからの安全印刷 / 強制印刷: `UnifiedPrintQueueController`

返品・取消レシート、仮締め票、点検・精算票、領収書には今回の売上レシート用画像スタンプを無条件付加しない。

## 回帰保護

`V136ReceiptStampToneTest.kt` と `V136ReceiptStampMultiCopyTest.kt` で次を確認する。

- 透過画素が白になること。
- 明るさ・閾値変更で白黒出力bitが変化すること。
- 58mm=384dot / 80mm=576dotと縦横比維持。
- Bayer / Floyd-Steinbergが決定的に処理されること。
- ESC/POSラスタコマンドの幅・高さ。
- 設定UI、自動印刷、手動印刷の各経路に画像スタンプ処理が接続されていること。
- 1部・2部・3部でスタンプ数と文書数が一致すること。
- カットなし設定でも各部へスタンプが付くこと。
- スタンプ無効時は元payloadをbyte単位で変えないこと。

## 実機確認

コード、自動テスト、Kotlin compile、APK build、APK独立検証とは別に、実機プリンターでは最終受入時に以下を確認する。実機確認前は確認済みと扱わない。

- 同一画像で明るさ / 閾値を変え、紙面上でも濃淡・白黒化の差が判別できること。
- 58mm / 80mmで右端欠け、横伸び、異常改行がないこと。
- PNG透過部が黒ベタにならず白として出ること。
- Bayer / Floyd-Steinbergの出力が対象プリンターで正常であること。
- 自動発行、後レシート / 再発行の双方で画像スタンプが付くこと。
- 2部・3部設定でも全ての紙片に画像スタンプが1回ずつ付くこと。
