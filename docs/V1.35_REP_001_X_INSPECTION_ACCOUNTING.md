# v1.35 REP-001 X点検 集計補完

## 目的

v2.5のREP-001に合わせ、X点検で売上・返品/取消・値引/割引・税・支払方法別内訳・入出金・想定現金残高等を確認できるようにする。

以前の「X点検はread-only」という表現は不正確だった。正しくは、X点検は集計結果を画面表示し、印刷/PDF保存可能な点検票として保存するが、営業期間を締めず、精算番号/対象期間を進めず、営業セッションをOPENのまま維持する。

## 値引/割引・税のデータ源

推測再計算は行わず、確定売上に保存済みの値を使用する。

- 税: `sales.tax_amount`
- 値引/割引: `sale_items.discount_amount`
- 対象範囲: `sales.business_session_id`

返品/取消は従来どおり別の反対取引集計として表示し、売上確定済み税額・値引額を書き換えない。

## 固定スナップショット

`settlement_rep001_totals_v135` を追加し、各X/Zレポートに以下を固定する。

- `discount_total_yen`
- `tax_total_yen`

新規X/Zは `settlement_reports` INSERTと同一SQLiteトランザクション中にトリガーで保存する。これにより、X点検後に同じ営業セッションへ売上が追加されても、過去Xの再印字/PDF値は変化しない。

既存履歴は、レポートの `created_at` 以前に確定したappend-only売上だけを対象に一度だけ補完する。

## 出力

共通の `OperationDocumentRenderer.renderSettlement()` に以下を追加する。

- 値引・割引
- 消費税

同じレンダラーを使用する印刷/PDF/再印字で同一値を扱う。

画面側も同じ営業セッションの確定売上から値引・割引、消費税を表示する。

## REP-003監査イベント互換

バックアップ失敗を確認してZ精算を継続した場合の正規イベント名は以下とする。

`Z_SETTLEMENT_BACKUP_FAILURE_ACK`

旧実装名 `Z_SETTLEMENT_BACKUP_FAILURE_ACKNOWLEDGED` が書き込まれようとした場合も、append-only監査をUPDATE/DELETEせず、INSERT時に正規イベントへ変換して保存する。

## 営業状態

- X点検成功後: `OPEN` のまま
- Z精算成功後のみ: `CLOSED`
- Z確定直前: REP-003の5項目を再評価し、TOCTOUを防止

## 実機確認

コード・自動検証・APK独立検証とは別に、実機で以下を確認する。

1. X点検画面の値引/割引・税表示
2. 58mm/80mm実プリンタでのX点検票
3. X点検PDF保存内容
4. X点検後も販売継続できること
5. X点検後に売上を追加しても、過去X再印字の値が変化しないこと
6. Z精算成功時だけ営業終了すること
