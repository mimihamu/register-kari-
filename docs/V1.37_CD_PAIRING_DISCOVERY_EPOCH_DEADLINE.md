# CDペアリング受付と探索世代の安全性（v1.37）

不具合候補:
1. レジのDNS-SD登録処理が遅い場合、元の受付開始時刻から2分経過後も、コールバック完了時に新しい2分タイマーを張って共有トークンを広告する可能性があった。
2. CD検索を止めたり再検索した後、旧検索セッションのonDiscoveryStopped/onServiceResolved/onResolveFailedなどが後から入り、新しい検索を停止させたり期限切れ候補をUIへ混入させる可能性があった。
3. レジの旧広告解除コールバックが新しい登録の`registered`状態を上書きする可能性があった。

実装:
- ペアリング期限は受付開始時に定め、その時点から2分後に必ず停止処理を予約。広告登録遅延で受付期間を延ばさない。
- 受付時間が経過してからonServiceRegisteredが呼ばれた場合、登録を解除する。旧listenerからの登録解除通知は新しいlistenerの状態を変えない。
- CD探索では単調増加するdiscoveryGenerationを設け、start/stopで世代が変わった旧コールバックを全て破棄する。旧resolveService完了やonDiscoveryStoppedが再検索を妨げない。
- 登録中の共有トークンは従来どおりmDNS TXTへ載る。これはLAN上の秘匿認証ではなく、個別端末の承認／失効やTLSの代わりにならない。

受入実機項目: Android端末から2分間受付開始→検索／停止→再検索→古い広告結果が復活しないこと。Wi-Fi不安定時の登録遅延／時間経過／旧通知、Android13以上のmDNS APIで確認する。
