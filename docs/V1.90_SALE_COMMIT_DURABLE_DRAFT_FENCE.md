# v1.90 売上確定直前の支払下書き完全一致検査

## 変更理由
これまでの会計画面は支払追加時にSQLiteへ保存したものの、`RegisterDatabase.saveSale()` の新規売上登録ではその時点の画面上の `PaymentState` を信頼していた。状態の食い違い、DB保全操作、端末再起動時などに、永続化された割当と異なる支払を売上登録するリスクがあった。

## 修正点
- `PaymentCommitDraftFenceV190.requireMatches()` を追加。新規売上INSERT前、同一SQLiteトランザクション内で `payment_draft_meta` と `payment_draft_allocations` を照会。
- 伝票指紋、UUID会計キー、支払方法、充当額、受取額、配分順、sequence_no連番、伝票合計を完全照合。一件でも不一致、表欠落、破損、読込例外なら売上登録せず確認を促す。
- 外部決済の「確認待ち」が存在する場合は、従来の `ExternalTenderLedgerV188.requireAbsent()` で先に停止。
- 既に同じ会計キーで正式に売上確定されている再試行は、v1.89の実売上支払内訳照合を通過すれば従来どおり同じ売上IDを返す。消去済みの旧下書きは不要。
- 古いコードからの会計キーなし `saveSale` 呼び出しは、保存済み下書きが存在しない場合に限り互換維持。通常のPOS画面は必ずUUIDキーを利用。
- `V190SaleCommitDraftFenceTest.kt` を追加。純粋ロジックと、INSERT前に検査されるソースの退行検出を行う。
