# v1.86 未確定支払の上書き防止（PaymentDraftStore.save）

## 背景
v1.85 の `clear()` は未確定の支払記録の消去を拒否するが、`save()` は旧レコードを DELETE してから INSERT していた。別カート・別会計キーから直接 `save()` に入った場合、未確定の支払証跡を上書きし得た。

## 今回の修正
- 支払レコードが保存済みの場合、保存済みカート指紋と会計キーの両方が今回の入力と完全一致する場合だけ更新を許可。
- メタデータ欠落、不正な会計キー、別カート、別会計キーの場合は書き込みを拒否し、既存の支払割当を保全。
- 同一セッションの追加支払／明示的な支払訂正は引き続き保存可能。
- 保存済み支払割当が壊れていた場合も、上書きせずエラーにする。
- 会計キーが既に `sale_commit_keys` に記録済みなら、そのキーでの新しい支払データ作成・更新を拒否。
- チェックと DELETE/INSERT は同一 SQLite トランザクション内に置き、チェック後の競合によるすり抜けを防止。
- 保存失敗時、販売画面側は従来どおり支払内容を受理せず、履歴確認の案内を出す。

## テスト
`V186PaymentDraftSaveFenceTest.kt`：同一会計の追加入力、別カート・別キーの拒否、識別情報破損、検証がDELETEに先行することを確認。
既存の `V185CommittedDraftRecoveryTest` などの累積テストと3アプリAPKビルドはCIで再検証。
