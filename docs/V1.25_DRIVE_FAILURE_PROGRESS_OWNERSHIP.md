# v1.25 Drive failure progress ownership

## 問題

v1.23で、Drive API同期の途中ページまでDB commit済みの状態で後続ページが失敗した場合、`GoogleDriveDirectSyncStatusStore` は最後にcommit済みの件数を保持するようになった。

一方、アクセストークン取得など repository の `running()` より前で失敗した場合は今回runの件数が存在しないにもかかわらず、従来の `failed()` は前回runの件数をそのまま残していた。

このため、同じ `failed()` が次の2種類を区別できていなかった。

1. repository所有runが途中失敗したため、commit済み進捗を保持すべき失敗
2. repository開始前（認可取得等）で失敗したため、旧run件数を0へ戻すべき失敗

## 修正

`GoogleDriveDirectSyncStatusStore` に `owned_run_failure_pending_v125` を追加した。

- `failedForRun(runToken, ...)`
  - run-token所有者だけが実行可能
  - 件数を保持
  - owned-run failure markerを立てる
- 外側の `failed(...)`
  - running中なら従来通り無視
  - owned-run failure markerがある場合は件数を保持したままmarkerを消費
  - markerがない場合はrepository開始前失敗と扱い、listed/downloaded/unchanged/imported/duplicates/rejected/errorsを0へ初期化
- `running()` / `complete()` / stale-run recovery
  - markerを必ず除去

これにより、WorkManager・Google Drive設定画面・同期運用ダッシュボードの既存外側failure handlerを変更せず、認可前失敗とrepository途中失敗を区別できる。

## 保証する性質

- 1ページ以上commit後の失敗では最後のcommit済み件数を保持する。
- アクセストークン取得失敗などrepository未開始の失敗では前回成功runの件数を表示しない。
- stale workerがactive runを上書きしないv1.21のrun-token ownershipを維持する。
- v1.22のimport/fingerprint atomic commit、v1.23のpartial progress checkpoint、v1.24のimporter compatibility replayを維持する。
- DB schema変更なし。つぐレジ＋ DB version 6を維持する。

## テスト

`V125DriveFailureProgressOwnershipTest` で以下を固定する。

- owned run failureが `resetProgress = false` を使用すること
- 外側failureがmarker有無でresetを分岐すること
- reset対象の7カウンタが全て0へ戻ること
- 新run / 成功完了でmarkerを残さないこと
- WorkManager workerが引き続き認可失敗・repository失敗をstatus storeへ渡すこと

## 実機未確認

- 実Google認可を失効させた状態での自動同期表示
- 1ページcommit後に2ページ目通信失敗させた場合の件数保持
- WorkManager retryを跨いだmarker消費
- 強制終了直後のstatus復旧

これらは最終総合実機試験へ繰り越し、確認済みとは扱わない。
