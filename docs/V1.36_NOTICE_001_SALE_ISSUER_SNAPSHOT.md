# v1.36 NOTICE-001 売上時発行者snapshot

## 対象

- 初版完成マスター Issue #137: #18 `NOTICE-001 登録番号表示`
- 関連正式仕様: 適格請求書発行者情報・登録番号表示、TAX-012売上時税snapshot
- 対象アプリ: つぐレジ（設定元はつぐレジの税計算・インボイス設定）

## v1.35 / v1.36 TAX-012実装後に残っていた問題

店舗名・住所・電話番号・登録番号は `TaxInvoiceSettingsRegistry.current()` からレシート生成時に取得していた。このため、売上確定後に店舗情報または登録番号を変更すると、過去売上の再印字が現在設定へ置き換わる可能性があった。

適格請求書の履歴再現性を守るには、税額だけでなく発行者情報も売上確定時点で固定する必要がある。

## 実装

### 1. 売上確定時に発行者情報を固定

既存 `sale_tax_snapshot_v136` に次を追加した。

- `issuer_snapshot_present`
- `issuer_store_name`
- `issuer_address`
- `issuer_phone`
- `issuer_registration_number`

`SaleTaxSnapshotStoreV136.save()` は既に `RegisterDatabase.saveSale()` の売上確定SQLiteトランザクション内で呼ばれているため、税率別集計snapshotと発行者snapshotを同じ売上確定境界で保存する。

既存v1.36 DBには `SchemaMigration.ensureColumn` で列だけを非破壊追加する。導入前売上は `issuer_snapshot_present=0` のlegacyとして識別し、新規売上と混同しない。

### 2. 再印字は売上時snapshotを優先

`RegisterDatabase.loadSaleDetail()` は `SaleTaxSnapshotStoreV136.load()` を通る。load時にDBの発行者snapshotをプロセス内read-through cacheへ復元し、`ReceiptFactory.fromSale()` はsaleIdに対応するsnapshotを現在設定より優先する。

そのため、売上後に店舗名・住所・電話番号・登録番号を変更しても、snapshot導入後の過去レシートは売上時情報のまま再現される。

snapshot導入前のlegacy売上だけは当時情報を復元できないため、従来互換として現在設定へフォールバックする。legacyを「当時情報確認済み」とは扱わない。

### 3. 同期SALE journal

TAX-012で生成しているSALE journalの `invoiceIssuer` に、同じ売上snapshot由来の以下を含める。

- `storeName`
- `address`
- `phone`
- `registrationNumber`

現在設定から同期JSONを再構築しない。

## 自動テスト

`V136SaleTaxSnapshotTest` に以下を追加した。

1. 売上snapshotが店舗名・住所・電話番号・登録番号を保持すること
2. SALE journalが売上時登録番号を出力すること
3. 売上後に現在設定を別店舗・別登録番号へ変更しても、再印字用 `ReceiptFactory.fromSale()` は売上時snapshotを使うこと
4. レンダリング結果に現在設定の登録番号が混入しないこと
