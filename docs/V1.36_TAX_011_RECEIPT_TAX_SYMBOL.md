# v1.36 TAX-011 レシート税シンボル

## 対象

- 初版完成マスター Issue #137: #15 `TAX-003 軽減税率記号※（レシート）`
- 正式仕様 v2.5: `TAX-011`
- 表示契約: `内 / 外 / 内※ / 外※ / 非`

## v1.35までの残件

税区分snapshotには `tax_symbol / rate_percent / tax_included / taxable / reduced` が売上明細単位で保存され、再読込時もsnapshotが適用されていた。一方、`ReceiptRenderer` は `Product.taxSymbol` をそのまま印字していたため、任意税率マスタの自由入力記号に正式レシートの税記号が依存していた。

また、正式仕様では「8%だから軽減税率」と推測せず、売上時snapshotの軽減税率属性を判定根拠にする必要がある。

## 実装

### 1. 正式5種記号の一元化

`ReceiptTaxSymbolV136` を追加し、次のsnapshot属性だけで正式レシート記号を確定する。

| taxable | taxIncluded | reducedTax | receipt symbol |
|---|---|---|---|
| false | * | * | 非 |
| true | true | false | 内 |
| true | false | false | 外 |
| true | true | true | 内※ |
| true | false | true | 外※ |

税率値は判定条件に含めない。そのため8%であっても `reducedTax=false` なら `内` または `外` になる。

### 2. 通常印字・再印字を同じ契約へ統一

`ReceiptRenderer` は税マスタの表示用 `taxSymbol` を直接使用せず、`taxable / taxIncluded / reducedTax` から正式記号を生成する。

- 初回印字: 会計確定時の商品税snapshot属性から生成
- 再印字: `LineTaxSnapshotStore` が保存済みの売上明細snapshotを復元し、その属性から同じ規則で生成

既存 `line_tax_snapshots` は `tax_key / tax_label / tax_symbol / rate_percent / tax_included / taxable / reduced` を明細単位で保持しているため、DB schema追加は行わない。過去データ互換性を維持し、正式印字側では可変の `tax_symbol` を信頼しない。

## 自動テスト

`V136Tax011ReceiptSymbolTest` で以下を固定する。

1. `内 / 外 / 内※ / 外※ / 非` の5パターン
2. 8%かつ `reducedTax=false` が軽減扱いにならないこと
3. 非課税は他属性に関係なく `非` になること
4. 税マスタ記号が `CUSTOM` でも正式レシートはsnapshot属性由来になること
5. 税マスタ記号だけが後から変わっても正式レシート記号が変わらないこと
