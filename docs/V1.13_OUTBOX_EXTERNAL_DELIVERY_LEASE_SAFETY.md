# v1.13 Outbox外部配送 lease安全性

## 背景
`DriveOutboxScheduler` は定期Workと即時Workを別のunique work名で登録するため、両方が重なる可能性があります。v1.12までの前段stagingは `PROCESSING + worker_token + lease_until` で排他されていましたが、後段の外部配送は `STAGED` を単純にSELECTしていました。

このため同じSTAGED JSONを2つのWorkerが同時に扱うと、同じ確定JSONへの配送、`.partial` の削除・作成、Outbox状態更新が競合する余地がありました。

## v1.13
- 外部配送対象のSTAGED行をSQLite transaction内でclaimする。
- claimは `worker_token` と `lease_until` を設定し、active lease中の行を別Workerへ渡さない。
- lease期限切れはクラッシュ・中断後の再取得対象とする。
- `markSent` / 再生成 / 権限保留 / 配送失敗は、claimした `worker_token` が一致する行だけ更新する。
- 状態遷移時に `processing_started_at` / `lease_until` / `worker_token` を必ず解除する。
- STAGED再キュー処理はactive delivery leaseを奪わない。
- 外部確定JSONのv1.06〜v1.12非破壊・SHA-256・TOCTOU対策はそのまま維持する。

## lease
外部配送leaseは30分です。通常のWorker処理時間を十分上回らせ、同一端末上の重複Workerが同時に同じSTAGED行を操作することを防ぎます。クラッシュ等で解除されなくても、期限後は次回Workerが再claimできます。

## 失敗時の正本
SQLite売上・Sales Journalを正本として保持します。lease所有権を失ったWorkerはOutbox状態を書き換えず、既存の確定JSONを削除・上書きしません。
