# v0.95 販売編集フロー レスポンシブ対応

## 目的

販売画面から直接使用する `SCR-120 行編集` と `SCR-121 値引・割引` について、800×480クラスの横画面やAndroidフォント倍率を上げた環境でも、主要な入力・確認・保存操作が画面外へ固定されない構成にする。

v0.95では販売・税・値引計算そのものは変更せず、既存の共通レスポンシブ基盤へ画面レイアウトを接続する。

## SCR-120 行編集

- `rememberRegisterResponsiveMetrics()` を使用する。
- 本文余白は `responsive.screenPaddingDp`、左右間隔は `responsive.panelGapDp` を使用する。
- 編集ペインと変更後サマリペインは、それぞれ独立した縦スクロール領域を持つ。
- Compact時は左右ペインを固定幅だけで構成せず、編集側 `1.28`、サマリ側 `0.72` の比率で利用可能幅を分配する。
- 通常画面では変更後サマリの既存 `330dp` 幅を維持する。
- Compact時は商品名・税区分等の文字、余白、行メモ高さを縮小する。
- 行メモはCompact `88dp`、通常 `110dp` とする。
- `値引・割引画面` 導線はサマリ下部に残し、スクロール量に依存せず操作可能な構造とする。
- 保存時の数量・単価・行値引・税区分・行メモの更新ロジックは変更しない。

## SCR-121 値引・割引

- `rememberRegisterResponsiveMetrics()` を使用する。
- 入力ペインと税率別プレビューペインは、それぞれ独立した縦スクロール領域を持つ。
- Compact時は入力側 `1.08`、プレビュー側 `0.92` の比率で利用可能幅を分配する。
- 通常画面では税率別プレビューの既存 `390dp` 幅を維持する。
- Compact時は見出し、余白、説明文の文字サイズを縮小する。
- 商品値引・伝票値引、定額・率割引の選択ロジックは変更しない。
- `DiscountEngine.applyToItem` / `DiscountEngine.applyToTransaction`、税率別再計算、端数処理の既存動作は変更しない。

## 非変更範囲

- 税マスター、税シンボル、混在税設定
- 会計計算・支払処理
- 売上保存、Sales Journal、Google Drive同期
- レシート・領収書・印刷キュー
- つぐレジ＋、つぐレジ CD
- データ保護、バックアップ、復元、ロールバック

## 回帰確認

自動検査では以下を確認する。

- v0.95専用JUnitがSCR-120/SCR-121のレスポンシブ構造を検査する。
- v0.14以降の累積unit testを3アプリすべてで実行する。
- 3アプリKotlin compile、debug APK buildを実行する。
- v0.92で導入したAPK実体整合性ゲートを継続する。
- Artifact取得後、ZIPおよび3 APKのSHA-256をCI外で再計算する。

## 実機確認

本版単独では実機確認済みとは扱わない。

最終総合実機試験で、800×480〜1920×1080およびAndroidフォント倍率変更時に、SCR-120/SCR-121の入力欄・税区分・プレビュー・値引導線・戻る・保存／適用が操作可能であることを確認する。
