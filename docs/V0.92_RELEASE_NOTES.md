# v0.92 Release Notes

## 概要

v0.92では、最終総合実機試験へ渡す3アプリのdebug APKに対して、生成後のAPKそのものを検証する「APKリリース整合性ゲート」を追加する。

v0.91までのソース・unit test・Kotlin compile・APK build・SHA-256に加えて、package名、version、SDK、Launcher、ZIP整合性、署名証明書をCIで確認する。

## バージョン

- つぐレジ: `0.92.0-dev.1` / versionCode `122`
- つぐレジ＋: `0.14.0-dev.1` / versionCode `14`（変更なし）
- つぐレジ CD: `0.14.0-dev.1` / versionCode `7`（変更なし）

## 追加内容

- `ci/verify-apk-release-integrity.sh` を追加
- 3 APKのZIP整合性を `unzip -tq` で検査
- `apkanalyzer manifest` で以下を実APKから検査
  - debug applicationId
  - versionCode
  - versionName
  - minSdk 26
  - targetSdk 36
- `aapt2 dump badging` でLauncherが1件であることを検査
- `apksigner verify --verbose --print-certs` で以下を検査
  - APK署名検証成功
  - APK Signature Scheme v2 有効
  - Signer #1 証明書SHA-256が開発署名鍵と一致
- 実APKのSHA-256と検査結果を `apk-integrity-summary.txt` に保存
- 整合性ゲートをArtifact uploadより前に実行し、不一致APKを配布しない

`aapt2 dump badging` はLauncher確認に限定し、applicationId・版番号・minSdk・targetSdkはAndroid SDKの `apkanalyzer manifest` 専用コマンドから取得する。これにより、badging表示形式の差に依存せずAPKマニフェスト値を確認する。

## データ安全性

v0.92で追加する処理はCI内のAPK読み取りだけで、アプリ内の営業データやSQLiteを変更しない。

税計算、販売、会計、保留伝票、印刷キュー、Drive同期、顧客表示、バックアップ／復元ロジックは変更しない。

## 検証

CIで以下を累積実行する。

- v0.14～v0.92 ソース受入検査
- Launcher / 画面向き検査
- 3アプリ累積unit test
- 3アプリ Kotlin compile
- 3アプリ debug APK build
- 3 APKリリース整合性ゲート
- APK SHA-256生成
- Artifact upload

## 実機確認

各開発版で個別の実機確認は行わず、ユーザー方針どおり**最終総合実機試験へ繰越**する。

v0.92で追加したAPK整合性検査は、最終実機試験へ渡すAPK自体が正しいことを保証するための事前ゲートであり、実機動作確認済みを意味しない。
