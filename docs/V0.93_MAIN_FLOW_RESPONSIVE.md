# v0.93 ログイン・会計完了レスポンシブ対応

## 目的

v0.93では、初回リリース前の主要画面確認で残っていた `SCR-010 担当者選択／ログイン` と `SCR-320 会計完了` の固定レイアウトを、既存の共通レスポンシブ基盤へ接続する。

対象は表示・操作到達性のみとし、認証、売上確定、税計算、支払、印刷、領収書、売上一覧への業務フローは変更しない。

## 共通方針

- `rememberRegisterResponsiveMetrics()` を使用する。
- `RegisterResponsiveLayoutPolicy` の Compact / Medium / Expanded 判定を既存どおり使用する。
- 800×480dpはCompactとして扱う。
- 1280×720dpでもAndroidフォント倍率1.30以上ではCompactへフォールバックする既存方針を維持する。
- 高さ不足時は主要操作を画面外へ固定せず、対象領域をスクロール可能にする。
- 通常サイズで既に成立している操作配置は不要に変更しない。

## SCR-010 担当者選択／ログイン

### 通常表示

従来の3列担当者配置、82dp担当者ボタン、390dp PINパネルを維持する。

### Compact表示

- 担当者一覧側を縦スクロール可能にする。
- PINパネル側も独立して縦スクロール可能にする。
- 外周余白と左右パネル間隔は共通レスポンシブ値を使用する。
- 担当者ボタン高を58dpへ縮小する。
- 担当者ボタン間隔を6dpへ縮小する。
- PINパネル幅を260dpへ縮小する。
- PIN表示欄は既存Compact値 `46dp` を使用する。
- PINテンキーは既存Compact値 `42dp`、行間 `5dp` を使用する。
- 担当者名は2行まで表示可能とし、Compact時は文字サイズを抑える。
- 認証処理 `onLogin(operatorId, pin)`、PIN最大8桁、担当者選択時PINクリアは変更しない。

## SCR-320 会計完了

### 通常表示

従来の横一列操作を維持する。

- レシート確認
- 領収書発行
- 統合印刷キュー
- 売上一覧
- 次の取引

### Compact表示

会計情報と操作領域全体を縦スクロール可能にし、主要操作が画面外へ消えたまま操作不能にならない構成とする。

4操作を2×2で配置する。

1段目:
- レシート
- 領収書

2段目:
- 印刷キュー
- 売上一覧

各操作ボタンは48dp以上のタップ高を確保する。

その下に `次の取引` を全幅54dpの独立した主要ボタンとして配置する。

会計完了後の遷移先は変更しない。

- レシート → `SaleReceiptNavigation`
- 領収書 → `ReceiptVoucherNavigation`
- 印刷キュー → `UnifiedPrintQueueActivity`
- 売上一覧 → `AppScreen.SALES_HISTORY`
- 次の取引 → `AppScreen.SALES`

## 自動検証

v0.93では以下を累積CIで検査する。

- 800×480dpがCompactになること。
- フォント倍率1.30時にCompactフォールバックすること。
- ログインの担当者一覧とPINパネルが独立スクロールを持つこと。
- PINテンキーが既存Compact寸法を利用すること。
- 会計完了Compact表示に2×2操作と独立した `次の取引` が存在すること。
- 通常表示の従来5操作が残っていること。
- 会計後の各コールバックが変更されていないこと。
- v0.92の実APK整合性ゲートを3アプリすべてで継続実行すること。
- 3アプリの累積unit test、Kotlin compile、debug APK buildを実行すること。
- Artifactは `TSUGUREGI-v0.93.0-dev1-main-flow-responsive-apks` として公開し、3 APKとSHA-256を同梱すること。

- 800×480での会計完了4操作と `次の取引` の到達性
- Androidフォント倍率変更時の会計完了操作
- レシート、領収書、印刷キュー、売上一覧、次取引への実画面遷移
