# v1.81 支払ドラフト識別・復元時の整合性保護

## 修正
- `PaymentDraftFingerprint.of` に **小数の実数量（quantityHundredths）** と **永続商品行ID（lineId）** を追加。金額が同じでも別商品行へ差し替えた場合や、同じ整数数量扱いとなる小数変更を異なる取引として判定する。
- v1.80以前の指紋は **識別専用** `legacyV180Of` として保持。古い支払割当が残っているときは、旧指紋を使って自動復元しない。
- SQLiteから支払割当を復元する際、伝票合計を超える割当、金額のオーバーフロー、壊れた行、会計キー不正を検出したら安全側へ停止。**保存済みの割当・会計キーを削除しない**。
- 停止時は販売画面でダイアログ「支払データを確認してください」を表示。支払データを勝手に作り直さず、「再決済せず売上履歴を確認し、責任者に連絡してください」と案内。
- 正常な支払配分は継続。現金の預り超過によるお釣り、複数決済手段の配分は既存の `PaymentEngine` の規則を維持。
- 空の古い支払入力については、過去の支払が無ければ新しい識別子で作り直す。

## アップグレード時の注意
v1.80からv1.81への更新時に、小数数量や商品行IDを含まない **古い保存済み支払入力** があり、かつ支払配分が残っている場合は、自動でその支払を採用しない。売上履歴と決済端末側の処理を先に照合すること。金額を再度請求する運用は避ける。

## 検証
- 小数数量1.25と1.50、同一商品/金額の別行への差し替え、正常なカード＋現金、お釣り、伝票超過、加算オーバーフローを単体テスト。
- 古い画面遷移・会計冪等キー・売上履歴と元取引無しレジマイナス処理は維持。
- 実機の支払中断・APK上書き・外部決済端末との突合は別途受入試験で確認する。
