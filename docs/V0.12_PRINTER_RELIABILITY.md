# v0.12 プリンター信頼性強化

## 目的

既存のTCP 9100／ESC-POS印刷基盤を実店舗向けに強化し、通信切断時の二重印刷を防止する。

## v0.11.1時点で実装済みの範囲

- プリンター名、IPアドレスまたはホスト名、TCPポート、タイムアウトの設定
- 58mm／80mm用紙幅の選択
- プリンターテスト印刷
- 売上レシート、返品・取消レシート、X点検票、Z精算票のESC-POS化
- SQLite印刷キュー
- WorkManagerによる自動印刷
- 失敗ジョブの再試行

## v0.12.0-dev.1で追加した安全対策

TCP 9100は、アプリ側で送信処理が完了しても実際の紙出力完了を保証できない。特に、データ書込み開始後に接続が切れた場合は、プリンターが一部または全部を受信済みの可能性がある。

送信処理を次の段階に分類する。

1. `CONNECTING`：接続開始前または接続処理中
2. `CONNECTED`：接続済み、データ書込み前
3. `WRITE_STARTED`：データ書込み開始後
4. `FLUSHED`：出力ストリームのflush完了後

判定方針：

- `CONNECTING`／`CONNECTED`で失敗：プリンターへデータ未送信と判断し、自動再試行を許可する。
- `WRITE_STARTED`／`FLUSHED`で失敗：送信結果不明と判断し、売上レシートジョブを`FAILED`へ移して自動再試行を止める。
- 結果不明ジョブは、紙が出ていないことを担当者が確認してから印刷キュー画面で手動再試行する。

## v0.12.0-dev.2で追加した開発版配布対策

GitHub Actionsの標準Debug署名は実行ごとに変わるため、以前のAPKへ上書きインストールできず、テストデータを継続できない問題があった。

開発版を次の構成へ変更した。

- 開発版専用パッケージ：`jp.co.tenposinfo.register.dev`
- アプリ表示名：`つぐレジ 開発版`
- 開発版専用の固定署名鍵を使用
- 署名証明書SHA-256：`752c4f56263c8887ada96184d25fad200aff0e84a80c67eda60c7607da3ac9e4`
- 本番用パッケージ`jp.co.tenposinfo.register`および将来の本番署名鍵とは分離

v0.11.1以前のテスト版とは別アプリとしてインストールされる。v0.12.0-dev.2以降は同じ開発版パッケージと署名を継続し、更新インストールできるようにする。

## v0.12.0-dev.3で追加した業務帳票の安全対策

返品・取消レシート、X点検票、Z精算票の`document_print_jobs`にも、売上レシートと同じ送信結果不明時の停止処理を適用した。

- 既存の帳票印刷処理が`RETRY`とエラー内容を保存した直後、SQLiteトリガーで判定する。
- エラーが「送信結果が不明です。」で始まる場合は、ジョブを即時に`FAILED`へ変更する。
- WorkManagerの次回実行対象は`PENDING`／`RETRY`のみのため、結果不明ジョブは自動再送されない。
- 接続前の失敗は`RETRY`を維持し、最大5回まで自動再試行する。
- 既存端末のSQLiteにもアプリ起動時に安全トリガーを後付けする。

## 自動テスト

- 接続前の失敗が自動再試行可能と判定されること
- 書込み開始後の失敗が手動確認必須と判定されること
- 例外が別例外に包まれていても送信結果不明を検出できること
- 通常の接続拒否等は再試行可能として扱うこと
- 売上レシート以外の業務帳票でも結果不明時に`FAILED`となること
- 業務帳票の接続前失敗は`RETRY`となり、5回目で`FAILED`となること
- 58mm／80mmの用紙幅選択を維持すること

## 実機試験で確認する項目

1. 正常接続時にレシートが1枚だけ出力される。
2. 存在しないIPアドレスではRETRYとなり、復旧後に1枚出力される。
3. 売上レシート送信中にLANを切断した場合、自動で再印刷されない。
4. 返品・取消レシート送信中にLANを切断した場合、自動で再印刷されない。
5. X点検票／Z精算票送信中にLANを切断した場合、自動で再印刷されない。
6. 結果不明表示後、紙出力の有無を確認して手動再試行できる。
7. 58mmと80mmで文字切れ、税記号、合計、カット位置を確認する。
8. EPSON機および今後の対応機種で日本語コードページを確認する。
9. 次回開発版APKを上書きインストールして、設定・売上・印刷キューが保持される。
