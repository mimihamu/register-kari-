# v0.12 プリンター信頼性強化

## 目的

既存のTCP 9100／ESC-POS印刷基盤を実店舗向けに強化し、通信切断時の二重印刷を防止する。

## v0.11.1時点で実装済みの範囲

- プリンター名、IPアドレスまたはホスト名、TCPポート、タイムアウトの設定
- 58mm／80mm用紙幅の選択
- プリンターテスト印刷
- 売上レシート、返品・取消レシート、X点検票、Z精算票のESC-POS化
- SQLite印刷キュー
- WorkManagerによる自動印刷
- 失敗ジョブの再試行

## v0.12.0-dev.1で追加した安全対策

TCP 9100は、アプリ側で送信処理が完了しても実際の紙出力完了を保証できない。特に、データ書込み開始後に接続が切れた場合は、プリンターが一部または全部を受信済みの可能性がある。

送信処理を次の段階に分類する。

1. `CONNECTING`：接続開始前または接続処理中
2. `CONNECTED`：接続済み、データ書込み前
3. `WRITE_STARTED`：データ書込み開始後
4. `FLUSHED`：出力ストリームのflush完了後

判定方針：

- `CONNECTING`／`CONNECTED`で失敗：プリンターへデータ未送信と判断し、自動再試行を許可する。
- `WRITE_STARTED`／`FLUSHED`で失敗：送信結果不明と判断し、売上レシートジョブを`FAILED`へ移して自動再試行を止める。
- 結果不明ジョブは、紙が出ていないことを担当者が確認してから印刷キュー画面で手動再試行する。

## 自動テスト

- 接続前の失敗が自動再試行可能と判定されること
- 書込み開始後の失敗が手動確認必須と判定されること
- 例外が別例外に包まれていても送信結果不明を検出できること
- 通常の接続拒否等は再試行可能として扱うこと
- 58mm／80mmの用紙幅選択を維持すること

## 実機試験で確認する項目

1. 正常接続時にレシートが1枚だけ出力される。
2. 存在しないIPアドレスではRETRYとなり、復旧後に1枚出力される。
3. 印刷データ送信中にLANを切断した場合、自動で再印刷されない。
4. 結果不明表示後、紙出力の有無を確認して手動再試行できる。
5. 58mmと80mmで文字切れ、税記号、合計、カット位置を確認する。
6. EPSON機および今後の対応機種で日本語コードページを確認する。
