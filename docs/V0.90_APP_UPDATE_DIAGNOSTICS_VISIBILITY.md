# v0.90 アプリ更新状態の現場可視化

## 目的

v0.88で上書き更新後の起動完了台帳、v0.89で更新成功確定前のDB健全性ゲートを追加した。

ただし、これらの状態はSharedPreferencesや監査ログを直接確認しないと現場から把握できず、実機試験や店舗サポート時に「この版は正常起動確定済みか」「前回起動が途中で止まったか」「DB健全性NGで成功確定が止まっているか」を即座に判断しにくかった。

v0.90では、責任者用のSCR-767「データ保全・バックアップ・復元」に更新状態を読み取り専用で表示する。

## 表示内容

- 現在インストール版
- 最終起動成功確定版
- 最終成功確定日時
- 現在版の起動成功確認中状態
- 未完了のsource→target版遷移
- 起動試行回数
- 未完了開始時刻
- 前版の未完了証跡
- v0.89 DB健全性NG証跡
- DB健全性NGを検出した対象版と時刻
- サニタイズ済みDB health summary

## 状態表示

優先順位は以下とする。

1. `DB健全性NG・更新成功未確定`
2. `起動成功確認中`
3. `起動成功確定済み`
4. `更新台帳未確立`

DB健全性NG証跡が現在版を対象としており、同じ現在版のpending起動が残っている場合は最優先でNG表示する。

## 読み取り専用

`AppUpdateDiagnosticsV090` は以下だけを読む。

- `BuildConfig.VERSION_NAME / VERSION_CODE`
- v0.88から継続している `app_update_transition_v088` SharedPreferences
- v0.89の `app_update_database_health_v089` SharedPreferences

以下は行わない。

- SharedPreferencesのedit/clear
- 更新成功状態の強制確定
- 未完了証跡の削除
- DB健全性失敗証跡の削除
- writableDatabase取得
- SQL実行
- sales等の業務データ更新・削除
- ロールバックDB操作

## UI

SCR-767の左側「整合性診断」領域へコンパクトな `AppUpdateDiagnosticsPanelV090` を追加する。

正常時は現在版、最終成功版、状態を中心に数行だけ表示する。異常時のみ未完了遷移、起動試行回数、DB健全性NG証跡を追加表示する。

新しい操作ボタンは追加しない。画面表示時とON_RESUME時にSharedPreferencesを再読込する。

## データ保護

v0.90は診断可視化のみであり、販売、会計、税、支払、印刷、Drive同期、顧客表示、バックアップ、復元の処理内容を変更しない。

以下を自動削除・変更しない。

- sales / sale_items / sale_payments
- products / cart_items
- held_tickets / held_ticket_items
- Sales Journal
- Drive JSON
- sync fingerprint
- SENT Outbox
- 隔離・同期履歴
- operation_audit
- 復元前ロールバックDB

## 実機確認事項

- 800×480相当の横画面でSCR-767が操作可能であること
- フォント倍率変更時に更新診断欄が他の操作を押し出さないこと
- v0.89→v0.90上書き後に最終成功版が正しく見えること
- 起動途中強制終了後に起動試行回数が見えること
- DB健全性NG時に赤表示されること
- 正常化・再起動後に成功確定済みへ戻ること
- 画面復帰時に状態が自動更新されること

実機で確認するまでは、表示レイアウトや端末固有のライフサイクル挙動を確認済みとは扱わない。
