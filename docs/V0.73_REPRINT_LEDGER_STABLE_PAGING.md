# v0.73 再印字台帳 安定スナップショット・カーソルページング

## 目的

v0.70〜v0.72のSCR-648はSQLite直接検索＋OFFSETページングです。運用中は5秒ごとに印刷状態を更新するため、その間に新しい再印字要求が先頭へ追加されるとOFFSET位置がずれ、2ページ目以降で同じ行が再表示されたり別の行を飛ばす可能性があります。

v0.73では、検索条件を適用した時点の最新監査行をスナップショットとして固定し、`(requested_at, id)` を使うkeysetカーソルへSCR-648を移行します。

## スナップショット

検索・状態フィルタ・固定期間・任意期間を適用した時に、その条件で最も新しい監査行を取得します。

- snapshot key: `(requested_at, id)`
- snapshot内に含める条件:
  - `requested_at < snapshot.requested_at`
  - または同時刻で `id <= snapshot.id`

同じミリ秒に新しい要求が追加されても、新しいIDはsnapshotより大きいため現在検索へ割り込みません。

## Nextカーソル

表示ページの最後の行を次ページカーソルにします。

- `requested_at < cursor.requested_at`
- または同時刻で `id < cursor.id`

IDは厳密な `<` とするため、直前ページの最後の行を次ページで重複表示しません。

## Previous

SCR-648は画面内に過去のページカーソルをスタックとして保持します。「前へ」は1つ前のカーソルを復元します。検索条件を変更するとsnapshot、現在カーソル、履歴スタックをすべてリセットします。

## 5秒更新

自動更新ではsnapshotとページカーソルを変更しません。ページ構成は新規要求の追加によってずらさず、`print_jobs`の状態・試行回数・最終エラーは現在値をJOINして更新表示します。

snapshotより新しい監査行が存在する場合は「新しい再印字要求 N件（検索再実行で反映）」を表示します。

## 互換性

v0.70のOFFSET検索APIは累積互換・テストのため残しますが、SCR-648からは使用しません。新しい安定ページング用ストアはOFFSETを使用しません。

## データ保護

本変更は読み取り経路だけです。監査履歴、売上、税、支払、印刷jobへのUPDATE/DELETEは追加しません。FAILED/RETRYの復旧は統合印刷キューへ集約したままです。

## 実機未確認

- 200件超ページング中の新規要求追加
- 同一ミリ秒に複数要求が作成された場合の実表示順
- 数千〜数万件の深いページ移動性能
- 状態変更によるフィルタ対象行の増減
- アプリ回転・プロセス再作成時のカーソル状態復元
