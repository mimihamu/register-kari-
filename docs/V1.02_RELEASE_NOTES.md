## 変更概要

つぐレジ CD への WebSocket snapshot 送信を POS の会計監視スレッドから分離した。

v1.01 までは `CustomerDisplayWebSocketServer.broadcast()` が各接続の socket write 完了を同期的に待っていたため、1 台の顧客表示端末が受信停止・LAN 半断線等で write を停滞させた場合、正常な別端末への表示更新まで巻き込む余地があった。

v1.02 では接続ごとに `CustomerDisplayLatestSendDispatcher` を持ち、text frame 送信を非同期化した。writer が処理中の場合は pending snapshot を最新 1 件へ置換し、古い SALES snapshot の無制限 backlog を作らない。

## 安全性

- 1 台の遅い/停止した CD が POS poller を待たせない
- 別の正常 CD は独立して送信を継続できる
- pending snapshot は 1 件のみで最新値優先
- socket write 失敗後は該当 dispatcher を閉じ、以後の投入を拒否
- token 認証、sequence/serverInstanceId、再接続、Ping/Pongは維持
- 売上SQLite / Sales Journal / Drive JSON / Outbox / imported sales等のデータ破壊処理は追加していない
