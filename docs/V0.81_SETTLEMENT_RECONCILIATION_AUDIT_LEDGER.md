# v0.81 点検・精算 整合確認監査台帳

## 目的

v0.78で追加した保存値と現在DBの整合確認、およびv0.79で追加した追記専用監査記録を、店舗運用で後から確認できる読み取り専用台帳へ接続する。

v0.80でレスポンシブ版SCR-520から整合確認を実行できるようになったため、v0.81では「誰が、いつ、どの点検・精算レポートを照合し、OK / INFO / ALERTのどの結果だったか」を検索可能にする。

## 画面

新規画面: `SCR-521 整合確認監査台帳`

SCR-520の整合確認エリアから「整合確認監査台帳を開く」で遷移する。

### 表示内容

- 全件 / OK / INFO / ALERT 件数
- OK / INFO / ALERT フィルター
- レポートNo.、担当者、営業日、営業セッションを対象とした検索
- 新しい監査から順に最大500件表示
- 監査No.
- 点検・精算レポートNo.
- 実行担当者
- 実行日時
- イベント種別
- v0.79で保存した比較証跡

## 権限

閲覧には以下の両方が必要。

1. `VIEW_SALES`
2. `X_INSPECTION` または `Z_SETTLEMENT`

画面表示中もログインセッションを再取得し、権限・セッション失効時は閲覧を継続しない。

## データ保全

監査台帳は既存 `operation_audit` のうち `SETTLEMENT_RECONCILIATION_%` のイベントだけを読み取る。

- `operation_audit` へのINSERTなし
- `operation_audit` のUPDATEなし
- `operation_audit` のDELETEなし
- 売上、税、支払、返品、点検・精算snapshotの変更なし
- 既存監査の修正・削除なし
- OAuth token、Authorization header、content URI、raw sales JSONを表示しない

v0.79の監査追記は従来どおりfail-closedであり、監査INSERTに失敗した整合確認を成功扱いにしない。

## 検索

検索文字は最大80文字とし、SQLiteのselectionArgsでバインドする。

検索対象:

- `reference_id`
- `operator_name`
- `detail`

一覧は `created_at DESC, id DESC` で安定して新しい順に表示する。

## 実機確認

CIでは以下を実機確認済みとは扱わない。

- SCR-520からSCR-521へ実際に遷移できること
- OK / INFO / ALERT件数が実データと一致すること
- 各フィルター・検索の操作性
- 多数監査データがある場合のスクロール・表示性能
- 800x480～1920x1080相当の表示
- Android表示サイズ・フォント倍率変更時の文字欠け・重なり
- 画面表示中に担当者停止・権限変更・ログアウトした場合の遮断
