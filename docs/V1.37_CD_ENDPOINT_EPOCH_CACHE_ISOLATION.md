# CD別レジ切替時の旧コールバック・永続キャッシュ混入防止

原因: MainActivityが前WebSocketからのonSnapshotを受けると、UI主スレッドで表示する前に設定に関係なくSnapshotStoreに書き込んでいた。接続先変更後に旧端末の遅延イベントが新端末の画面や再起動用キャッシュへ混入しうる。またキャッシュが接続先無指定で、別レジ接続後も以前の表示状態を復元していた。

修正:
- CustomerDisplayConnectionEpochGuard（AtomicLong）で接続世代を管理する。
- 各ネットワークコールバックは主スレッドで世代照合し、失効後のイベントをUIにもキャッシュにも反映しない。
- 設定変更が確定した瞬間に旧世代を失効させ、Composeのeffect廃棄を待たない。同一設定を再保存しただけの場合は現行接続を維持する。
- onSnapshotは受信側スレッドで無条件にキャッシュへ保存せず、CustomerDisplayStateReducerが採用した新しいsnapshotのみ永続化。古いシーケンスや別通信の値は保存しない。
- 保存キャッシュはhost/port/tokenから算出したSHA256指紋で分割し、違う接続先・トークンでは読み込まない。トークン生値はキャッシュ領域には保存しない。
- 旧形式キャッシュには指紋がないので移行後の初回再接続では復元せず、新しい通信で再作成する。売上・会計DBへの影響なし。

JUnit: 世代切替、遅延dispose、指紋一致/不一致、接続先変更、キャッシュ保存ガード、main source gates。実機でレジA/B切替・断続通信・再起動を確認すること。
