# v1.36 / Issue #137 #24 RCPT-001 — レシート番号表示

## 正式仕様との突合

詳細仕様書 v2.5 §16.4「販売レシートの印字順序」では、取引情報として営業日、日時、レシート番号、端末番号、担当者を扱い、日時・番号を必須とする。販売レシート標準例では `No.000123` の形式で表示する。

Issue #137 #24 `RCPT-001 レシート番号表示` について、本対応では販売レシート番号の表示・追跡性を対象とする。端末番号等の別取引情報は当該行へ混在させず、各対応項目で扱う。

## 実装方針

- レシート番号の正本は新しい別カウンタを作らず、確定売上の永続 `saleId` とする。
- `ReceiptFactory.fromSale()` は `SaleSummaryRecord.id` を `ReceiptData.saleId` へ復元するため、初回印刷・再印刷で同じ番号を使用する。
- `ReceiptNumberV136.format()` で6桁未満を0埋めし、仕様書標準例に合わせる。
- 6桁を超えたIDは末尾切捨てや循環を行わず、そのまま表示して一意性と追跡性を維持する。
- 58mm / 80mmとも同一番号を表示する。

## 自動テスト

`V136ReceiptNumberDisplayTest.kt` で以下を確認する。

1. 1 → `000001`、123 → `000123`、123456 → `123456`。
2. 7桁以上は切り捨てず保持する。
3. 通常印刷と再印刷で同一 `No.000123` を表示する。
4. 58mm / 80mmで同一番号を表示する。
5. `ReceiptFactory` が売上ID、`ReceiptRenderer` がその `saleId` を番号表示の単一ソースとして使用する。

## 実機確認

最終統合受入で58mm / 80mm実紙に以下を確認する。

- `No.000123` 等の番号が欠けず判読できる。
- 後レシート・再印刷でも元売上と同一番号になる。
- 長期運用で6桁を超えた場合にも番号欠落がない。

実機未確認の段階ではIssue #137の完了条件を満たしたとは扱わない。
