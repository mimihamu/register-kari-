# つぐレジ v0.11.1 統合安定化版

## 位置付け

- 対象ブランチ: `develop/v0.11.1`
- ベース: `develop/v0.11`
- 目的: v0.1～v0.11の既存機能を維持し、実店舗試験前の重大な整合性・復旧性・保守性問題を修正する
- PRはDraftのまま保持し、明示的な承認があるまでマージしない
- アプリ表示名は「つぐレジ」、applicationIdは`jp.co.tenposinfo.register`を維持する

## v0.11.1で修正した内容

### 1. 深夜営業の営業日集計

- `sales`、`cash_movements`、`reversal_transactions`へ`business_session_id`と`business_date`を保持する。
- `settlement_reports`へ`business_session_id`を保持する。
- X点検・Z精算は暦日0時～24時ではなく、営業セッションIDで売上・返品・入出金を集計する。
- 既存データは`business_sessions.opened_at～closed_at`の範囲から可能な範囲で営業セッションを補完する。

### 2. 任意税率商品の返品

- 元売上の`line_tax_snapshots`から販売時の税区分キー、名称、税率、内外税、課税、軽減、税記号を復元する。
- 返品明細にも完全な税スナップショットを保存する。
- 返品額・返品税額は現在の税率マスターではなく販売時スナップショットから再計算する。
- 返品JSONも商品別完全税情報と税率単位集計を出力する。

### 3. メニュー改定の税スナップショット

- 改定予約時に税区分キー、名称、税率、内外税、課税、軽減、税記号を固定保存する。
- 改定適用時は最新税率マスターを再参照せず、予約時スナップショットを使用する。
- v0.11で作成済みの改定は、対応する動的税区分が残っている場合、その内容からスナップショットを補完する。

### 4. セッション失効と権限キャッシュ

- 販売画面表示中も5秒間隔でセッションを検証する。
- 30分無操作、担当者停止、販売権限剥奪時はログイン画面へ戻す。
- 担当者の`updated_at`だけでなく、DBから再取得した名称・ロール・権限集合そのものを比較し、権限変更を反映する。
- タッチ操作時に最終操作時刻を更新する。

### 5. OutboxのPROCESSING復旧

- `processing_started_at`、`lease_until`、`worker_token`を追加する。
- Worker開始時に期限切れPROCESSINGをRETRYへ戻す。
- 対象取得とPROCESSING化を1つのDBトランザクションで実行する。
- Workerごとのtokenを使用し、他Workerが取得したレコードを完了・失敗更新しない。

### 6. 同期フォルダー設定

- 新規Outboxの`object_key`は現在の同期フォルダー設定から生成する。
- SQLiteトリガーが生成する返品、精算、入出金、営業開始・状態、メニュー改定も同じ設定を参照する。
- フォルダー変更時の既存Outbox方針:
  - `PENDING`、`RETRY`、`FAILED`: 新しいフォルダー名へ付け替える。
  - `PROCESSING`: 処理中のため変更しない。期限切れ復旧後に再評価する。
  - `STAGED`、`SENT`: 生成済み・送信済み成果物として元のキーを維持する。

### 7. 同期JSONの税情報

売上・返品の商品明細へ以下を出力する。

- `taxKey`
- `taxLabel`
- `taxRatePercent`
- `taxIncluded`
- `taxable`
- `reduced`
- `taxSymbol`

さらに`taxTotals`として税率単位の税抜額、税額、税込額、対象税キーを出力する。

### 8. Python生成ソースの廃止

- 生成後のKotlinを正式な`app/src/main/java`へ統合した。
- `generate_v010.py`、`tools/v08`、生成sourceSets、preBuildのPython依存を削除した。
- Windowsを含め、通常のGradleタスクだけで単体テスト・APKビルドできる構成へ変更した。

## Android実機総合試験手順

### A. インストール・起動

1. v0.11 APKを導入済み端末では、v0.11.1を上書きインストールする。
2. 新規端末ではv0.11.1を新規インストールする。
3. 横画面固定、起動診断、DB移行、担当者ログイン、既存マスター・売上・保留伝票の保持を確認する。
4. アプリ一覧とタイトル表示が「つぐレジ」であることを確認する。

### B. 深夜営業

1. 営業日を7月30日、営業開始を17:00として開始釣銭を登録する。
2. 23:50に現金売上、カード売上、入金、出金を各1件登録する。
3. 端末時刻を翌日00:10以降に進め、売上、部分返品、入金、出金を各1件登録する。
4. X点検で00:00前後の全件が7月30日の同一営業日へ含まれることを確認する。
5. Z精算し、売上、返品、支払別、入出金、期待現金、実査差異が一致することを確認する。
6. 7月31日の新営業開始後、前営業日の取引が新営業日集計へ混入しないことを確認する。

### C. 任意税率返品

1. 12%内税と12%外税の税区分を作り、それぞれ数量3で販売する。
2. レシート、売上詳細、同期JSONの税情報と税率集計を記録する。
3. 税率マスターを15%へ変更、または無効化する。
4. 元売上から数量1または2を部分返品する。
5. 返品額・税額・税記号が販売時の12%条件のままであることを確認する。
6. 返品レシートと返品JSONの商品税情報・`taxTotals`が一致することを確認する。

### D. メニュー改定

1. 12%税区分を使用する商品を含む翌営業日の改定を予約する。
2. 予約後に同じ税区分マスターを15%へ変更する。
3. 翌営業開始時に改定を適用する。
4. 商品が予約時の12%条件で適用されること、比較画面・適用結果・JSONも12%であることを確認する。

### E. セッション・権限

1. 販売担当でログインし、操作せず30分経過させる。販売画面からログイン画面へ戻ることを確認する。
2. 別の管理操作でログイン中担当者を停止する。5秒程度でログイン画面へ戻ることを確認する。
3. ログイン中担当者から返品、点検、設定等の権限を外し、対象操作が拒否されることを確認する。
4. 販売権限を外した場合はセッション継続不可になることを確認する。

### F. Outbox強制終了・多重実行

1. 同期対象を複数件作成し、Worker開始直後にアプリを強制終了または端末再起動する。
2. PROCESSINGが永久残留せず、lease期限後にRETRYへ戻ることを確認する。
3. 手動同期と自動Workerを近い時刻に実行し、同一eventが重複ステージされないことを確認する。
4. retry回数、エラー、object key、生成JSON件数を確認する。

### G. 同期フォルダー変更

1. 同期フォルダーを「店舗A 同期」に変更する。
2. 新規売上、返品、精算、入出金、メニュー改定を作成する。
3. 全種別のobject keyが`店舗A_同期/営業日/...`になることを確認する。
4. 変更前のPENDING/RETRY/FAILEDは新キーへ変わり、STAGED/SENTは旧キーを維持することを確認する。

### H. v0.1～v0.11回帰

## 仕様書に対して残る主要差分

v0.11.1は8件の安定化を優先した版であり、詳細仕様書v2.5の初版完成状態ではない。主な未実装・未完了は以下。

- SQLiteOpenHelperのままで、仕様書が実装基準とするRoom移行は未実施。
- 数量はIntで、1/100単位のscaled Longへ未移行。
- Google Drive OAuth、Drive APIアップロード、ACK、SALE_BATCH、Changes APIは未実装。
- 現在のOutboxはローカルJSONステージ基盤であり、仕様書の完全な不変canonical bytes・hash・ACK状態機械には未到達。
- つぐレジ＋、つぐレジ CDは未実装。
- 全88画面、バックアップ暗号、決済結果不明、完全な印刷結果不明処理などは未完成または実機未検証。
- 実プリンター、58mm/80mm実紙、旧APK更新、長時間運転、正式署名は未検証。

ビルド成功は実店舗運用可能の判定ではない。上記実機試験を完了し、重大不具合が0件であることを確認してからリリース判定する。
