# v1.36 BKP-AUTO-001 / BKP-001 自動バックアップ

## 正式仕様 v2.5 の契約

- 日計精算後に暗号化バックアップを作成する。
- 1日1回、暗号化バックアップを作成する。
- `backup.retention` は 7～365 世代、初期値 30 世代。
- 通常時は設定世代数を超えた古い成功世代から削除する。
- 容量閾値を満たせない場合は、最新の正常な自動バックアップを保護したうえで古い成功世代から追加削除する。
- 自動バックアップ本体は `DataProtectionManager` の暗号化バックアップ／検証経路を使用する。

## v1.36 実装方針

- 旧設定に `periodicEnabled=false`、`WEEKLY`、`settlementAutoBackupEnabled=false` が残っていても、読み込み時に `毎日 + Z精算後` へ安全側に移行する。
- Z精算後バックアップの無効化ゲートを削除し、精算確定後トリガを必須化する。
- 定期 WorkManager は 1 日間隔を固定し、指定時刻は初回実行の目安として扱う。
- `backup.retention` を永続化し、世代数上限と容量不足時の古い成功世代削除を分離して扱う。
- 手動バックアップ、復元予約中、破損・未検証状態は自動削除対象にしない。
- 設定画面では「1日1回」「Z精算後」を常時有効として表示し、保持世代数のみ 7～365 の範囲で変更可能とする。

## 検証

- `V033PeriodicBackupSettingsTest` の既存契約「Z精算後バックアップは常時有効」を維持する。
- `V139AutoBackupScheduleTest` で旧設定の安全移行、30世代初期値、7～365境界、世代削除、容量不足時の最新世代保護、暗号化作成経路を確認する。
- 累積 unit test / Kotlin compile / 3 APK build / APK独立検証を実施する。

以下はソフトウェア検証とは分離し、実機確認完了まで未確認として扱う。

- 24時間運用で1日1回のWorkManager実行タイミング。
- 再起動・Doze・バックグラウンド制限後の遅延実行／復帰。
- 実際のZ精算確定後に暗号化バックアップが生成されること。
- 実ストレージ容量逼迫時の削除・通知・継続動作。
