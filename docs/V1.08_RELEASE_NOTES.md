## 主な変更

### SAF送信先の同名複数項目を任意選択しない

v1.07までの `OutboxExternalDocumentProvider.findChild()` は、要求名と一致する子項目を見つけると最初の1件を返していた。

v1.08では、一致する子項目を最後まで数え、候補が2件以上存在した場合は `OutboxDuplicateDisplayNameException` として処理を停止する。

- 一致0件: 未作成
- 一致1件: 従来どおり利用
- 一致2件以上: 衝突FAILED

### 既存項目を非破壊で保持

複数候補のどれが正しいかを推測しないため、重複検出を行う `findChild()` 自体ではdelete/create/rename/writeを行わない。

対象は以下すべて。

- object key途中のフォルダ
- 確定JSON
- `.partial` 一時JSON

複数候補検出時は既存の衝突安全経路へ合流する。

- 即時FAILED
- 自動再試行なし
- SQLite売上保持
- Sales Journal保持
- staging JSON保持
- 送信先既存候補をすべて保持
- 監査 `SYNC_OUTBOX_EXTERNAL_COLLISION`
- 外部で重複を解消後の手動retryを維持

### v1.06 / v1.07の安全性を維持

同名候補が1件だけならv1.06のサイズ＋SHA-256検証を従来どおり実行する。

新規create/rename後はv1.07の実保存名完全一致検証を従来どおり実行する。

v1.08はこれらの前段に「既存候補が一意であること」を追加するだけで、売上・税・会計・印刷等の業務仕様は変更しない。

- 一致0件／1件は一意として許可
- 2件目検出時に専用衝突例外

- 既存の即FAILED／自動retry抑止／監査衝突経路を再利用
