# v0.40 つぐレジ＋ 売上集計基盤

## 1. 目的

v0.39で取り込んだ売上ジャーナルを、営業日・店舗・端末単位で確認できる売上集計画面へ接続する。

本版では、売上イベントと取消イベントの意味を明示し、点検・精算・入出金などを売上へ誤加算しないことを最優先とする。

## 2. 対象アプリとバージョン

- つぐレジ: `0.40.0-dev.1` / versionCode 70
- つぐレジ＋: `0.2.0-dev.1` / versionCode 2
- つぐレジ CD: `0.14.0-dev.1` / versionCode 7（変更なし）

## 3. 売上集計対象

売上集計へ含めるイベントは次の2種類だけとする。

- `SALE`: 売上額を加算
- `REVERSAL`: 取消額を減算

次のイベントは取込件数・取引詳細には表示するが、売上集計から除外する。

- `INSPECTION`
- `Z_SETTLEMENT`
- `CASH_MOVEMENT`
- `BUSINESS_OPEN`
- `BUSINESS_STATE`
- `MENU_REVISION`

点検値・精算値・入出金額を売上として二重計上しない。

## 4. 金額の取得順序

売上・取消金額は次の順で取得する。

1. 取込時に正規化した `imported_journal.total_amount`
2. payloadの `totalAmount`
3. payloadの `grossAmount`
4. payloadの `amount`

いずれにも金額がないSALE/REVERSALは0円として確定せず、金額不足件数へ計上する。画面上の合計は参考値と明示し、客単価は算出しない。

## 5. 取消相殺

純売上は次の式で求める。

```text
純売上 = SALE金額合計 - REVERSAL金額合計
```

取消payloadの `originalSaleId` と、同一店舗・同一端末のSALE `aggregateId` を照合する。

- 照合できた取消: 元売上を有効取引件数から除外
- 照合できない取消: 取消金額は純売上から減算するが、取引件数の根拠が不足するため客単価は算出しない

店舗または端末が異なる同一番号の売上を誤相殺しない。

## 6. 客単価

客単価は次の条件をすべて満たす場合だけ算出する。

- 金額不足のSALE/REVERSALが0件
- 元売上に結び付かないREVERSALが0件
- 有効取引件数が1件以上

```text
客単価 = 純売上 / 有効取引件数
```

端数はLong整数除算とし、通貨の最小単位未満は保持しない。

## 7. フィルター

画面上で次を選択できる。

- 営業日: 最新営業日を初期選択、全営業日も選択可能
- 店舗: 全店舗または特定 `storeId`
- 端末: 全端末または特定 `terminalId`

フィルターはSQLiteのプレースホルダーを使い、文字列連結による値埋込みは行わない。

## 8. 支払方法別内訳

payloadに次のいずれかがある場合に集計する。

- `paymentBreakdown` オブジェクトまたは配列
- `payments` 配列
- `paymentMethod` / `paymentType` / `tenderType` と金額

SALEは加算、REVERSALは減算する。

現行POSの一部JSONには支払方法が含まれないため、内訳がない取引を含む場合は「表示分だけの集計」と明示する。内訳不足を推測値で補完しない。

## 9. 税額内訳

payloadの `taxTotals` 配列を優先し、`taxAmount` がある場合は税額合計として扱う。

- 税率別・税区分別の名称を可能な範囲で表示
- SALEは加算、REVERSALは減算
- 内訳不足を推測値で補完しない

## 10. 取引詳細

フィルター対象イベントを発生日時の新しい順で表示する。

表示内容:

- 発生日時
- イベント種別
- 営業日
- 店舗ID
- 端末ID
- aggregateId
- 売上・取消の符号付き金額
- payload schema
- 取込元ファイル名
- REVERSALの元売上ID
- payload JSONプレビュー（先頭1,200文字）

画面表示は新しい順で50件までとする。集計計算自体は50件へ制限しない。

## 11. DB移行

`tsuguregi_plus.db` をversion 2へ更新する。

追加する索引:

- `idx_imported_journal_report`
- `idx_imported_journal_aggregate`

既存の取込済データ・取込履歴・隔離データは削除しない。

## 12. テスト

最低限、次をユニットテストする。

- SALE加算
- REVERSAL減算
- 元売上との相殺
- 非売上イベント除外
- 金額不足時の客単価抑止
- 営業日・店舗・端末フィルター
- 支払方法別内訳の取消減算
- 税額内訳の取消減算
- v0.39からのDB移行用索引定義
- UI・Repository・Docs・CIの接続

## 13. 実機確認が必要な事項

以下はコード・CI・APKビルドの確認対象であり、実機確認済みとは扱わない。

- v0.39のDBを保持したままv0.40へ上書き更新した場合のDB移行
- 数千件以上のジャーナルを対象とした集計時間・メモリ使用量
- 長い店舗ID・端末ID・ファイル名の表示
- 横画面でのフィルターメニュー操作
- 50件の取引詳細展開・スクロール
- Google Drive、USB、端末フォルダーから取り込んだ実データの金額・税・支払内訳
- 同一売上の取消、元売上が未取込の取消、別端末の同一aggregateId
- payloadが1,200文字を超える場合の表示
