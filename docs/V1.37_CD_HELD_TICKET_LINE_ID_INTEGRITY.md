# v1.37 CD保留伝票の明細行ID統合修正

対象: 旧保留伝票の持越し、保留→作業中カート呼出、退避、伝票の結合・分割。

原因: HeldTicketSafetyCoordinator.toDatabaseValues() が行IDを保存せず、正常な行IDでも保留票操作後に空IDへ戻る。旧 held_ticket_items には line_id が空/重複して残る。

修正:
- 保留票の通常閲覧はreadonly。要修復の伝票だけ同一SQLiteトランザクションで id+ticket_id を特定し line_id 列のみUUID補完（価格/税/数/値引を変更しない）。
- 別のトランザクション中に loadHeldTicket した場合、独立コミットはせず既存トランザクション内で修復。
- 退避/呼出/結合/分割共通の ContentValues に line_id を必ず格納。共通保留保存では再採番が必要な行だけ正規化し税snapshotと一致させる。
- 同じ lineId を持つ保留伝票同士を結合しても target 側IDを維持し source 側IDを再採番する。
- 行数量の一部だけを分割した場合、残側の行IDを保持し移動側には新規IDを発行する。全行移動なら既存IDを保持。
- テスト: 新旧ID・重複ID、保留結合、全行/部分分割、金額保持、保存項目を回帰検証。

制約: 実機DBアップグレードや電源断中の結合操作は未試験。税snapshotの内部DB実行はCIのJVMテストでは代替できない。
