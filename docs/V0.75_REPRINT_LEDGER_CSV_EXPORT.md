# v0.75 通常レシート再印字台帳 CSV出力

## 目的

SCR-648で調査した再印字要求を、監査・問い合わせ・障害調査で利用できるCSVとしてユーザーが明示的に保存できるようにする。

出力対象はボタン押下時点の **適用済み検索条件** と **固定snapshot** とする。検索欄・任意期間欄へ入力しただけで未適用の値や、snapshot取得後に作成された新着要求はCSVへ混入させない。

## 出力方法

Android Storage Access Frameworkの `CreateDocument("text/csv")` を利用し、ユーザーが保存先を選択する。

出力時はSQLiteの1 SELECTをcursorで走査し、全件をListへ載せず逐次書き込む。SCR-648の200件表示上限とは独立し、固定snapshot内で条件に一致する全要求を出力する。

## 固定条件

CSV SQLは次を再利用する。

- `SaleReceiptReprintLedgerPolicy.buildDatabaseQuery(criteria)`
- `SaleReceiptReprintStablePagingPolicy.appendSnapshotBound(base, snapshot)`
- `ORDER BY requested_at DESC, id DESC`

これにより状態・固定期間・任意期間・検索語・snapshot上限が画面と一致する。

## CSV形式

- UTF-8 BOM
- CRLF
- 全セルを二重引用符で囲む
- セル内 `"` は `""` へエスケープ
- requested_at / sale_created_at は端末タイムゾーンのISO offset日時

列:

1. request_id
2. requested_at
3. sale_id
4. sale_amount
5. sale_created_at
6. print_job_id
7. operator_name
8. paper_width_mm
9. status
10. attempt_count
11. last_error

## CSV数式注入対策

ユーザー由来・外部由来文字列が先頭空白を除いて `=` `+` `-` `@` から始まる場合は、先頭へ `'` を付加する。

対象にはrequest ID、担当者名、last error等を含める。Excel等でCSVを開いた際に文字列が数式として評価されることを防ぐ。

## 権限

SCR-648自体と同じく `VIEW_SALES` を必須とする。

保存先選択画面から戻った後にも現在のoperator sessionを再取得し、`VIEW_SALES` が失効していればCSVを書き込まずfail-closedとする。

## データ安全性

CSV出力は読み取り専用。

- salesを更新・削除しない
- tax/payment情報を更新しない
- `sale_receipt_reprint_requests` を更新・削除しない
- `print_jobs` を更新・削除しない
- OAuth token / Authorization header / raw sales JSON / content URIをCSVへ含めない

## 実機確認が必要な項目

- Android標準の保存先選択UI
- 日本語を含むCSVのExcel等での表示
- 0件時のボタン状態
- 200件超・1,000件超の逐次出力
- 保存先選択中の権限失効
- 保存先書き込み失敗時のエラー表示
- snapshot後に新着が入った状態でCSVへ混入しないこと
- 任意期間＋検索語＋状態フィルタの複合条件
