# v0.94 起動・自己診断レスポンシブ対応

## 目的

v0.94では、アプリ起動後に担当者ログインより先に表示される `SCR-001 起動・自己診断` の固定レイアウトを、既存の共通レスポンシブ基盤へ接続する。

現行画面は診断カードが `700dp × 280dp`、外周余白が固定、本文が非スクロールである。800×480やAndroidフォント倍率を上げた環境では、`診断完了・担当者選択へ` が画面外へ押し出される可能性があるため、販売開始前の阻害要因として解消する。

## 変更内容

- `rememberRegisterResponsiveMetrics()` を使用する。
- 診断本文に `rememberScrollState()` / `verticalScroll()` を追加する。
- Compact時は外周余白に共通 `screenPaddingDp` を使用する。
- Compact時は本文を上寄せし、通常時は従来どおり中央寄せを維持する。
- Compact時の診断カードは固定700dp幅をやめて全幅とし、最小高250dpを確保する。
- 通常時は従来の `700dp × DIAGNOSTIC_CARD_HEIGHT_DP` を維持する。
- Compact時の `診断完了・担当者選択へ` は全幅54dp、通常時は従来の340dp幅×54dpを維持する。
- タイトルはCompact時に縮小し、通常時の見た目は維持する。

## 変更しない処理

- SQLite初期化・読込
- 作業中取引の復元判定
- 印刷キュー件数表示
- プリンター未設定時の販売可否
- Google Drive未接続時の販売可否
- `onComplete = { screen = AppScreen.LOGIN }` の遷移
- 税、販売、会計、印刷、領収書、Drive同期、CD通信
- backup / rollback / restoreデータ

## 自動検証

- 診断画面が共通レスポンシブメトリクスを使用すること。
- Compact時に本文スクロールが存在すること。
- Compact時に700dp固定幅を使用しないこと。
- 通常サイズでは従来の診断カード幅・高とボタン幅を維持すること。
- 診断完了後の遷移先が担当者ログインのままであること。
- v0.92 APK実体整合性ゲートを継続すること。
- 3アプリの累積unit test、Kotlin compile、debug APK buildを継続すること。

## 実機確認

本版単独の実機確認は行わず、以下を開発終盤の**最終総合実機試験**へまとめて繰り越す。

- 800×480〜1920×1080でのSCR-001表示
- Androidフォント倍率変更時の表示とスクロール
- 作業中取引あり／なし
- 印刷キューあり／なし
- `診断完了・担当者選択へ` からSCR-010への実画面遷移

CI成功・APK生成成功を実機確認済みとは扱わない。
