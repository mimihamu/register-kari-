# v1.22 Google Drive import / fingerprint atomicity

## 目的

v1.20でDrive pagination completeness、v1.21で同期single-flightを保証した後、1ページのSQLite commit境界を確認した。

従来は `SalesJournalImportRepository.importDocuments()` が `imported_journal` / `import_rejections` / `import_runs` をtransaction commitしてから、`GoogleDriveDirectSyncRepository` が `drive_sync_files` fingerprintを別commitしていた。

このため、import commit直後からfingerprint記録までの間にプロセス停止・クラッシュが起きると、次回同期では同じDrive fileIdを未処理と判断して再download・再importする。売上本体はduplicateImportKeyで二重計上を防げても、余分なimport runや不正JSONの隔離履歴が再作成されるクラッシュ境界が残っていた。

## v1.22の修正

- `SalesJournalImportRepository.importDocumentsWithCommitHook()` を追加。
- 既存の `importDocuments()` はcommit hookなしで同メソッドを呼ぶため、Drive以外の既存呼出契約を維持する。
- Drive pageの新規/変更ファイルでは次を1つのSQLite transactionに統合する。
  1. import run作成
  2. JSON parse / imported_journal または import_rejections 書込
  3. import run完了更新
  4. 対応する `drive_sync_files` fingerprint書込
  5. `setTransactionSuccessful()`
- fingerprint書込で例外が発生した場合、売上取込・隔離・import run・fingerprintを同じtransactionでrollbackする。
- transaction成功後にのみ次のDrive pageへ進む。
- content SHA-256が既知値と一致しimport不要なmetadata更新だけの場合は、従来どおりfingerprintのみ更新する。

## 維持する保証

- v1.19 Drive server version fingerprint / SHA-256 fallback。
- v1.20 全page取得、incompleteSearch失敗化、page token循環検出。
- v1.21 periodic / startup / manual / 画面同期のsingle-flight、run ownership。
- duplicateImportKey完全一致の冪等性と内容衝突の隔離監査。
- Drive削除とローカル売上削除は自動連動しない。

## 回帰テスト

`V122DriveImportFingerprintAtomicityTest` で以下を固定する。

- commit hookがimport run完了更新後、`setTransactionSuccessful()`より前に実行されること。
- Drive fingerprint書込がcommit hook内で実行されること。
- 次pageへの遷移がatomic page commitの後にあること。
- fingerprint writerがcallerから渡されたSQLiteDatabaseを使用すること。
- Drive以外の既存 `importDocuments()` APIが維持されること。
- v1.20/v1.21の安全境界が残ること。

## 実機確認へ繰り越す項目

- 実Drive同期中のimport commit境界での強制プロセス停止試験。
- 再起動後に同じfileIdが余分なimport run / rejectionを生成しないことの実端末確認。
- v1.20/v1.21から継続する5,000件超、ページ途中ネットワーク断、同期競合の統合実機確認。
