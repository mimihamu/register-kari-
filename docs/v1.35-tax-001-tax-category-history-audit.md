# v1.35 TAX-001 税区分履歴 監査

## 対象

初版完成マスター Issue #137 の TAX-001「税区分履歴」。詳細仕様書 v2.5 の税マスタ／営業日適用要件を、既存の動的税区分と売上税スナップショットを壊さずに補強する。

## 仕様対応

- 税区分キーは一意の論理IDとして扱う。
- 履歴revisionに名称、税率、内税／外税／非課税、端数処理、軽減税率フラグ、税記号、有効／無効、適用開始営業日、適用終了営業日を保持する。
- 新規・編集する税区分は適用開始営業日を必須とする。
- 非課税は税率0%かつ `NON_TAXABLE` とする。
- 適用判定は端末の暦日ではなく `businessDate` を引数として行う。暦日0時をまたいだだけでは税率を切り替えない。
- 同一税区分キーの将来営業日revisionを登録した場合、OPEN中の営業日に使う現行行を即時上書きしない。`tax_category_history_v135` へ将来revisionを保存し、次のOPEN営業日の `business_date` に該当した時だけ互換テーブル `dynamic_tax_rules` へ昇格する。
- 同一キーの前revisionは次revisionの前営業日までに自動終端し、履歴として残す。明示的な履歴APIでは重複期間を異常として拒否する。
- `dynamic_tax_rules` の物理DELETEはTAX-001 triggerで禁止する。廃止は `enabled=false` と有効期間で表現する。
- 既存DBに存在する開始日未指定のlegacy税区分は、履歴移行時のみ `0001-01-01` 開始として扱う。TAX-001導入後の新規・編集では空の開始営業日を許可しない。
- 既存の `LineTaxSnapshotStore`（cart / held / sale）は維持し、保留・確定売上・再印字が税マスタの後日変更で書き換わらない構造を保持する。

## 実装

### `TaxCategoryHistoryV135.kt`

- `TaxRoundingV135`: `FLOOR / HALF_UP / CEILING`
- `TaxCategoryRevisionV135`: 税区分revisionモデル
- `TaxCategoryHistoryPolicyV135`: businessDateだけを使う純粋なvalidation / overlap / resolve
- `tax_category_history_v135`: 正規化された履歴テーブル
- `trg_tax001_stage_future_revision_v135`: OPEN営業日より未来の同一キー改定を即時反映せず予約
- `trg_tax001_business_open_insert_v135` / `...update...`: OPEN営業日の開始／変更時に該当revisionを現行税マスタへ昇格
- `trg_tax001_block_delete_v135`: 物理DELETE禁止
- `trg_tax001_require_start_*`: TAX-001導入後の開始営業日必須化
- 起動時にOPENセッションが残っている場合も `promoteForOpenBusinessDate` でその営業日のrevisionへ復元する。

### Bootstrap

`MixedTaxCartBootstrapProviderV135` から `TaxCategoryHistoryRuntimeV135.initialize` を起動し、販売UIが動く前に履歴schema／trigger／OPEN営業日の現行revisionを確定する。

## 既存機能との境界

- TAX-002 税率別計算の計算式そのものはこの項目では変更しない。
- TAX-004 のcart / held / sale税スナップショットはそのまま利用する。
- TAX-005 の返品／訂正時の元取引税再現は別項目で改めて監査する。
- **TAX-006** の設定画面について、履歴一覧表示、端数処理の編集UI、将来revisionの予約表示／取消などはTAX-006側で完成させる。TAX-001ではデータ層と営業日切替契約を先に固定する。

## 自動テスト

`V135Tax001TaxCategoryHistoryTest` で以下を固定する。

1. 営業日Dでは旧税率、D+1では新税率を解決する。
2. 暦日0時をまたいでもbusinessDateがDのままなら旧税率を使う。
3. 無効revisionは履歴には残るが新規販売用には解決しない。
4. 同一キーの重複期間を拒否する。
5. 非課税0%／課税税率のvalidation。
6. 将来revision staging triggerとOPEN営業日promotion triggerの存在。
7. 適用開始営業日必須と物理DELETE禁止。
8. cart / held / sale の既存税スナップショット経路を維持。
9. bootstrap順序。

## 実機未確認

自動テスト／APK検証が成功しても以下は実機未確認として残す。

1. 営業日Dで旧税率商品を登録できること。
2. D営業中に同一税区分キーへD+1開始の新税率を設定しても、Dの販売は旧税率のままであること。
3. 暦日0時をまたいでも精算・営業日更新前は旧税率のままであること。
4. Z精算後、新しい営業日D+1を開始すると新税率へ切り替わること。
5. 端末再起動後もOPEN営業日の税率が変わらないこと。
6. 過去revisionが履歴から消えないこと。
7. 税区分の物理削除が拒否され、無効化運用になること。
8. 保留伝票をDで作成し、D+1で呼び出してもD時点のline tax snapshotを維持すること。
9. 過去売上のレシート再印字が当時の税snapshotと一致すること。
10. 既存DBからTAX-001 schemaを追加した際、legacy税区分が失われないこと。

この実機確認が未了のため、Issue #137 のTAX-001は自動検証だけで完了扱いにしない。
