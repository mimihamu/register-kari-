## 主な変更

### 外部同期先の既存JSONを非破壊化

v1.05以前は、Google Drive等の外部送信先に同一object keyのJSONが既に存在し、今回のstaging JSONと内容が異なる場合、既存JSONを削除して置き換える経路があった。

v1.06ではこの自動置換を廃止した。

- 同名・同サイズ・同SHA-256: 既送信として成功
- 同名・異サイズ: 衝突として停止
- 同名・同サイズ・異SHA-256: 衝突として停止
- 同名フォルダ: 衝突として停止
- 衝突時に既存の確定JSONを削除・上書きしない
- 衝突は自動再試行せず即FAILED
- ローカルstaging、sync_outbox、Sales Journal、SQLite売上を保持
- `SYNC_OUTBOX_EXTERNAL_COLLISION` を監査へ記録
- 管理者が外部で衝突を解消した後の手動再試行は維持

### 未確定一時ファイルのcleanupは維持

`*.json.partial` は送信途中の未確定一時ファイルであり、前回処理の残留 `.partial` の回収は継続する。今回処理で新規作成した未確定ファイルの失敗時cleanupも維持する。

既存の確定JSONを保護する規則と、一時ファイルcleanupを分離した。

### 売上確定後の境界を再確認

リリース前スキャンで通常会計のSQLite transactionを再確認した。

売上本体、明細、税/支払スナップショット、receipt print job、Sales Journal / sync_outbox、work cart clear、sale commit key bindは同一transaction内にあり、売上だけが確定して印刷queueまたは同期outboxが欠落する構造は確認されなかった。

起動時の残留PRINTING jobは自動再送せずFAILEDへ回収する既存仕様も維持する。

## 自動テスト

`V106DriveJsonCollisionSafetyTest` を追加する。

- 同一サイズ＋同一SHA-256のみ既送信扱い
- サイズ差/ハッシュ差/同名フォルダは衝突
- 既存確定JSONの削除経路がdeliverOneから消えていること
- 衝突がforcePermanentで即FAILEDになること
- 衝突時に自動retryを推奨しないこと
- FAILED状態を後段のIDLE更新で隠さないこと
- 手動retry経路を維持すること
- `.partial` cleanupを維持すること
- staging/outbox/journalを衝突処理で破棄しないこと
- v1.05 Z精算安全策を維持すること
- release identity / docs / CI gate

v1.06への版番号更新に伴い、v1.05のrelease identityテストは現行Gradleを135へ固定せず、v1.05 release notesの履歴値を確認する方式へ更新する。
