# v1.11 SAF renameフォールバック安全化

## 背景

v1.10までで、SAF / DocumentsProviderへのJSON送信について、同名衝突、Provider自動変名、重複表示名、query null、メタデータquery nullを安全側に扱うようにした。

一方、`.partial` を確定JSON名へrenameする箇所では、`OutboxProviderNameMismatchException` 以外のすべての例外をcatchして `null` に変換し、rename非対応と同じcopyフォールバックへ進んでいた。

このため、Provider一時障害、権限異常、メタデータ確認不能など、本来その場で中断・再試行すべき異常まで「rename非対応」と誤認する余地があった。

## v1.11 方針

- `DocumentsContract.renameDocument()` が `null` を返した場合だけcopy-to-finalへフォールバックする。
- rename中に例外が発生した場合はcatchで握りつぶさず上位へ伝播する。
- v1.10の `OutboxProviderMetadataUnavailableException` は通常retry経路へ伝播する。
- v1.07の `OutboxProviderNameMismatchException` は永久衝突経路へ伝播する。
- `SecurityException` など権限異常は既存の権限喪失経路へ伝播する。
- 例外発生時に不要なcopy-to-finalを開始しない。

## 既存安全性との関係

- v1.06: 同名確定JSONの内容衝突を非破壊で停止。
- v1.07: Provider自動変名を拒否。
- v1.08: 同名複数候補の任意選択を禁止。
- v1.09: 子一覧query nullを「対象なし」と扱わない。
- v1.10: 表示名／サイズメタデータquery nullを未検証成功にしない。
- v1.11: rename例外をrename非対応へ誤変換しない。

## 実機確認

rename非対応Provider、rename成功Provider、一時障害、権限喪失、Provider自動変名は最終総合実機試験で確認する。
