# v0.36 つぐレジ売上ジャーナル外部JSON契約

## 目的

v0.35で外部配送可能になったJSONを、将来の「つぐレジ＋」が安全かつ重複なく取り込める固定契約にします。Google Drive REST APIやGoogle OAuthは使用しません。

## 固定エンベロープ

外部配送JSONの最上位は `jp.co.tenposinfo.tsuguregi.sales-journal`、`schemaVersion=1` とします。互換性を壊す変更だけで `schemaVersion` を増やし、任意項目の追加は同一バージョン内で許可します。

必須項目は次のとおりです。

- `schema`, `schemaVersion`, `minimumReaderVersion`
- `duplicateKeyVersion`, `duplicateImportKey`
- `eventId`, `eventType`, `aggregateId`, `occurredAt`
- `storeId`, `terminalId`, `businessDate`
- `payloadSchema`, `payload`

機械可読仕様は `docs/schemas/tsuguregi-sales-journal-v1.schema.json` を正本とします。

## 種別

- `SALE`: 売上
- `REVERSAL`: 返品・取消
- `INSPECTION`: 点検
- `Z_SETTLEMENT`: Z精算
- `CASH_MOVEMENT`: 入出金
- `BUSINESS_OPEN`: 営業開始
- `BUSINESS_STATE`: 営業状態変更
- `MENU_REVISION`: メニュー改定

点検とZ精算は、既存 `register.settlement.v1` payloadの `type` から分離します。

## 店舗・端末識別

- 店舗ID未設定時は `STORE-UNCONFIGURED` を明示します。
- 端末IDはSQLiteの `sync_runtime_settings` にUUIDを一度生成して固定します。
- 将来の設定画面から `SalesJournalIdentityStore.update` を使用して店舗ID・端末IDを変更できます。
- 端末初期化やDB復元でIDが変わる可能性は運用上の確認事項として残します。

## 重複取込防止

`duplicateImportKey` は以下を連結した値のSHA-256です。

1. duplicateKeyVersion
2. storeId
3. terminalId
4. businessDate
5. eventType
6. eventId

形式は `sj1-` + 64桁小文字16進数です。「つぐレジ＋」はこのキーを一意制約として扱い、同じキーの再取込を成功扱いの重複スキップにします。

## 後方互換

v0.35以前に生成済みの以下のJSONも読取対象として維持します。

- `register.sale.v2`
- `register.reversal.v2`
- `register.settlement.v1`
- `register.menu-revision.v1`
- `register.generic.v1`

v0.36はこれらを `payload` にそのまま内包します。税内訳 `taxTotals`、明細 `items`、支払 `payments` の既存構造を壊しません。

## 失敗分離

JSON契約の生成や外部配送が失敗しても、SQLite、`sales_journal`、売上、印刷、返品、点検、Z精算は巻き戻しません。v0.35のOutbox再試行・手動復旧境界を維持します。

## 実機未確認

- 実売上・返品・点検・Z精算で生成される外部JSON
- 端末IDの初回生成と再起動後の維持
- DBバックアップ復元時の端末ID運用
- 「つぐレジ＋」でのJSON Schema検証と重複スキップ
- Google Drive、USB、端末フォルダへの配送後ファイル内容
