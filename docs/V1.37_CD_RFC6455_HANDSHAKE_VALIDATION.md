# CD WebSocket認証・RFC6455ハンドシェイク検査

POS側WebSocket接続入口でHTTP GET/HTTP1.1、Upgrade: websocket、ConnectionのUpgradeトークン、Version:13、Sec-WebSocket-Keyのbase64正規形＋16バイト乱数を検証する。共有トークンはMessageDigest.isEqualで比較。トークン不一致は401、正しいトークンでも不正handshakeは400。旧版CDもRFC6455標準なので互換性維持。

CD-IDヘッダはUUIDの8-4-4-4-12構文だけ許可し、正規化して接続先自身のsnapshotに反映。不正ヘッダは旧クライアント同様IDなしとして扱い、認証には使用しない。

ローカルTCP/WebSocketの不正ハンドシェイク拒否もテスト。平文wsの盗聴を防ぐ機能ではないため、外部ネットワークには公開しない。
