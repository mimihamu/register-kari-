# v1.00 EPSON日本語印字 文字化け修正

## 1. 背景

実プリンターで日本語を印刷した際、文字化けが発生していることを実機確認で把握した。

v0.99までの送信処理は、日本語文字列を `MS932` の2バイト列へ変換していた一方、プリンター初期化後は `ESC t 1` による1バイト文字テーブル選択だけを行っていた。EPSON日本語仕様で使用する漢字コード体系の選択が送信されていなかったため、アプリ側の2バイト日本語とプリンター側の解釈が一致していなかった。

## 2. v1.00の対応

`PrinterProfile.EPSON_TM_JAPAN` に以下を明示する。

- Java Charset: `Shift_JIS`
- EPSON漢字コード体系: Shift JIS
- `ESC @` 初期化後に `FS C 1` を送信
- その後に本文のShift JISバイト列を送信

EPSON日本語プロファイルの文書開始バイト列は次の順序とする。

```text
ESC @
ESC t 1
FS C 1
ESC a 0
<Shift_JIS本文>
```

16進表記:

```text
1B 40 1B 74 01 1C 43 01 1B 61 00
```

`ESC @` はプリンター状態を初期化するため、漢字コード体系の選択は必ず初期化の後で再設定する。

Shift JIS漢字コード体系では先頭バイトにより1バイト／2バイト文字が判定されるため、本文全体を固定の漢字モードへ切り替える `FS &` は追加しない。

## 3. 適用範囲

`PrinterCommandEncoder.encodeText()` を使用する既存印刷経路へ共通適用される。

- 売上レシート
- レシート再印字
- 領収書
- 業務帳票
- 精算関連帳票
- プリンター連続印刷試験
- その他 `PrinterCommandEncoder` を通る文字印刷

TCP送信自体はv0.99の `TcpEscPosPrinterGateway` / `PrinterEndpointSendGate` をそのまま使用する。

## 4. プロファイル境界

### EPSON_TM_JAPAN

- `Shift_JIS`
- `FS C 1` を送信
- EPSON DLE EOT状態確認を継続

### STAR_ESC_POS / GENERIC_ESC_POS

- v1.00ではEPSON専用の `FS C 1` を追加しない
- `kanjiCodeSystem = null`
- 既存互換動作を維持

機種依存コマンドを汎用プロファイルへ拡散しない。

## 5. 自動テスト

`V100JapanesePrinterEncodingTest.kt` で次を検証する。

- EPSON日本語プロファイルのCharsetが `Shift_JIS`
- `kanjiCodeSystem = 1`
- 初期化直後の `FS C 1`
- `つぐレジ` のShift JISバイト列
- UTF-8バイト列が混入していないこと
- `領収書`、`内`、`外`、`※`、`円`、`￥` のShift JISバイト列
- `FS C 1` が `ESC @` より後、本文より前にあること
- STAR / GENERICに `FS C 1` が混入しないこと
- 既存プリンター連続印刷試験が1枚から実行でき、日本語サンプルを持つこと

既存 `V012PrinterProfileTest.kt` も、EPSON文書開始シーケンスを `ESC @ / ESC t 1 / FS C 1 / ESC a 0` として回帰確認する。

## 6. 実プリンター再確認方法

v1.00 APKを実機へ導入後、既存のプリンター連続印刷試験を利用する。

推奨条件:

- プロファイル: `EPSON TM（日本語）`
- 印刷回数: `1`
- 印刷間隔: `1秒`
- 対象プリンターのIP / TCPポートを確認

印刷される代表文字:

```text
つぐレジ 連続印刷試験
あいうえお アイウエオ 1234567890
日本語印字・通信・連続動作確認
```

確認項目:

1. ひらがなが正しく印字される
2. カタカナが正しく印字される
3. 漢字が正しく印字される
4. 数字・記号が崩れない
5. レシート／領収書では `内 / 外 / 内※ / 外※` が正しく印字される
6. 文字化けが一部だけ残る場合は、その文字列と実紙を記録する

## 7. 変更しない安全仕様

- TCP 9100送信
- v0.99のendpoint単位シリアライズ
- 自動／手動の同一ジョブ二重印刷防止
- `CONNECTING / CONNECTED / WRITE_STARTED / FLUSHED`
- `WRITE_STARTED`以降の障害を送信結果不明として自動再送しない仕様
- 58mm / 80mm設定
- カット設定
- ドロア設定
- EPSON DLE EOT状態確認
- 売上・税計算・インボイス処理
- Google Drive
- つぐレジ CD
- データ保護・バックアップ・復元・ロールバック

売上DB等の削除・上書き処理は追加しない。

## 8. 実機検証の扱い

v1.00ではソース・バイト列・CIまで自動検証するが、**文字化けが実プリンターで解消したことは実紙を再確認するまで未確認**とする。

実機再確認結果は最終総合実機試験へ引き継ぐ。ただし今回の文字化けは既に実機で発生確認済みのため、v1.00 APK完成後は日本語1枚テストを優先して実施する。
