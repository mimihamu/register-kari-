# v1.05 Z精算 現金実査必須化

## 目的

Z精算で現金実査を空欄のまま進めた場合に、理論現金を自動的に実在高として保存してしまう挙動を廃止する。

従来は `actualCash == null` の場合に `expectedCash` を使用していたため、実際に現金を確認していなくても差異0円のZ精算記録を作成できた。Z精算は営業終了を伴う確定操作であり、実査額を明示入力して理論現金との差異を記録することを優先する。

X点検は営業途中の参考確認として従来互換を維持し、現金実査が空欄の場合は理論現金を使用できる。

## 1. 共通ポリシー

`SettlementActualCashSafetyV105` を追加する。

- Z精算 + `actualCash == null` は拒否する。
- 拒否メッセージ: `Z精算では現金実査を入力してください。`
- X点検 + `actualCash == null` は従来通り許可する。
- X/Zとも負数は拒否する。
- 0円は明示入力された有効な実査額として扱う。
- 保存に使用する実査額の決定をUIではなく共通ポリシーへ集約する。

## 2. UI

`SettlementActivityV030` のZ精算画面を次のように変更する。

- 入力ラベルを `現金実査額（必須）` と表示する。
- 必須であることを補足表示する。
- 空欄では `Z精算の確認へ` を有効化しない。
- 空欄時のプレビューは理論現金を実査として表示せず、`現金実査: 未入力` / `過不足: 未計算` と表示する。
- 確認ダイアログは有効な実査額がある場合だけ開く。

X点検では従来の `現金実査額（空欄は理論額）` を維持する。

## 3. Coordinator / Storeの防御

UIだけの制御には依存しない。

`SecureOperationsCoordinator.recordSettlement()` で共通ポリシーを検証し、非UI呼び出しでも空欄Zを拒否する。

さらに `OperationsStore.recordSettlement()` でも `effectiveActualCash()` を使用し、DB保存直前でも同じ規則を適用する。

これにより、将来別画面や別経路からZ精算を呼び出しても、実査額なしでは保存できない。

## 4. 維持する既存安全策

次は変更しない。

- Z精算と営業セッション終了の同一SQLite transaction
- Z精算operation keyによる永続重複防止
- 未会計伝票のZ精算禁止
- 未印刷job確認
- 責任者PIN承認
- settlement snapshot / payment totals保存
- Z精算票印刷job
- Z精算後自動バックアップ要求
- X点検の空欄→理論現金互換
- 売上・税・値引・支払・印刷・Drive・CDの既存業務ロジック

## 5. 自動テスト

`V105SettlementActualCashSafetyTest` で次を固定する。

- Z空欄を拒否する。
- Zの0円は許可する。
- Zの正数はその値を保存対象にする。
- X/Zの負数を拒否する。
- X空欄は従来通り理論現金へfallbackする。
- UI / Coordinator / Storeの3層で同じポリシーを利用する。
- Z精算のtransaction / preflight / operation key / session closeを維持する。

## 6. 実機確認

以下は最終総合実機試験へ繰越する。

- Z精算画面で空欄時に確認ボタンが無効であること
- 0円を明示入力した場合のZ精算
- 理論現金と実査額が一致する場合
- 過不足がある場合の精算票・履歴表示
- 未会計伝票あり/未印刷ありとの組み合わせ
- 責任者PIN誤り/正しいPIN
- Z精算完了直後の販売禁止
- Z精算直後のprocess kill / 再起動
- Z精算後自動バックアップ

実機未確認事項を確認済みとは扱わない。
