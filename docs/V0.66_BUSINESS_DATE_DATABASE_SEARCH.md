# v0.66 営業日売上 DB直接検索

## 目的

v0.65の「営業日別 売上検索」は、直近最大1,000件を読み込んだ後にメモリ上で絞り込んでいました。そのため、対象営業日の売上が直近1,000件より前にある場合は、正しい営業日を入力しても検索結果に出ない制約がありました。

v0.66では、検索条件をSQLiteへバインドして直接検索し、古い営業日も対象にできるようにします。

## 検索条件

- 営業日From / To（`business_date`）
- 売上No.
- 担当者名
- 支払方法
- 金額以上 / 以下
- 売上No.直接表示

営業日は会計時刻のカレンダー日から推定せず、保存済み `business_date` のみを使用します。

## DB検索

- 値はすべて `?` プレースホルダとselectionArgsでバインドします。
- LIKE検索では `\\`、`%`、`_` をエスケープします。
- 1ページ最大200件で取得します。
- `pageSize + 1` 件を取得し、次ページ有無だけ判定します。
- `LIMIT ? OFFSET ?` もバインドします。
- 並び順は `created_at DESC, id DESC` です。

## 旧DB

`business_date` 列の有無は `SchemaMigration.hasColumn()` で確認します。

- 列あり: 保存済み営業日で検索
- 列なし + 営業日条件あり: 0件でfail-closed
- 列なし + 営業日条件なし: 売上No.・担当・支払・金額条件は利用可能

旧売上の営業日を自動推定したり、バックフィルしたりしません。

## 非破壊条件

検索画面は以下を実行しません。

- salesのUPDATE
- ALTER TABLE
- 営業日のバックフィル
- 税計算の再計算
- 返品履歴の変更
- 印刷履歴の削除
- 同期履歴の変更

検索結果から領収書発行・返品取消を開く場合も、既存の各安全処理へ売上No.を引き渡すだけです。

## 実機確認

以下は実機未確認です。

- 大量売上データでのページ送り
- 古い営業日の検索速度
- 深夜0時跨ぎ売上のbusiness_date表示
- 売上No.を保持した領収書／返品画面遷移
