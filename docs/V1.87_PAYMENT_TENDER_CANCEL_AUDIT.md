# v1.87 支払取消の操作確認と監査ログを原子的に記録

## 修正前の問題
会計画面でカード／電子マネー／QR等を「取消」すると、画面の支払配分から直ちに消え、通常の `PaymentDraftStore.save()` が旧レコードを書き換えていた。決済端末での取消が済んでいない場合やアプリが途中終了した場合、実際の決済結果との照合証跡を失う。

## 変更点
- 現金以外の支払は明示の確認ダイアログを表示し、端末の取消・返金または金券の返却確認後にのみ支払一覧から取消。外部決済をアプリが自動取消するわけではない。
- 現金・非現金とも、支払取消は `PaymentDraftStore.cancelAllocation()` に集約。保存済みの会計キー・カート指紋・配分全件との一致、売上未確定を検証。
- `operation_audit` に `PAYMENT_TENDER_CANCELLED`、会計キー・指紋・取消方法・金額・担当者・確認有無を記録した上で、同一SQLiteトランザクション内で配分を変更。いずれかに失敗すれば取消も監査もロールバック。
- `save()` は既存配分に対する追加入力のみ許可。既存配分の削除／改ざんは `requireAppendOnly` で拒否し、監査を通らない取消経路を閉じる。
- 保存成功後に画面状態とCDへ通知。失敗時は支払記録を保持しエラーを表示。

## テストと未確認
`V187TenderCancellationSafetyTest.kt`：支払種別の確認必須、追記専用規則、SQLite上の監査先行・同一トランザクション・画面経路を検査。累積テスト／3 APK検証はCIの結果に従う。

**実機で未確認**：カード端末側の取消／返金実行、加盟店側履歴との照合、紙切れや通信断、端末再起動、監査ログ閲覧・運用。今回のダイアログは操作者の確認であり、CAT端末の取消成功をシステムが自動取得するものではない。
