# v1.27 Drive WorkManager同期の検証履歴整合

## 背景

v1.26では、手動のDrive API同期が失敗した際に、direct statusで確定した件数と同期検証履歴の件数が一致するよう修正した。

一方、`GoogleDriveDirectSyncWorker`から実行される起動時・即時・定期WorkManager同期はdirect statusだけを更新し、`GoogleDriveSyncVerificationHistoryStore`へ結果を保存していなかった。

このため、バックグラウンド同期が成功または失敗しても、診断画面の最新履歴が以前の手動同期のまま残り、direct statusと監査履歴の時系列が一致しない状態になり得た。

## v1.27の修正

- WorkManagerによるDrive API同期成功時も同期検証履歴を1件追加する。
- 成功履歴はrepository完了後のfinalized direct statusから件数を生成する。
- WorkManager失敗時は次の順序を維持する。
  1. `statusStore.failed(...)`
  2. `statusStore.load()`
  3. finalized statusからfailure history生成
  4. history append
  5. retryable判定
- failure historyはv1.26の`GoogleDriveFailureVerificationRecordV126`を再利用し、preflight failureでは0へresetされた件数、partial failureではcommit済み件数をそのまま記録する。
- WorkManager由来であることは既存`message`内に記録する。SharedPreferencesのhistory schemaは変更しない。
- repositoryのsingle-flight、run-token ownership、page atomic commit、partial progress保持には変更を加えない。

## 成功判定

手動Drive API同期と同じく、finalized statusの`errorCount == 0 && rejectedCount == 0`を成功とする。

隔離またはファイル単位読取エラーを含みrepository自体が完走した場合は、WorkManager自体は成功終了しても検証履歴上はwarning相当の`success=false`として残す。

## 変更しないもの

- DB schema
- Drive fingerprint schema
- 同期検証履歴SharedPreferences形式
- WorkManager unique work名、周期、coalescing policy
- Google認可前のアカウント未登録時にWorkerを正常終了する既存挙動
- Compatibility Folderの履歴semantics

## 回帰保証

v1.21〜v1.26の以下を維持する。

- Drive sync single-flight / run-token ownership / immediate work coalescing
- import + fingerprint atomic commit
- page commit後のpartial progress保持
- importer compatibility signatureとtransport fingerprint reset境界
- preflight failureの旧件数reset
- owned-run failureのcommit済みprogress保持
- failure historyとfinalized direct statusの件数一致

## 実機未確認・最終総合実機試験へ繰越し

- WorkManager由来の成功履歴が手動ダッシュボード履歴と同じ件数で表示されること
- 1ページcommit後、2ページ目通信断時のWorkManager failure履歴
- Google認可失効によるWorkManager preflight failure履歴
- retryable failureからのWorkManager再試行時にattemptごとの履歴が時系列で残ること
- アプリ再起動後のWorkManager履歴永続化

これらはCI成功のみでは確認済みと扱わない。
