# v0.69 通常レシート再印字 運用台帳

## 目的

v0.68で記録する通常レシート再印字要求を、売上単位の画面だけでなく全売上横断で確認できるようにします。

## 表示データ

`SaleReceiptReprintOperationsStore` は次をJOINして読み取ります。

- `sale_receipt_reprint_requests`
- `print_jobs`
- `sales`

表示項目：

- 再印字要求日時
- 売上No.
- 元売上日時
- 売上金額
- 再印字担当者
- 用紙幅
- 監査ID
- print job ID
- 印刷状態
- 試行回数
- エラー分類
- 最終エラー

## フィルタ

- すべて
- 要対応: RETRY / FAILED
- 処理中: PENDING / RETRY / FAILED / PRINTING
- 完了: COMPLETED
- 破棄済み: DISCARDED

売上No.、job No.、担当、状態、エラー分類、最終エラーをテキスト検索できます。

## 読み取り専用

運用台帳では以下を行いません。

- 再試行
- 破棄
- 強制印刷
- 監査履歴削除
- 売上変更
- 税・支払情報変更

対応が必要なjobは既存の「統合印刷キューで確認・対応」を開き、同一の安全ロジックで処理します。

## 導線

- レジ管理メニュー → レシート再印字台帳
- SCR-647 売上指定レシート画面 → 運用台帳を開く
- 台帳詳細 → この売上のレシート画面
- 台帳詳細 → 統合印刷キューで確認・対応

## 権限

`VIEW_SALES` を必須とし、表示中もセッションを定期再確認します。

## データ保全

監査履歴はv0.68の追記専用履歴をそのまま読み取ります。運用台帳のために履歴を更新・削除しません。

## 実機確認

以下は未確認です。

- 大量履歴での表示速度
- FAILED / RETRY / PRINTING状態のリアルタイム更新
- レジ管理／SCR-647からの導線
- 台帳→統合印刷キュー→復旧後の状態反映
