# v0.79 点検・精算 整合確認監査

## 目的

v0.78で追加したSCR-520の「保存値と現在DBを照合」は、X点検・Z精算の保存snapshotと現在の営業セッション集計を比較できるようになった。一方、照合結果は画面上のダイアログだけであり、誰がいつどの履歴を確認したかは監査証跡として残っていなかった。

v0.79では、整合確認を実行した事実と判定結果を既存の追記専用 `operation_audit` に保存する。

## 記録対象

整合確認が正常に完了した場合、判定にかかわらずすべて記録する。

- `OK`
- `INFO`
- `ALERT`

イベント種別は以下とする。

- `SETTLEMENT_RECONCILIATION_OK`
- `SETTLEMENT_RECONCILIATION_INFO`
- `SETTLEMENT_RECONCILIATION_ALERT`

## 保存する情報

- 点検・精算レポートNo.
- X点検 / Z精算
- 営業日
- 営業セッションNo.
- 判定 `OK / INFO / ALERT`
- 完全snapshot / 旧形式snapshot
- 差異件数
- 差異がある場合の項目名、保存値、現在DB値
- 照合を実行したログイン担当者
- 実行日時

## fail-closed

SCR-520では従来どおり、照合直前に以下を再確認する。

1. `VIEW_SALES`
2. 対象レポートに必要なX点検またはZ精算権限
3. 選択中レポートをSQLiteから再取得
4. 営業セッションNo.一致
5. v0.78の整合比較
6. v0.79の監査追記

監査追記に失敗した場合は、照合結果を成功ダイアログとして返さない。画面上で「監査済み」に見えるのに監査履歴が存在しない状態を作らない。

監査追記が成功した場合のみ、結果ダイアログに「整合確認を監査履歴へ記録しました。」と表示する。

## データ安全

v0.79が追加する書込み先は既存の `operation_audit` の新規行だけである。

以下は変更・削除しない。

- 売上SQLiteの既存売上行
- Sales Journal
- Google Drive JSON
- sync fingerprint
- imported sales
- SENT Outbox
- quarantine履歴
- sync履歴
- 通常レシート再印字監査履歴
- 点検・精算snapshot
- 税・インボイス計算
- 印刷ジョブ

監査詳細にはOAuth token、Authorization header、content URI、生の売上JSONを保存しない。

## 実機確認

この版では実機確認を行っていない。以下は実機未確認として扱う。

- SCR-520でOK/INFO/ALERTの各照合後に成功表示されること
- 監査DB書込み失敗時に成功ダイアログを出さないこと
- 長い差異詳細でも操作に支障がないこと
- 既存の点検・精算・再印字・売上検索に影響がないこと
