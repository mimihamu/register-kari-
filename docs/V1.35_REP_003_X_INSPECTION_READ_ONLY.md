# v1.35 REP-003 X点検の読取専用化

## 仕様

詳細仕様書 v2.5 の REP-003 に合わせ、X点検は現在の営業セッションをその時点で再集計して表示するだけとする。

- X点検で営業状態を変更しない。
- X点検で `settlement_reports` へ固定スナップショットを追加しない。
- X点検で固定帳票・印刷ジョブを作成しない。
- X点検は繰り返し実行でき、毎回その時点の売上・返品取消・支払・入出金・現金理論残高を表示する。
- Z精算のみ固定スナップショットを保存し、既存のZ事前確認・責任者PIN・二重精算防止・営業終了を維持する。

## 実装

### OperationsStore

`inspectX()` は `dailySummary()` の結果を返すだけで、DB書込を行わない。

`recordSettlement()` は冒頭で `Z_SETTLEMENT` 以外を拒否する。これによりUIや将来の呼出元が誤ってX点検を永続化経路へ渡しても、`settlement_reports`、固定帳票、印刷ジョブ、営業状態更新へ到達しない。

### SecureOperationsCoordinator

`inspectX()` を追加し、現在のログインセッションと `X_INSPECTION` 権限を再検証したうえで読取専用集計を返す。印刷スケジューラやZ精算後バックアップは呼び出さない。

`recordSettlement()` 側でもZ精算だけを許可し、二重の安全境界とする。

### OperationsActivity / SettlementActivityV030

X点検の実行ボタンは `inspectX()` を呼び、固定IDを表示しない。X画面では現在セッションの保存履歴を読み込まず、「リアルタイム表示のみ・固定履歴/固定帳票/印刷ジョブなし」を明示する。

Z精算画面は従来どおり固定履歴を扱い、Z精算確定処理を継続する。

## 既存データとの互換性

旧バージョンで既に作成されたX点検の `settlement_reports` は削除しない。過去データ破壊を避けるため、従来の履歴読取・再印字コードは残す。ただしv1.35以降の通常X点検操作から新しい固定X履歴は作成しない。

## 自動試験

`V135XInspectionReadOnlyTest` で以下を固定する。

1. `OperationsStore.inspectX()` がライブ集計のみを返すこと。
2. 永続化用 `recordSettlement()` がZ精算以外を拒否すること。
3. CoordinatorのX経路に精算保存・印刷・バックアップ副作用がないこと。
4. 通常管理画面のX点検が `inspectX()` を使い、現在セッションX履歴を表示しないこと。
5. v0.30精算画面も同じ読取専用経路を使うこと。
6. Z精算の事前確認・現金実査・履歴・再印字経路を維持すること。

## 実機確認として残す項目

- 営業中にX点検を複数回実行しても営業状態がOPENのままであること。
- X点検前後で固定X履歴件数が増えないこと。
- X点検で新規の固定帳票/印刷ジョブが発生しないこと。
- X点検後も販売を継続できること。
- 売上、返品、取消、入出金の追加後にX点検を更新すると最新値へ変わること。
- Z精算は従来どおり責任者PIN・事前確認後に固定保存され、営業終了すること。
- 旧DBに過去のX点検固定履歴が残っていても、新しいX点検画面のリアルタイム表示を妨げないこと。
