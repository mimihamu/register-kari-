# v0.42 つぐレジ＋ 取込フォルダ・差分一括取込仕様

## 1. 目的

v0.39〜v0.41では、つぐレジ＋へ売上ジャーナルを取り込むたびに、Androidのファイル選択画面からJSONを複数選択する必要があった。

v0.42ではスマートフォンでの継続運用を容易にするため、Android Storage Access Frameworkのフォルダ選択を使用して取込元フォルダを登録し、以後はアプリ内の「差分取込」から一括確認できるようにする。

## 2. 対象アプリ

- つぐレジ＋
- applicationId: `jp.co.tenposinfo.register.plus`
- versionName: `0.4.0-dev.1`
- versionCode: `4`
- スマートフォン縦画面（`sensorPortrait`）

つぐレジ本体とつぐレジ CDの画面仕様は変更しない。

## 3. フォルダ登録

### 3.1 選択方式

`ActivityResultContracts.OpenDocumentTree`を使用する。

選択後、`ContentResolver.takePersistableUriPermission`で読み取り権限を永続化する。アプリ終了・端末再起動後も、DocumentsProviderが権限を維持する限り同じフォルダを使用する。

### 3.2 保存項目

SharedPreferencesへ以下を保存する。

- tree URI
- 表示名
- 最終確認日時
- 検出JSON件数
- 変更件数
- 未変更件数
- JSON以外の対象外件数
- 読込エラー件数
- 全件再確認であったか

### 3.3 登録解除

登録解除時は以下を行う。

- 永続読み取り権限の解放を試行
- 登録情報の削除
- 対象tree URIの差分判定履歴を削除

権限解放に失敗しても、アプリ内の登録解除処理は継続する。

## 4. フォルダ走査

### 4.1 DocumentsProvider

`DocumentsContract.buildChildDocumentsUriUsingTree`を用いて子要素を取得する。

フォルダ内のサブフォルダも再帰的に確認する。

### 4.2 安全上限

- 最大階層: 12階層
- 最大JSON数: 5,000件
- 1JSON当たり: 20MiB

上限を超えた場合は処理を中止し、画面にエラーを表示する。

### 4.3 JSON判定

以下のいずれかを満たすファイルをJSON候補とする。

- ファイル名の末尾が `.json`（大文字小文字を区別しない）
- MIME typeが `application/json`
- MIME typeが `text/json`

PDF、画像、ZIPなどは取込対象外として件数のみ記録する。

## 5. 差分判定

更新日時やファイルサイズだけでは、Google DriveなどのDocumentsProviderによって値が欠落・不正確になる可能性がある。

そのためv0.42では、読み取ったファイル内容のSHA-256を計算し、内容SHA-256で差分を判定する。

```text
同一source URI かつ 内容SHA-256一致 → 未変更
同一source URI で 内容SHA-256不一致 → 変更
未登録source URI → 新規候補
```

同一内容のファイルは通常の「差分取込」では売上ジャーナル取込処理へ渡さない。

## 6. 全件再確認

「全件再確認」では、保存済み内容SHA-256と一致していても全JSONを取込処理へ渡す。

売上ジャーナル側では`duplicateImportKey`が主キーであるため、既存データは重複としてスキップされ、上書きされない。

用途:

- 取込契約やアプリ更新後の再確認
- 過去の隔離データの再検証
- 差分履歴への疑義がある場合

## 7. SQLite

Management DBをversion 3へ更新する。

追加テーブル:

```sql
CREATE TABLE folder_import_files (
    source_uri TEXT PRIMARY KEY NOT NULL,
    tree_uri TEXT NOT NULL,
    display_name TEXT NOT NULL,
    content_sha256 TEXT NOT NULL,
    last_processed_at INTEGER NOT NULL
);
```

追加索引:

```sql
CREATE INDEX idx_folder_import_files_tree
ON folder_import_files(tree_uri, last_processed_at DESC);
```

v0.40/v0.41のDB version 2からは既存の売上ジャーナル、取込履歴、隔離データを保持したままテーブルを追加する。

## 8. 画面

スマホ縦画面上部へコンパクトな取込フォルダバーを追加する。

未登録時:

- 「取込フォルダ未登録」
- 「登録」ボタン

登録時:

- フォルダ表示名
- 最終確認状態
- 「差分取込」
- 「設定」

設定展開時:

- 最終確認日時
- JSON件数
- 変更件数
- 未変更件数
- 対象外件数
- 読込エラー件数
- 「全件再確認」
- 「変更」
- 「解除」

従来の「JSON取込」は残し、単発ファイルの手動取込にも対応する。

## 9. エラー処理

以下を画面へ表示する。

- 永続権限を取得できない
- 登録URIを開けない
- フォルダ一覧を取得できない
- 階層上限超過
- JSON数上限超過
- ファイル読込エラー
- 20MiB超過

個別JSONの読込エラーは既存の隔離処理へ渡す。フォルダ全体を開けない場合は取込処理を開始しない。

## 10. 自動実行について

v0.42ではバックグラウンド定期取込は実装しない。

理由:

- DocumentsProviderのバックグラウンドアクセス可否を実機確認する必要がある
- Google Driveのオフライン状態・認証状態による挙動が未確認
- Android Dozeやメーカー独自省電力の影響が未確認

まず手動の「差分取込」で安全性を確認し、その後のバージョンで定期取込を検討する。

## 11. 実機確認事項

- Google Driveアプリ内フォルダの登録
- USBストレージ内フォルダの登録
- 端末ローカルフォルダの登録
- アプリ再起動後の永続権限
- 端末再起動後の永続権限
- サブフォルダ再帰走査
- 変更なし時のスキップ
- 内容変更時の再取込
- ファイル名変更時の扱い
- ファイル移動時の扱い
- 全件再確認時の重複件数
- 20MiB境界
- 5,000件付近の性能とメモリ
- Google Drive未同期・通信断時の表示
- v0.41からのDB version 3上書き移行

これらはコード・CI上の確認であり、実機確認済みとは扱わない。
