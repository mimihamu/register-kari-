# V1.38 APP-CRASH-001 — 障害調査用レポート

## 正式仕様 v2.5 との対応

`ERR-002 クラッシュログ` の MUST 要件を対象とする。

- 未処理例外を保存する。
- 発生画面、操作、アプリ版、端末情報を記録する。
- 個人情報を保存しない。
- アプリ再起動後にレポートを出力できる。

Issue #137 の #38 `APP-CRASH-001` は、つぐレジ / つぐレジ＋ / つぐレジ CD の3アプリが対象。

## 実装

3アプリそれぞれに `CrashReportRuntimeV138` を配置し、アプリ起動時に既定の `UncaughtExceptionHandler` をラップする。障害レポートをアプリprivate領域へ `fd.sync()` 後、`ATOMIC_MOVE + REPLACE_EXISTING` で確定する。書込み後は既存の既定例外ハンドラへ処理を引き継ぐ。

Activity lifecycle から、現在画面と `SCREEN_RESUMED:<Activity>` 形式の安全な操作コードだけを追跡する。障害ログが残っている場合、再起動後の画面へ「障害レポート」ボタンを表示し、Androidの共有UIからJSONを出力できる。

### 保存する情報

- 発生時刻
- package name
- app version name / code
- 画面クラス
- 操作コード
- main threadか否か
- process uptime
- 端末 manufacturer / model / SDK / Android release / ABI
- 例外クラス名
- cause chain
- stack frame の class / method / file / line

### 保存しない情報

- 例外message
- TextField等の入力内容
- 氏名、電話番号、メールアドレス
- Google等のアカウント識別子
- Android ID / serial
- 取引・売上・商品・決済内容
- 認証token / API key / folder ID

例外messageを採用しないのは、messageへ商品名、入力値、URI、アカウント情報等が混入する可能性を排除するため。

## 起動点

- つぐレジ: `RegisterApplication.onCreate()` の通常scheduler起動前
- つぐレジ＋: `PlusApplicationV138`
- つぐレジ CD: `CustomerDisplayApplicationV138`

## 自動テスト

各moduleの `V138CrashReportContractTest` で以下を固定する。

- uncaught handlerの導入
- 画面/操作/app版/端末情報
- private atomic persistence
- 再起動後共有導線
- exception message非保存
- Android ID / serial非保存
- Application起動点

通常の累積CIで3moduleのunit test、Kotlin compile、3 APK build、release identity/integrity gateを実行する。

## 実機受入

以下は `実機未確認`。

1. つぐレジで意図的に未処理例外を発生させ、プロセス終了後に再起動する。
2. 「障害レポート」導線が表示され、共有先へJSONを出力できることを確認する。
3. JSONに画面、操作、アプリ版、端末情報、例外位置が存在することを確認する。
4. 個人情報、入力値、売上・決済内容、認証情報が含まれないことを確認する。
5. 同じ確認をつぐレジ＋ / つぐレジ CDでも行う。
