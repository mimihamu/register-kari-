# v0.55 同期運用ダッシュボード＋個別再試行

## 目的

v0.54のGoogleかんたん接続を、初期設定だけでなく日常運用まで迷わず使える構成へ拡張する。

利用者は通常、同期方式や内部WorkManager名を意識せず、現在の状態、最終同期、同期件数、隔離・失敗の有無だけを確認する。異常時だけ安全な再試行または保守・復旧へ進む。

## つぐレジ＋

従来の「Google Drive売上同期検証・復旧」を日常運用向けの「同期運用ダッシュボード」へ拡張する。

表示項目:

- 現在の同期経路: Drive API / 互換フォルダ / 未確定
- 健康状態: 正常 / 注意 / エラー / 実行中 / 停止疑い / 未実行
- 最終同期日時と経過時間
- 最新取込営業日
- 取込済み累計、隔離履歴累計
- 直近Drive APIの確認、取得、新規、重複、隔離、エラー件数
- Drive API自動同期設定
- 1時間ごとの定期Work、起動時Work、手動Workの状態
- 互換フォルダ起動時取込状態
- 直近の隔離データ
- 直近20件までの同期検証履歴

## 安全な再試行

### 同期全体

Drive APIまたは互換フォルダの現在方式で通常の差分同期を再実行する。

- `forceReimport=true`は日常画面から使用しない
- 同期指紋を削除しない
- 取込済み売上を削除しない
- Drive上JSONを削除しない

### 隔離1件

隔離レコードが元ファイルを再取得できる場合だけ「この1件を再試行」を有効にする。

対象:

- `gdrive://` のDrive API元ファイル
- `content://` の互換フォルダ元ファイル

再試行では元ファイルを再取得し、既存の `SalesJournalImportRepository` へ1件だけ渡す。duplicateImportKeyによる重複防止をそのまま使用する。

**元の隔離履歴は削除しない。** 再試行が成功しても監査・原因確認用として過去の隔離レコードを維持する。再試行後に同じ内容が不正な場合は新しい隔離履歴が追加される。

元ファイルを再取得できない隔離データはボタンを無効化する。

## スケジューラ可視化

WorkManagerのunique workを参照し、次を表示する。

- `tsuguregi-plus-drive-api-sync-periodic`
- `tsuguregi-plus-drive-api-sync-startup`
- `tsuguregi-plus-drive-api-sync-manual`

表示のみで、通常のスケジュール設定・修復は既存のScheduler APIを通して行う。

## つぐレジ

v0.38で実装済みのOutbox送信運用ダッシュボードと1件個別再試行を、Google Drive・同期設定から日常運用機能として明示する。

表示・操作:

- PENDING / PROCESSING / RETRY / STAGED / SENT / FAILED件数
- 最終送信成功
- 直近エラー
- Outbox一覧
- FAILED 1件ごとの個別再試行
- JSONプレビュー
- 送信監査履歴
- 互換フォルダ送信先テスト

個別再試行は既存ルールを維持する。

- ローカルJSONあり: STAGEDへ戻す
- ローカルJSONなし: PENDINGへ戻す
- FAILED以外は個別再試行不可
- 売上、ジャーナル、印刷、精算を巻き戻さない

## データ保護

以下は自動削除しない。

- SQLiteの取込済み売上
- POSのsales_journal / sync_outbox原本
- Drive上の売上JSON
- Drive同期fingerprint
- 互換フォルダのfingerprint
- 隔離履歴
- 同期検証履歴（利用者が履歴消去を明示した場合を除く）

OAuthアクセストークン・更新トークンは引き続き永続保存しない。

## 実機確認事項

- WorkManagerの表示状態と端末上の実際の定期実行の一致
- Drive API失敗後の再試行
- `gdrive://`隔離データの1件再試行
- `content://`隔離データの1件再試行
- 再試行成功時のduplicateImportKey重複防止
- 再試行後も元の隔離履歴が残ること
- v0.54からv0.55への上書き更新
- 実Google Drive / Workspace管理アカウント
- 本番署名・本番OAuthクライアント
