# v0.68 通常レシート再印字 監査・冪等基盤

## 目的

通常レシート再印字について、単なる印刷回数だけでなく「誰が・いつ・どの売上を・どの印刷jobとして再印字要求したか」を追跡できるようにします。

## 追記専用履歴

新規テーブル `sale_receipt_reprint_requests` に以下を保存します。

- request UUID
- 売上No.
- print job ID
- 担当者名
- 用紙幅（58 / 80mm）
- 要求日時

request UUIDとprint job IDはUNIQUEです。履歴を更新・削除するAPIは提供しません。

## 原子性

再印字要求確定時は、以下を同一SQLiteトランザクションで行います。

1. request UUIDの既存確認
2. 対象売上の存在確認
3. `print_jobs`へPENDING job追加
4. `sale_receipt_reprint_requests`へ監査行追加
5. commit

監査行だけ、またはprint jobだけが追加される中途半端な状態を避けます。

## 冪等性

同じrequest UUIDで再実行した場合は既存要求／既存jobを返し、新しいprint jobを二重作成しません。

UUIDが別売上に再利用された場合はエラーにします。

## 画面

SCR-647「売上指定 レシート確認・再印字」に、同一売上の再印字要求履歴を表示します。

表示項目：

- 要求日時
- 担当者
- 用紙幅
- job No.
- 印刷状態
- 試行回数
- 最終エラー

印刷状態は画面表示中に定期更新します。

## 導線統一

会計完了画面と売上詳細画面の通常レシート操作も、監査付きの独立SCR-647へ統一します。これにより日常UIから監査を経由しない通常再印字経路を残しません。

## 非破壊条件

- 売上金額を変更しない
- 税スナップショットを変更しない
- 支払情報を変更しない
- 既存印刷履歴を削除しない
- FAILEDを自動再送しない
- 復旧は統合印刷キューを利用する
