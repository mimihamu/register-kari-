# v0.60 領収書運用台帳＋印刷状態

## 目的

v0.58で追加した領収書の追記専用安全基盤と、v0.59で追加した発行・再発行操作UIを、日常の印刷障害対応まで追跡できる運用状態へ仕上げる。

新しい印刷再試行ロジックは作らず、既存の統合印刷キューを唯一の印刷障害対応画面として継続利用する。

## 運用台帳

領収書発行画面の「運用台帳・印刷状態」から開く。

表示対象：

- 領収書No.
- 元売上No.
- 金額
- 宛名
- 但し書き
- 発行担当
- 発行日時
- 一括発行時の連番
- 印刷ジョブ件数
- 再発行回数
- 最新印刷状態

## 印刷イベント

`receipt_voucher_issuances`を起点に、既存の`document_print_jobs`と`receipt_voucher_reprints`を読み取り専用で関連付ける。

各イベントには以下を表示する。

- 初回発行／再発行
- 統合印刷Job ID
- 用紙幅
- PENDING / PRINTING / COMPLETED / RETRY / FAILED / DISCARDED
- 試行回数
- 作成日時
- 再発行イベントID
- 再発行担当者
- 失敗分類
- 最終エラー

## フィルター

- すべて
- 要対応
- 未完了
- 完了
- 再発行あり

検索対象：

- 領収書No.
- 元売上No.
- 宛名
- 但し書き
- 発行担当
- 印刷Job ID
- 状態
- 失敗分類
- 最終エラー
- 再発行担当者

## 要対応

FAILEDまたはRETRYが存在する領収書を要対応として表示する。

領収書履歴が存在するのに対応する印刷ジョブが存在しない場合も要確認対象とする。

PENDING / PRINTING / RETRY / FAILEDが存在する領収書は未完了として表示する。

## 印刷障害対応

領収書運用台帳から直接、再試行・破棄・強制印刷を実装しない。

「統合印刷キューで確認・対応」から既存の統合印刷キューを開き、以下の既存安全制御をそのまま使用する。

- 安全な再試行
- プリンター状態確認
- 送信結果不明時の二重印刷防止
- 責任者承認付き強制印刷
- 破棄理由と監査履歴

これにより、印刷障害対応ロジックが領収書画面と統合印刷キューへ二重実装されることを防ぐ。

## データ保護

運用台帳は読み取り専用とする。

以下を削除・上書きしない。

- SQLite売上
- Sales Journal
- Drive上JSON
- 同期fingerprint
- SENT済みOutbox
- 領収書発行履歴
- 領収書再発行履歴
- document_print_jobsの完了履歴
- 統合印刷キュー監査履歴

## 権限

領収書運用台帳は`VIEW_SALES`権限があるオペレーターのみ利用可能。

## 実機確認が必要な項目

CIでは以下を確認済みとは扱わない。

- 実タブレットでの台帳レイアウト
- 数百件の領収書履歴を持つ実データでの操作性
- 実プリンター障害時のFAILED/RETRY表示遷移
- 紙切れ・通信断・送信結果不明から統合印刷キューへの復旧導線
- v0.59→v0.60上書き更新
