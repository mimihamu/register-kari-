# v0.39 つぐレジ＋ 売上ジャーナルJSON取込基盤

## 1. 目的

つぐレジが外部フォルダへ出力する売上ジャーナルJSONを、管理アプリ「つぐレジ＋」で安全に取り込み、重複を防止しながら履歴として保持する初期基盤を構築する。

この版では多店舗クラウドサービスやGoogle Drive REST APIを実装せず、Android Storage Access Framework（SAF）でユーザーが選択したJSONファイルを端末内DBへ取り込む。

## 2. アプリ構成

- モジュール: `management-app`
- アプリ名: `つぐレジ＋`
- applicationId: `jp.co.tenposinfo.register.plus`
- minSdk: 26
- targetSdk / compileSdk: 36
- 画面方向: 横画面
- DB: `SQLiteOpenHelper`
- DB名: `tsuguregi_plus.db`

## 3. 取込対象契約

外側のJSON envelopeは以下に固定する。

- schema: `jp.co.tenposinfo.tsuguregi.sales-journal`
- schemaVersion: `1`
- minimumReaderVersion: `1`以下
- duplicateKeyVersion: `1`
- duplicateImportKey: `sj1-` + 64文字の小文字16進SHA-256

`duplicateImportKey`は形式だけでなく、つぐレジ側と同じ次の生成式で再計算して一致確認する。

```text
sj1- + SHA-256("1|storeId|terminalId|businessDate|eventType|eventId")
```

必須項目:

- eventId
- duplicateImportKey
- eventType
- storeId
- terminalId
- businessDate
- aggregateId
- occurredAt
- payloadSchema
- payload

対応eventType:

- SALE
- REVERSAL
- INSPECTION
- Z_SETTLEMENT
- CASH_MOVEMENT
- BUSINESS_OPEN
- BUSINESS_STATE
- MENU_REVISION

対応payloadSchema:

- register.sale.v2
- register.reversal.v2
- register.settlement.v1
- register.menu-revision.v1
- register.generic.v1

`payload.schema`が存在する場合は、外側の`payloadSchema`と一致しなければならない。

## 4. 取込手順

1. 「JSONファイルを選択」を押す。
2. Androidのファイル選択画面で1件以上のJSONを選ぶ。
3. 1ファイル20MiBを上限として読み込む。
4. JSON構文と固定契約を検証する。
5. 識別項目から`duplicateImportKey`を再計算して一致確認する。
6. `duplicateImportKey`を主キーとしてDBへ登録する。
7. 既に同じキーが存在する場合は重複取込としてスキップする。
8. 不正なJSONは取込済データへ混ぜず、隔離テーブルへ記録する。
9. 新規・重複・隔離件数を取込履歴へ保存する。

## 5. 重複取込

`imported_journal.duplicate_import_key`をPRIMARY KEYとし、SQLiteの`CONFLICT_IGNORE`で二重登録を防ぐ。

同一JSONを繰り返し選択しても、既存レコードを更新・上書きせず、取込履歴の重複件数だけを増やす。

生成式と一致しない重複キーは通常の重複として扱わず、不正データとして隔離する。

## 6. 不正データ隔離

以下を隔離対象とする。

- JSONとして解析できない
- 20MiB超過
- ファイル読込失敗
- 未対応schema
- 未対応schemaVersion / readerVersion / duplicateKeyVersion
- 必須項目不足
- duplicateImportKey形式不正
- duplicateImportKey再計算値との不一致
- 未対応eventType
- 未対応payloadSchema
- payloadSchemaとpayload.schemaの不一致
- businessDateやoccurredAtなどの値不正

隔離レコードには、ファイル名、URI、理由コード、説明、先頭4,096文字、元JSONのSHA-256を記録する。元JSON全文を隔離テーブルへ重複保存しない。

## 7. 管理画面

初期画面で次を確認できる。

- 取込済件数
- 隔離件数
- 店舗数
- 最終取込時刻
- eventType別件数
- 直前取込の対象・新規・重複・隔離件数
- 最近の取込データ
- 最近の隔離データ
- 取込履歴

## 8. データ保持

### imported_journal

固定envelope、payload、元JSON、取込元、取込日時を保持する。

### import_runs

1回の複数ファイル選択を1取込として、対象件数、新規件数、重複件数、隔離件数、開始・完了時刻を保持する。

### import_rejections

不正データの理由と調査用情報を保持する。
