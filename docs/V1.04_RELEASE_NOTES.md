## 主な変更

### バックアップfallbackのWAL-safe化

`VACUUM INTO` が利用できない/失敗した場合のraw DB fallbackを強化した。

- `PRAGMA wal_checkpoint(TRUNCATE)` の結果を確認
- busyまたはcheckpoint未完了ならcopyしない
- EXCLUSIVE transaction取得後にWALが0 byteのままか再確認
- checkpointとlockの間にwriteが入った場合は再試行
- 最大3回で安全状態を作れなければbackupを失敗させる
- 安全性不明のsnapshotを成功扱いしない

### ファイル置換のクラッシュ安全性強化

`DataProtectionManager.atomicReplace()` の「targetを先にdeleteしてからrename/copy」を廃止した。

- `CrashSafeFileReplaceV104` を追加
- targetと同じfilesystem/directoryへstaging
- stagingをsync
- `Files.move(..., ATOMIC_MOVE, REPLACE_EXISTING)` で確定
- atomic move不可、またはFileSystemProviderが既存targetのatomic replacementを提供しない場合はunsafe fallbackを行わず失敗
- 置換失敗時に既存targetを保持
- target確定後の元source削除はbest-effort cleanupとして扱い、掃除失敗を置換失敗へ戻さない
- 1時間未満のatomic-replace stagingは他処理が利用中の可能性があるため自動削除しない

この変更は既存のbackup/restore/rollback/metadata確定経路から共通利用される。

## 自動テスト

`V104DataProtectionCrashSafetyTest` を追加。

- WAL checkpoint complete判定
- WAL quiescent判定
- checkpoint → lock → WAL再確認 → raw copy順序
- same-directory atomic replacement
- cross-directory staging + atomic replacement
- target pre-delete廃止
- target commit後のsource cleanupが非致命であること
- release identity / docs gate

v1.04への版番号更新に伴い、`V103CustomerDisplayConnectionLivenessTest` のrelease identity確認も「現行Gradleをv1.03へ固定」から「v1.03 release notesの履歴版番号を確認」へ修正した。CD liveness本体の機能テストは変更していない。

## 実機確認

実端末でのbackup/restore/process kill/端末再起動、SQLite version差、並行write中snapshot、実端末FileSystemProviderでの既存target atomic replacementは未確認。

これらは**最終総合実機試験へ繰越**する。実機で確認していない項目を確認済みとは扱わない。
