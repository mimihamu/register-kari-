# v1.35 COR-001 置数訂正

## 対象仕様

詳細仕様書 v2.5 の COR-001「置数訂正」。

商品登録前の置数が残っている場合、`C` または `訂正` は登録済み明細を変更せず、現在の置数だけを消去する。

## v1.35 で確認した既存状態

販売画面のテンキー `C` は、既に `numericInput = ""` として置数だけを消去していた。

一方、`訂正` ボタンは置数の有無を判定せず `onRemove` を直接実行していたため、置数入力中でも選択行または直前行を削除できる状態だった。

## v1.35 の修正

`NumericCorrectionPolicyV135` を追加し、販売画面の `訂正` を次の優先順位にした。

1. 置数が残っている場合は置数だけを消去する。
2. 置数が空の場合のみ、従来の明細訂正処理へ進む。

COR-001 の経路では `cart`、`sales`、`sale_items` などの登録済み／確定済みデータを変更しない。

## 自動検証

`V135NumericCorrectionTest` で以下を固定する。

- 数字が入力済みなら置数訂正を優先すること。
- 空文字・空白のみなら明細訂正へフォールバックできること。
- `SalesScreen` が `NumericCorrectionPolicyV135` を経由すること。
- `訂正` ボタンから `onRemove` を直接呼ぶ旧配線へ戻らないこと。

## 実機確認として残す項目

コード・自動テストとは別に、対象タブレット上で以下を確認する。

- 置数入力後に `C` を押すと置数のみ消えること。
- 置数入力後に `訂正` を押すと置数のみ消え、明細が残ること。
- 置数が空の状態で `訂正` を押すと従来の明細訂正へ進むこと。
- 連続タップでも意図しない明細削除が発生しないこと。

実機未確認の間は COR-001 を「実機確認済み」とは扱わない。
