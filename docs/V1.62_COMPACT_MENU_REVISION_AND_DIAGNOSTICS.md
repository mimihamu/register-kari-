# v1.62 管理補助画面の統一と狭い端末の操作領域

## 調査で見つかった問題

- `MenuRevisionEditorActivity.kt` は改定一覧 **285dp**、商品編集 **390dp**、残りを比較一覧に配分する3列固定。800×480の小型POSで比較一覧の操作面積が実質消失する。
- 改定画面ヘッダーが独自の `MrHeader` で、共通の可変高さヘッダーと異なる。SCR番号・重複したアプリ名・補助ラベルで幅が狭い。
- `PerformanceDiagnosticsActivityV136.kt` のヘッダーが固定62dpの独自Rowで、戻るが本文下部のみ。短い端末では値と戻る/再計測ボタンが下にはみ出す。
- メニュー税区分の候補が0件の場合、循環ボタンの空リスト参照でクラッシュする可能性。

## 修正

1. 改定編集画面で `RegisterResponsiveLayoutPolicy` による分類を利用。
   - **COMPACT / MEDIUM**：改定一覧と差分比較の2ペイン。差分項目を押すと**編集画面**へ切替。上部「一覧・比較」「商品編集」で戻れる。
   - **EXPANDED**：従来の3ペイン。変更操作の意味・保存先・税選択・営業日判定の業務ロジックは維持。
2. 改定画面の `MrHeader` を除去し、`RegisterTopBarV141(title="メニュー改定", onBack=...)` へ統一。不要な `SCR-274` を表示しない。
3. 性能診断画面も共通ヘッダー。上部から「戻る」「再計測」に常時アクセスでき、メモリ・ストレージ値は縦スクロール可能。診断値と「取得不可」の説明は維持。
4. 空の税区分候補では切替ボタンを無効にし、空リストを添字アクセスしない。
