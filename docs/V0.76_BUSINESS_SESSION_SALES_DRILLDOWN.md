# v0.76 営業セッション売上明細ドリルダウン

## 目的

SCR-510「営業セッション売上簡易確認」には営業日と営業セッションNo.が表示されるが、同じ集計対象の売上明細へ直接進む導線がない。

つぐレジはZ精算後、同じ営業日で新しい営業セッションを開始できる。そのため営業日だけで明細検索すると、別セッションの売上が混在する可能性がある。

v0.76ではSCR-510から営業日＋business_session_idを固定したSCR-620へ遷移し、集計と同じセッションだけを表示する。

## DB検索

`SalesHistoryCriteria`へ `businessSessionId` を追加する。

固定contextでは次を同時にバインドする。

- `business_date >= ?`
- `business_date <= ?`
- `business_session_id = ?`

営業日From/Toは同じ日を指定する。

`business_session_id`列が旧DBに存在しない場合は別情報から推測せず、検索結果をfail-closedとする。検索のためのALTER TABLE、backfill、UPDATEは行わない。

## Navigation

`BusinessDateSalesLookupNavigation` が次をIntentへ格納する。

- business date
- business session ID

受信時はbusiness dateを`LocalDate.parse`で正規化し、session ID <= 0は拒否する。不正contextの場合は通常の営業日検索画面として開き、誤った固定条件を作らない。

## SCR-620 固定context

SCR-510から開いた場合:

- 営業日From/Toを同一営業日で初期化
- business_session_idを固定
- 日付・検索語・金額条件の変更を無効化
- 売上No.直接表示を無効化
- 条件クリアを無効化
- 固定営業日・セッションNo.を画面へ明示

「固定解除・同日全売上を表示」を押した場合だけbusiness_session_id固定を解除する。解除後も営業日は同じ日を維持し、その営業日全体を表示してから通常検索へ移行できる。

## SCR-510

`businessSessionId > 0` の場合に「この営業セッションの売上明細」ボタンを表示する。

SCR-510自体はVIEW_SALES権限で開かれており、SCR-620側でも5秒周期を含めVIEW_SALESを再確認する。遷移元だけの権限に依存しない。

## データ安全性

本機能は売上参照のみ。

- salesを更新・削除しない
- business_date / business_session_idを推測・backfillしない
- 税スナップショットを変更しない
- 支払情報を変更しない
- 返品・取消、通常レシート、領収書の既存安全導線を維持

## 実機確認が必要な項目

- SCR-510からSCR-620への遷移
- 同一営業日に複数セッションがある実データで混在しないこと
- 固定中の入力欄・売上No.直接表示の無効化
- 固定解除後に同日全売上へ切り替わること
- VIEW_SALES失効時の画面遷移
- 0件セッションの表示
- 200件超セッションでのページング
