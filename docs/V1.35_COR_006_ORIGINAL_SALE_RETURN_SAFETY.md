# v1.35 COR-006 元取引あり返品 安全性

## 対象

詳細仕様書 v2.5 の COR-006「元取引を指定した返品」を、全量返品・部分返品・複数回返品まで含めて初版運用できる状態に固定する。

## 元取引と返品数量

- 元売上を選択して返品する。
- 全量返品と部分返品を扱う。
- `reversal_items` の既返却数量を元売上明細ごとに集計し、`remainingQuantity` を再計算する。
- 返品確定時は画面表示時の残数を信用せず、同じDBトランザクション内で `loadReturnableLines(this, originalSaleId)` を再実行する。
- 残数を超える返品は `ReturnableSaleLine.toReturnItem()` / `PartialReturnPolicy.select()` で拒否する。
- 同一売上の同時実行は `SecureOperationsCoordinator` の `reversal:<saleId>` 実行ゲートで直列化する。
- 同じ requestId の再実行は操作キーで重複登録を拒否する。

## 売上時税スナップショット

返品計算は現在の商品マスター・税率マスターではなく、元売上の `line_tax_snapshots` (`scope='SALE'`) を使用する。

保持する情報:

- 税キー / 税表示名
- 税率
- 内税 / 外税
- 課税 / 非課税
- 軽減税率フラグ
- レシート税シンボル

元売上後に税マスターを変更しても、返品は売上時の税条件で計算する。

## 値引の複数回返品

明細値引は部分返品時に数量比で配賦し、最終残数を返品するときは未返金の値引残額を全て返す。複数回に分けても返金値引合計が元値引額と一致する。

## 複数支払の複数回返品

### 修正前の問題

従来は各返品ごとに元の `sale_payments` 全額を基準として返金方法を比例配賦していた。このため、現金＋カードなどの複数支払で部分返品を何度も行うと、丸め端数の積み重ねにより特定支払方法の累積返金額が元支払額を超える余地があった。

### v1.35 修正

返品確定トランザクション内で、対象元売上に紐づく過去の `reversal_payments` を支払方法別に集計する。

各支払方法の返金可能残高を次で求める。

`返金可能残高 = 元支払額 - 過去返金額`

新しい返金は、この残高だけを母数として比例配賦する。

- 同一支払方法の元支払行が複数ある場合は合算する。
- 支払方法ごとの配賦額は返金可能残高を超えない。
- 今回返金額が全支払方法の未返金残高合計を超える場合は確定しない。
- 比例計算は `BigInteger` を使い、Long乗算オーバーフローを避ける。
- 端数は最大剰余法で安定して配賦し、今回返金額との1円単位の一致を保証する。

## COR-008との境界

元売上に利用可能な `sale_payments` が無い場合、元の支払方法別上限を復元できない。この場合はCOR-008の責任者による手動返金方法選択へフォールバックする。推定した支払上限を捏造しない。

## 記録

返品は元売上を更新・削除せず追記する。

- `reversal_transactions`
- `reversal_items`
- `reversal_payments`
- `line_tax_snapshots` (`scope='REVERSAL'`)
- `operation_audit`
- `document_print_jobs`

訂正は実行時点のOPEN営業セッション・営業日へ計上し、元売上との参照を保持する。

## 自動検証

- `V019PartialReturnPolicyTest`
  - 値引残額
  - 複数回値引返品
  - 支払別上限
  - 元支払行集約
  - Longオーバーフロー回避
  - 売上時税スナップショット
- `V135OriginalSaleReturnSafetyTest`
  - トランザクション内の残数再読込
  - 過去返金支払の集計
  - 残支払枠を配賦へ渡すこと
  - 権限 / 責任者PIN / 同一売上実行ゲート
  - 追記型保存

## 実機確認待ち

1. 元売上選択からの全量返品
2. 一部返品後に同じ売上を再度開いた残数表示
3. 複数回の部分返品を残数ゼロまで実行
4. 残数超過を拒否
5. 同じ売上の確定連打・競合操作で二重返品されない
6. 現金＋カード等の複数支払を複数回返品しても、各支払方法の累積返金が元支払額を超えない
7. 税マスター変更後も売上時税率・内外税・税シンボルで返品される
8. 複数回返品の値引返金合計が元値引額と一致
9. 訂正営業日が実行時の営業日になる
10. 返品票、監査ログ、元売上↔反対取引参照
11. 一部返品状態から全量返品済状態への遷移
12. COR-008対象データで責任者選択した返金方法と実決済端末側返金が一致すること

実機確認が完了するまではCOR-006を初版チェックリスト上の完了扱いにしない。
