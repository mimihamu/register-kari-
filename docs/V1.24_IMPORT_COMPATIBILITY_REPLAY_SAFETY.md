# v1.24 取込互換性変更時の自動再評価

## 背景

つぐレジ＋はDrive API方式と互換フォルダ方式の両方で、処理済みファイルのfingerprintを保存し、内容が変わっていないファイルを差分同期時にskipする。

この方式では、ある時点で次のような理由により隔離されたJSONも「処理済み」としてfingerprintが残る。

- `UNSUPPORTED_VERSION`
- `UNSUPPORTED_EVENT_TYPE`
- `UNSUPPORTED_PAYLOAD_SCHEMA`

これらはJSON自体が壊れているとは限らず、将来のつぐレジ＋更新でreader/parserが対応すれば正常に取り込める可能性がある。

しかしremote versionや内容SHAが変化しなければ、従来の自動差分同期ではそのファイルを再評価しないため、手動の「隔離データ個別再試行」または全件再取込に依存していた。

## v1.24の対策

### importer signature

`SalesJournalProcessorSignatureV124` を追加し、現在の取込互換性をSHA-256 signatureとして表す。

signatureには以下を含める。

- parser rule version
- sales-journal schema名
- 対応schemaVersion
- readerVersion
- duplicateKeyVersion
- 対応eventType集合
- 対応payloadSchema集合

eventType / payloadSchemaはsortしてからsignatureへ含めるため、集合の定義順だけではsignatureは変わらない。

parser内部の検証規則だけを変更する場合は `RULE_VERSION` を上げる。

### fingerprint無効化

`ManagementDatabase.onOpen()` で保存済みsignatureと現在signatureを比較する。

一致しない、または初回でsignatureがない場合のみ、1 transactionで次のtransport fingerprintを削除する。

- `drive_sync_files`
- `folder_import_files`

次の業務・監査データは削除しない。

- `imported_journal`
- `import_rejections`
- `import_runs`

そのため既存売上を消さず、次回のDrive API同期／互換フォルダ同期だけが全件を再評価する。既に取り込まれている同一イベントは既存のduplicate replay guardで重複登録されない。

### crash safety

fingerprint削除transactionをcommitしてからprocessor signatureを同期保存する。

- fingerprint削除前に停止: 次回再実行。
- fingerprint削除commit後、signature保存前に停止: 次回もう一度空のfingerprintを削除して再実行。
- signature保存後に停止: fingerprintは既に空なので次回同期で全件再評価。

売上本体を削除する境界はない。

## version

- つぐレジ: 154 / `1.24.0-dev.1`
- つぐレジ＋: 23 / `0.23.0-dev.1`
- つぐレジ CD: 7 / `0.14.0-dev.1`

DB schema変更はなく、Management DB version 6を維持する。

## テスト

`V124ImportCompatibilityReplaySafetyTest` で以下を確認する。

- signature欠落・変更時だけreplayが必要になること。
- signatureがschema/version/event/payload互換面を含むこと。
- 無効化対象がtransport fingerprint 2テーブルだけであること。
- fingerprint transaction完了後にsignatureを保存する順序であること。
- unsupported系の隔離監査と既存の個別再試行経路を維持すること。

## 実機確認へ繰り越す項目

- v1.23以前からv1.24へ更新した初回起動後、次回Drive同期が全件再評価になること。
- 互換フォルダ方式でも初回だけ全件再評価になること。
- 数千件規模での初回再評価時間・Drive API負荷。
- importer signature変更を模擬した更新後、remote未変更の過去隔離JSONが自動再評価されること。
- fingerprint reset直後の強制終了・再起動。

これらは最終総合実機試験まで確認済みとは扱わない。
