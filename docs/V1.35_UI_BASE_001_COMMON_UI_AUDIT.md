# v1.35 UI-BASE-001 基本画面・共通UI 仕様監査

## Issue #137 対応

Issue #137 #1 `UI-BASE-001 基本画面・共通UI` を、詳細仕様書 v2.5 の共通UI受入条件と現行実装へ突合した。

この監査では `MODAL-001` を別項目として扱い、モーダル共通仕様は `UI-BASE-001` の完了条件へ混在させない。

## v2.5 受入条件

主に次を対象とする。

- `UI-AT-01`: 1280×800で販売 → 会計 → 次取引まで主要操作部品が見切れないこと。
- `UI-AT-01`: 主要フローで不要な横スクロールを発生させないこと。
- `UI-AT-06`: 文字サイズ1.3倍でも文字・主要操作が欠けないこと。
- `UI-AT-06`: 状態を色だけで表現しないこと。

## 現行レスポンシブ実装の監査

### `rememberRegisterResponsiveMetrics()`

`ResponsiveLayoutV029.kt` の `rememberRegisterResponsiveMetrics()` は、`screenWidthDp` / `screenHeightDp` だけでなく `configuration.fontScale` も `remember` キーへ含め、`RegisterResponsiveLayoutPolicy.metrics()` へ渡している。

`RegisterResponsiveLayoutPolicy.classify()` は `fontScale >= 1.30f` を `COMPACT` と判定する。このため 1280×800・文字1.3倍では安全側のCOMPACTレイアウトへ切り替わる。

### 販売画面

`SalesScreen` は画面全体を横スクロールさせず、注文一覧・置数/機能・商品パネルを `salesListWeight` / `salesKeypadWeight` / `salesProductsWeight` で配分する。

置数パネルは実高さから `keypadMetrics()` を計算し、不足時だけパネル内部を縦スクロールする。商品パネルも縦方向へ退避するため、主要3ペインを保持する目的で横スクロールを追加しない。

### 会計画面

`PaymentScreen` も `paymentDetailWeight` / `paymentKeypadWeight` による2ペイン構成で、画面全体の横スクロールを使用しない。置数側は販売画面と同じ `keypadMetrics()` により高さ不足を縦方向へ退避する。

### 会計完了 → 次取引

`CompleteScreen` はCOMPACT時に本文を縦スクロール可能とし、レシート / 領収書 / 印刷キュー / 売上一覧を2列へ再配置した上で、「次の取引」を全幅の主要ボタンとして残す。

## UI-AT-06 色だけに依存しない状態表示

監査で、販売画面の選択中明細が `PaleBlue` 背景だけで選択状態を表している箇所を確認した。

v1.35では選択明細の背景強調を残しつつ、同じ明細内へ明示的な `選択中` ラベルを追加する。これにより色覚だけへ依存せず、文字でも現在の選択対象を確認できる。

プリンター状態は既存実装で `確認中 / 正常 / 注意 / 異常 / 未使用 / 未設定` の文字ラベルを色と併用しているため、その構造を維持する。

## 自動テスト

新規 `V135UiBaseCommonUiTest` で以下を固定する。

- 販売 / 会計 / 会計完了の主要フローへ `horizontalScroll` を導入しない。
- 販売3ペインと会計2ペインがレスポンシブweightを使用する。
- 1280×800・fontScale 1.30がCOMPACTになる。
- `rememberRegisterResponsiveMetrics()` が `configuration.fontScale` を監視・伝搬する。
- 選択明細に背景色だけでなく `選択中` 文字ラベルが存在する。
- プリンター状態に色だけでなく状態名が存在する。

既存の `V029ResponsiveLayoutTest` / `V093MainFlowResponsiveTest` も回帰対象として維持する。

コード変更後は通常の累積ゲートとして、unit test、Kotlin compile、つぐレジ / つぐレジ＋ / つぐレジ CD の3 APK build、APK identity/integrityを実行する。

## 最後にまとめて行う実機確認

- 1280×800実機で販売 → 会計 → 会計完了 → 次の取引を通し、主要操作・金額・ボタンが欠けないこと。
- 1280×800・文字サイズ1.3倍で販売 / 会計 / 会計完了を通し、文字欠け・重なり・主要操作欠落がないこと。
- 選択明細で背景色に加えて `選択中` ラベルを視認できること。
- プリンター状態が色を区別しなくても状態名で判別できること。
- ダークモード相当・色覚確認で黒地黒文字などの視認不能がないこと。

実機確認は初版の最終総合実機試験へ繰り越す。実機未確認のため、Issue #137 の完了件数には加算しない。
