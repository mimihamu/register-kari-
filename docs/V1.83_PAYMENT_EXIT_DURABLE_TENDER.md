# v1.83 UC-08 会計戻る操作と支払保存の安全性

## 修正内容
- 会計画面で保存済みの支払配分が1件以上ある場合は、「戻る」操作で支払ドラフト・会計キーを消去しない。AndroidシステムBackと画面内「戻る」を同じ `returnFromPayment` で保護。
- 代わりに「支払入力が残っています」ダイアログを表示。元の会計画面へ戻り、配分取消・決済端末側の取消確認を案内する。
- 支払配分が0件の場合のみ `PaymentDraftStore.clear()` を試行。DBエラー時は販売画面へ遷移せず、不整合警告を表示。
- 分割支払の追加/取消では、**先にSQLiteへ支払ドラフトを保存してから** Compose状態、会計キー、顧客表示を更新。保存失敗時は直前の支払入力画面を維持し、警告を表示。
- 二重売上防止 `SaleCommitGuard`・`PaymentCommitKey`、v1.81/v1.82の小数数量・別取引ドラフト判定は維持。

## 検証
- `V183PaymentExitAndDurableTenderTest`：配分有無のガード、システム/画面Back、SQLite保存成功の順序と失敗経路、既存会計キー保護を検査。
- 実機での外部決済端末の取消反映は後続受入試験。アプリ内の「配分取消」は外部決済そのものの取消を保証しない。
