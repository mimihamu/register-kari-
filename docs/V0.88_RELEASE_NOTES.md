# v0.88.0-dev.1 リリースノート

## 上書き更新起動セーフティ台帳

v0.88では、APK上書き更新後に新しい版が実際に通常画面まで起動できたかを永続的に追跡する基盤を追加する。

### 追加内容

- 復元Provider直後に更新起動追跡Providerを実行
- 通常Provider群より前に起動未完了状態をSharedPreferencesへ同期保存
- Provider完了だけでは成功扱いにしない
- `MainActivity`が`RESUMED`した時だけ成功版を確定
- 同じ版の前回起動未完了を検知し、起動試行回数を継続
- 未完了のまま別版へ更新した場合、古い未完了証跡を保持
- 成功後は既存の追記専用監査ログへ版遷移結果を記録
- 成功時のSQLite `user_version`を監査detailへ記録

### 監査event type

- `APP_VERSION_BASELINE_ESTABLISHED`
- `APP_UPDATE_STARTUP_SUCCEEDED`
- `APP_UPDATE_STARTUP_RECOVERED`
- `APP_UPDATE_PREVIOUS_STARTUP_INCOMPLETE`

v0.87以前には正常起動版の永続記録がないため、v0.88初回は旧版を推測せず基準記録として扱う。一度v0.88が正常起動した後は、以後の版遷移をsource/targetで追跡できる。

## 既存機能への影響

販売、税計算、支払、保留伝票、返品・取消、点検・精算、印刷、Google Drive、つぐレジ＋、つぐレジ CDの業務ロジックは変更しない。

更新追跡処理は業務テーブルのUPDATE/DELETEやDBテーブルDROPを行わない。正常起動後に既存`operation_audit`へ診断イベントを追記するだけである。

## 実機確認

本版のCI成功は、実機での上書き更新成功を意味しない。

特に以下は要実機確認。

- v0.87→v0.88上書き更新
- 更新後初回起動
- 初回起動途中の強制終了と次回復旧記録
- 復元予約と上書き更新が重なった場合の起動順序
- 端末再起動後の未完了証跡保持
- 実DBでの監査ログ記録

詳細は`docs/V0.88_APP_UPDATE_TRANSITION_LEDGER.md`を参照。
