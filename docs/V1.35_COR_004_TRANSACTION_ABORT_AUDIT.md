# v1.35 COR-004 取引中止 — 監査付き未確定取引破棄

## 対象仕様

詳細仕様書 v2.5 COR-004 の初版必須要件を対象とする。

- 未確定取引を中止する。
- 中止理由と担当者を監査ログへ記録する。
- 中止した未確定取引を売上集計へ含めない。

## v1.35 実装

販売画面の既存「取引中止」ボタンを `TransactionAbortButtonV135` へ置き換える。

1. 明細が存在する場合だけ取引中止ボタンを有効化する。
2. 押下時に中止理由入力ダイアログを表示する。
3. 空白理由は確定不可とする。
4. `OperatorSessionRegistry.current()` で現在の担当者セッションを再確認する。
5. `operation_audit` へ `TRANSACTION_ABORT` を記録する。
6. 監査記録と `cart_items` / CART税スナップショット削除を同一SQLite transactionで確定する。
7. DB transaction成功後にだけ販売画面上のカートをクリアする。

監査 detail には営業日、理由、明細行数、総数量、中止時点金額を保存する。未確定取引には売上No.が存在しないため `reference_id = 0` とする。

## 売上データとの分離

本経路は以下を作成・更新・削除しない。

- `sales`
- `sale_items`
- `sale_payments`
- 確定売上の印刷ジョブ
- 返品・取消取引

削除対象は未確定作業領域 `cart_items` と、そのCART税スナップショットだけである。したがってCOR-004の取引中止は売上件数、売上金額、支払別集計、X/Z精算へ入らない。

## 失敗時の安全性

`operation_audit` INSERT と作業カート削除は同一transactionである。監査INSERT、カート削除、transaction commitのいずれかが失敗した場合はrollbackし、画面の `onAbortCommitted` を呼ばない。

ログインセッションが失効している場合も取引中止を確定しない。

## 自動検証

`V135TransactionAbortTest` で以下を固定する。

- 理由必須・trim
- 空カート拒否
- 中止時点の明細数・総数量・税込総額snapshot
- 現在担当者の取得
- `TRANSACTION_ABORT` 監査イベント
- 監査INSERTが作業カート削除より先であること
- DB成功後にのみ画面カートを消すこと
- `sales` / `sale_items` / `sale_payments` を作成・更新・削除しないこと
- 販売画面が直接クリアではなく監査付きボタンを使用すること

## 実機確認待ち

コード・CI成功だけでは以下を確認済みと扱わない。

1. 明細なしでは「取引中止」が押せないこと。
2. 明細ありで理由入力ダイアログが開くこと。
3. 理由空欄では確定できないこと。
4. 「戻る」で明細が完全に残ること。
5. 正常確定時に明細が消え、売上件数・売上金額が増えないこと。
6. `operation_audit` に担当者・理由・明細数・数量・金額が残ること。
7. セッション失効時は中止できず、明細が残ること。
8. DB書込失敗を模擬した場合、監査と作業カートが中途半端に片方だけ確定しないこと。

## 初版完成判定

自動テスト・APK検証後も上記実機確認が残るため、マスター台帳 #137 の完了数には実機受入完了まで加算しない。
