# v1.35 COR-007 通常売上照会の取消・返品参照

## 目的

詳細仕様書 v2.5 `COR-007` のうち、反対取引を作成した元売上を通常の売上照会から識別し、元売上と反対取引を相互参照できるようにする。

## 実装

`BusinessDateSalesLookupActivity` の読み取り専用表示に `SaleReversalTraceV135` を結線する。

- 通常売上: 状態表示なし。
- 一部返品: `一部返品`。残数量があるため追加返品を許可。
- 全量返品: `返品済`。追加の返品・取消ボタンを無効化。
- 売上取消: `取消済（VOIDED）`。追加の返品・取消ボタンを無効化。
- 詳細欄に `反対取引 返品/取消 No.x`、返金額、訂正営業日を表示。
- 返品・取消画面側は従来どおり元売上No.を保持するため、これで元売上→反対取引、反対取引→元売上の双方を追跡できる。

## 読み取りモデル

`SaleReversalTraceReadStoreV135` は `reversal_transactions` / `reversal_items` / `sale_items` を読み取り専用で参照する。

- `CANCEL` が1件でもあれば `VOIDED`。
- RETURNの返却数量合計が元数量以上なら `返品済`。
- RETURNが存在し残数量があれば `一部返品`。
- `reversal_items` を持たない旧形式のRETURNは従来の全量反対取引として `返品済`。
- 旧DBで反対取引テーブル自体が存在しない場合は状態なしとして売上検索を継続する。
- `reversal_transactions.business_date` が旧DBにない場合も `NULL` として表示を継続する。

元 `sales`、過去Z精算、反対取引の内容は更新・削除しない。

## 自動テスト

- `V135SaleReversalTracePolicyTest`
  - 通常
  - 一部返品
  - 全量返品
  - 取消/VOIDED
  - 旧形式RETURN
  - CANCEL優先
- `V135CorrectionAccountingSafetyTest`
  - 通常売上照会への状態結線
  - 反対取引No.表示
  - 全量処理済みの再返品・取消無効化
  - COR-009/COR-010既存安全ゲートを継続

## 実機確認

自動検証だけでは完了扱いにしない。以下を実機で確認する。

1. 通常売上は状態ラベルなし。
2. 一部返品後に `一部返品` と反対取引No.が表示され、残数量の追加返品が可能。
3. 全量返品後に `返品済` となり、再返品・取消ボタンが無効。
4. 取消後に `取消済（VOIDED）` となり、再返品・取消ボタンが無効。
5. 複数回の一部返品で全反対取引No.が表示される。
6. 売上照会の「更新」後に最新状態へ反映される。
7. 過去営業日の売上を当日訂正した場合、元売上の営業日は変わらず、反対取引側に訂正営業日が表示される。
8. 旧DBで反対取引情報がない売上でも売上照会がクラッシュしない。
