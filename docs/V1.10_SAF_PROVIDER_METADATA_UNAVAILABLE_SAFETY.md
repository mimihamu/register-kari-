# v1.10 SAF Providerメタデータ検索不能時の安全化

## 背景

v1.09では、DocumentsProvider の子項目一覧 `ContentResolver.query()` が `null` を返した場合に「対象なし」と誤認して新規作成へ進まないようにした。

一方、作成・rename後の `COLUMN_DISPLAY_NAME` 確認と、書込み後の `COLUMN_SIZE` 確認では、query自体が `null` の場合も値が不明なだけとして処理される経路が残っていた。

特に表示名確認では、Provider一時障害によるquery nullと実際のProvider自動変名を区別できず、永久衝突へ誤分類する可能性があった。

## v1.10 方針

- `COLUMN_DISPLAY_NAME` のquery結果がnullならメタデータ検索不能として停止する。
- `COLUMN_SIZE` のquery結果がnullならメタデータ検索不能として停止する。
- メタデータ検索不能は `IOException` 系の一時障害とし、衝突例外にしない。
- 表示名検証前にメタデータ検索不能となった場合、アプリ自身が直前に作成／renameした未検証オブジェクトだけを削除して再試行する。
- 既存の確定JSONは削除・上書きしない。
- Providerから有効なCursorが返り、サイズ値自体がnullの場合は従来どおり「Providerがサイズを提供しない」ケースとしてSHA-256検証を継続する。
- Providerから有効なCursorが返り、表示名値がnull／不一致の場合はv1.07のProvider変名拒否を維持する。

## 既存安全性との関係

- v1.06: 同名確定JSONはサイズ＋SHA-256一致時のみ送信済み扱い。
- v1.07: create/rename後の実表示名が要求名と完全一致しなければ確定しない。
- v1.08: 同一表示名候補が複数あれば任意選択しない。
- v1.09: 子一覧query nullを「対象なし」と扱わない。
- v1.10: 作成後の表示名／サイズquery nullを未検証成功として扱わない。

## 実機確認

実Google Drive / DocumentsProviderでのquery null発生条件、未検証オブジェクトcleanup、Provider復旧後retryは最終総合実機試験で確認する。
