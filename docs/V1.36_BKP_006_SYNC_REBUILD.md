# v1.36 BKP-006 / BKP-018 復元後同期・同期再構築

正式仕様 v2.5 の BKP-006「同期再構築」および BKP-018「復元後同期」に対する実装記録。

## 実装方針

- Drive の売上データを REGISTER / つぐレジの業務DBへ逆輸入しない。
- 復元DB内の `sales_journal` を正として、対応する `sync_outbox` が欠落しているイベントだけを `PENDING` で再構築する。
- 既存 `sync_outbox` 行、`SENT` 状態、Drive API の `SUCCEEDED` ACK、`drive_api_uploads.file_id`（documentId）は変更・削除しない。
- 再構築後に不足件数が 0 であること、既存SENT/ACK/documentId件数が変化していないことを検証し、成立しない場合は復元処理を失敗させて既存ロールバック境界へ戻す。
- 予備端末移行では terminalId 切替より前に再構築する。再構築outboxには復元元の `storeId / terminalId / generation` を保存し、旧イベントの duplicateImportKey を維持する。
- 通常生成される outbox にも source identity snapshot を保存する。JSON再生成時は現在のruntime identityではなくoutboxのsource identityを優先する。
- 復元成功後は Direct Drive upload worker を即時enqueueする。workerは PENDING をstagingしたうえで既存の `duplicateKey` と `contentSha256` を照合し、同一イベントを冪等処理する。

## 主な実装

- `RestoreSyncRebuildV136.kt`
  - `sales_journal LEFT JOIN sync_outbox` で欠落イベントのみ検出
  - 不足outboxの再構築
  - SENT / ACK / documentId 不変確認
  - Drive読込・売上逆輸入経路を持たない
- `BusinessSyncFoundation.kt`
  - `sync_outbox.source_store_id`
  - `sync_outbox.source_terminal_id`
  - `sync_outbox.source_generation`
  - outbox identity snapshot trigger
  - `OutboxPayloadAssembler` がsnapshot identityを使用
- `DataRestoreBootstrapV086.kt`
  - BKP-006再構築をBKP-005 terminal migrationより先に実行
  - 復元監査・結果へ再構築件数とSENT/ACK/documentId保持件数を記録
  - 復元成功後にDrive reconciliationをenqueue
- `GoogleDriveDirectUpload.kt`
  - Direct Drive処理開始時にPENDING outboxをstaging
  - 既存 `duplicateKey` / `contentSha256` / `file_id` 契約を継続利用

- 実Driveに既に存在する売上JSONを含むバックアップからの復元後、duplicateKey照合で二重作成されないこと
