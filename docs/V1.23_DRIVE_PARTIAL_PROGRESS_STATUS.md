# v1.23 Google Drive 同期のcommit済み進捗表示

## 背景

v1.22で、1ページ分のSalesJournal importとDrive fingerprintは同一SQLite transactionでatomicにcommitされるようになった。

一方、同期statusの件数は最終成功時にしか更新していなかったため、次の状態があり得た。

1. 前回同期が成功し、statusに前回件数が残る。
2. 新しい同期で1ページ目が正常にDB commitされる。
3. 2ページ目の取得中にネットワーク/APIエラーで同期が失敗する。
4. DBには1ページ目が反映済みなのに、失敗statusの件数は前回成功時の値のまま残る。

運用画面で「今回どこまでcommitされたか」を誤認し得るため、v1.23でstatusのrun ownershipとページcommit境界を揃える。

## 変更

- 同期開始 `running()` 時に listed / downloaded / unchanged / imported / duplicates / rejected / errors を0へ初期化する。
- `progress(runToken, result)` を追加する。
- `progress()` は現在の `run_token` 所有者だけが更新できる。
- 各Driveページのimport/fingerprint処理が完了し、v1.22のatomic transactionから戻った後にだけprogressを保存する。
- progress保存後に次のpage tokenへ進む。
- 後続ページで失敗した場合、failure処理は件数を上書きせず、最後に保存されたcommit済みページの進捗を保持する。
- stale worker/callerが別runのprogressを上書きできないv1.21のrun ownershipを維持する。

## 保持する既存保証

- v1.19: Drive server version fingerprint
- v1.20: 全ページ走査 / incompleteSearch拒否 / page token loop検出
- v1.21: single-flight / run ownership / immediate work統合
- v1.22: import + fingerprint atomic commit

DB schema変更はない。Management DB version 6を維持する。

## テスト

`V123DrivePartialProgressStatusTest` で以下を確認する。

- 新run開始時に旧件数を0へ初期化すること。
- progressがrun token所有者に限定されること。
- atomic import/fingerprintの後、next pageへ進む前にprogressを書き込むこと。
- failureがcommit済みprogress件数を消さないこと。
- v1.21 / v1.22のsingle-flight・atomicity境界を維持すること。

## 実機確認へ繰り越す項目

- 実Google Driveで1ページ目commit後、2ページ目通信中に回線断した場合の表示。
- WorkManager再試行後に新runの件数が0から始まり、前回失敗runと混ざらないこと。
- アプリ強制終了・再起動時のstale run修復表示との組合せ。
- 5,000件超データを含む総合実機確認。

これらは最終総合実機試験まで「確認済み」とは扱わない。
