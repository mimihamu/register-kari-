# v1.60 レジマイナス：二重返金を防ぐ確定復旧

## 解消する障害

レジマイナスは通常の売上カートと独立した負数取引として登録する。従来、DBコミット後にドロアの非同期送信キューへ登録する際の例外がUIの確定失敗と見なされると、もう一度確定して別の `approval_request_id` を発行する可能性があった。**1操作の二重マイナスを許してはならない**。

## 実装

- 画面の確定ダイアログごとに1つの `checkoutRequestId` を発行し、`rememberSaveable` で画面再作成を跨ぐ。確定の連打は既存 `ManualReturnSubmissionGateV135` でブロック。
- 確定が失敗して同じダイアログ内で再実行すると、同じ操作IDを使用する。
- DBの `approval_request_id TEXT NOT NULL UNIQUE` を保持。取引登録前にそのIDで既存の負数取引を検索する。
- 既存取引が存在した場合、符号付き総額、返金方法、理由、担当者、承認責任者、商品ID/名称、単価、負数数量の全件が同一の場合のみ、保存済み取引番号と印刷ジョブ番号・印刷文面を返す。異なる場合は新規登録せず拒否する。
- DBコミット後のドロア起動キュー例外はログに記録しても取引確定結果を失敗に戻さない。ドロアの `eventKey` は取引番号に依存し、同じ取引の二重キックを防ぐ既存制御を維持する。
- 既存の返品/取消履歴、Z精算、負数税計算、監査情報、印刷キュー形式は変更しない。

## テスト

`V160RegisterMinusCommitRecoveryTest` に同一・差分再実行の検証を追加。変更対象は金額、返金方法、理由、担当者、責任者、商品ID、商品名、単価、数量、明細数。UI操作ID、DBの一意制約、コミット後の副作用分離もソースゲート検証。

## リリース受入に残る項目

1. 実機で確定連打・バックグラウンド復帰・ネット断・紙切れ時の負数取引の件数と金額が1件に収まること。
2. 現金返金でドロアが一度だけ開くこと。送信失敗時の運用を確認すること。
3. 非現金返金は決済端末側で別途取消/返金する必要がある。端末との二重処理がないこと。
4. 同一操作IDでの回復および既存印刷文面の再取得をDB入り実機試験で確認すること。
5. 正式署名と旧版からの上書き更新は未確認。
