# v0.33 定期バックアップ・保存世代設定・失敗通知

## 目的

v0.21〜v0.23で実装した安全なバックアップ、外部保存、Z精算後自動バックアップ、保存世代管理を維持したまま、端末単体で継続運用できる定期バックアップと管理者通知を追加する。

## バックアップの発生条件

- Z精算後バックアップは従来どおり常時有効で、無効化できない。
- 定期バックアップは責任者がON／OFFを設定できる。
- 周期は「毎日」または「7日ごと」。
- 実行時刻は0〜23時で指定する。
- WorkManagerの制約により、指定時刻は開始目安であり、端末停止、バッテリー低下、ストレージ低下中は遅れて実行される。
- ネットワーク接続は不要。
- アプリ起動時は既存の定期Workを`KEEP`し、設定保存時だけ`UPDATE`する。アプリ起動のたびに翌日へ先送りしない。

## 安全条件

- `requiresBatteryNotLow=true`
- `requiresStorageNotLow=true`
- 実行直前にもDB、WAL、SHMと空き容量を再判定する。
- 必要容量を満たさない場合は世代整理後に再判定し、それでも不足する場合はバックアップを開始しない。
- 定期バックアップ失敗によって販売、売上、Z精算を巻き戻さない。
- 既存のSQLite整合性検査、SHA-256検証、原子的ファイル確定を使用する。

## 保存世代設定

責任者は以下を設定できる。

- Z精算後バックアップ保持営業日：1〜90営業日、初期値14営業日
- 定期バックアップ保持月数：1〜36か月、初期値12か月

次は設定値に関係なく保護する。

- 手動バックアップ
- 外部取込バックアップ
- 「自動バックアップを今すぐ実行」で作成したバックアップ
- 最新の正常なバックアップ
- 復元予約中のバックアップ
- 検証中、破損判定、不明なバックアップ

## 失敗通知

- バックアップ失敗と空き容量不足による中止をAndroid通知する。
- 通知タップでデータ保全画面を開く。
- Android 13以降では`POST_NOTIFICATIONS`の許可が必要。
- 責任者はバックアップ失敗通知だけをOFFにできる。
- 通知をOFFにしても、画面の最終結果、エラー詳細、監査ログは維持する。
- 次回バックアップ成功時に以前のバックアップ異常通知を解除する。

## 監査ログ

既存イベントに加え、以下を使用する。

- `DATA_BACKUP_SETTINGS_UPDATED`
- 定期Worker開始時の`DATA_BACKUP_AUTO_REQUESTED`

既存の成功、失敗、容量不足、世代整理イベントも継続する。

## Google Driveとの区別

定期バックアップはアプリ内部保存であり、Google Driveへの自動アップロードではない。Google Drive、USB、端末フォルダへの外部保存はStorage Access Frameworkによる手動操作を維持する。OAuthやDrive APIの認証情報は本版に含めない。

## 要実機確認

- 設定時刻付近で定期Workerが実行されること
- 端末停止中の予定が起動後に遅延実行されること
- 毎日／7日ごとの切替
- バッテリー低下・ストレージ低下中の延期
- 容量不足通知、一般失敗通知、通知タップ遷移
- Android 13以降の通知権限許可・拒否
- 設定した保持営業日・保持月数で実ファイルが整理されること
- Z精算後バックアップが定期設定OFFでも継続すること
