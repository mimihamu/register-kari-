# v1.08 SAF同名複数項目の非破壊安全化

## 背景

つぐレジの外部売上同期は、object keyの各パス要素をSAFの子ドキュメント一覧から `COLUMN_DISPLAY_NAME` で検索している。

v1.06では同名の確定JSONが1件見つかった場合にサイズとSHA-256を照合し、同一内容だけを送信済みとして扱うようにした。v1.07ではcreate/rename後の実保存名が要求したobject key名と完全一致することも確認するようにした。

しかしv1.07までの `findChild()` は、同じ表示名に一致する子項目が複数あっても最初の1件を返していた。

この状態では、例えば同一フォルダ内に `sale.json` が複数存在し、そのうち最初に列挙された1件だけがローカルJSONと一致する場合、別の同名・異内容項目を残したまま「既に送信済み」と判断できる余地がある。また、object key途中のフォルダ名や `.partial` 一時ファイルでも、複数候補から任意の1件を選ぶことになる。

## v1.08の規則

`OutboxExternalDocumentProvider.findChild()` は、要求した `displayName` と完全一致するすべての子項目を最後まで確認する。

- 一致0件: 未作成として扱う
- 一致1件: その1件だけを候補として返す
- 一致2件以上: `OutboxDuplicateDisplayNameException` を送出し、任意の1件を選ばない

`OutboxDuplicateDisplayNameException` は `OutboxDestinationCollisionException` を継承し、既存の非破壊衝突経路へ合流する。

## 適用範囲

一意性確認は `findChild()` を利用する以下すべてに適用する。

1. object key途中のディレクトリ
2. 確定JSON
3. `.partial` 一時JSON

同名候補が複数ある場合、どの候補が正しいかをアプリが推測しない。

## 衝突時の安全動作

同名複数項目を検出した時点では、検索だけを行い、既存候補に対するdelete/create/rename/writeは実行しない。

既存の衝突処理により以下となる。

- sync_outbox: `FAILED`
- 自動再試行: 行わない
- SQLite売上: 変更しない
- Sales Journal: 保持
- ローカルstaging JSON: 保持
- 送信先の既存同名項目: すべて保持
- 監査: `SYNC_OUTBOX_EXTERNAL_COLLISION`
- 管理者が送信先の重複状態を解消した後の手動再試行: 維持

同名候補を自動削除、自動上書き、自動renameして整理しない。

## v1.06 / v1.07との関係

### v1.06

同名候補がちょうど1件の場合のみ、従来どおりサイズとSHA-256を照合する。

- 同一内容: `ALREADY_SENT`
- 異内容／ディレクトリ: 衝突FAILED

### v1.07

新規create/rename後の `COLUMN_DISPLAY_NAME` 完全一致確認を維持する。

v1.08はこれらを置き換えず、「検索時に同名候補が複数なら一意に決めない」という前段の安全条件を追加する。

## 非変更範囲

- 売上計算
- 税計算・税マスタ・内税／外税・軽減税率
- 値引・割引
- 支払配賦・会計冪等性
- Z精算
- レシート／領収書
- プリンタ通信・印刷queue
- つぐレジ CD通信
- バックアップ／復元
- v1.06の既存確定JSON非破壊ルール
- v1.07のcreate/rename保存名完全一致ルール

## 実機・実アカウント確認

以下は最終総合実機試験へ繰り越す。

- Google Drive実アカウントの送信先で同名複数項目を作れる／発生する場合の検出
- 同名確定JSONが複数ある場合に既存ファイルを一切変更しないこと
- 同名ディレクトリが複数ある場合に書込を開始しないこと
- 同名 `.partial` が複数ある場合に任意削除しないこと
- 重複を外部で解消した後の手動再試行
- provider固有の子ドキュメント列挙順・重複名挙動

実Google Driveアカウント・実DocumentsProviderでは未確認のため、CI成功後も確認済みとは扱わない。
