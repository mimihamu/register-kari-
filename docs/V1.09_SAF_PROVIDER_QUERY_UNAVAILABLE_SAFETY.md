# v1.09 SAF Provider Query Unavailable Safety

## 目的

SAF/DocumentsProvider の子項目検索 `ContentResolver.query()` が `null` を返した場合に、「子項目が存在しない」と誤認して新規作成へ進まないようにする。

## 問題

v1.08 までの `findChild()` は `resolver.query(...)? .use` 相当の構造で、query が `null` の場合は一致候補0件として `null` を返していた。

この場合、Provider の一時障害や応答不能を「対象なし」と誤認し、フォルダ・確定JSON・partial JSONの作成へ進む余地がある。

## v1.09 の変更

- `OutboxProviderQuerySafetyV109.requireAvailable()` を追加。
- `findChild()` の子項目query結果が `null` なら `OutboxProviderQueryUnavailableException` を送出。
- `OutboxProviderQueryUnavailableException` は `IOException` 系で、既存の衝突例外を継承しない。
- query不能時は lookup 内で create / delete / rename / write を行わない。
- 既存の通常失敗リトライ経路を利用し、Provider復旧後に再試行可能とする。
- permission lost や同名衝突とは区別する。

## 維持する既存安全性

- v1.06: 同名確定JSONのサイズ＋SHA-256照合、異内容は非破壊衝突。
- v1.07: create/rename後の実保存表示名完全一致検証。
- v1.08: 同一表示名が複数存在する場合は任意採用せず非破壊衝突。

## 対象

`findChild()` を経由する以下すべて。

- object key途中のdirectory
- 確定JSON
- `.partial` 一時JSON

## 非変更範囲

販売、税、値引、支払、会計、印刷、顧客表示、つぐレジ＋、つぐレジ CD の業務仕様は変更しない。

## 実機確認

実DocumentsProviderがどの条件でquery nullを返すか、実Google Driveアカウントでの挙動、復旧後の再試行は最終総合実機試験へ繰り越す。
