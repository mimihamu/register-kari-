# v1.37 CD会計安全性 / canonicalMode段階導入
基準：正式仕様 v2.5 §30.5–30.7、CDP-AT-03/04。

- 旧CDとの互換性を保つため、旧 `mode` (SALES/ACCOUNTING/COMPLETE) をそのまま残し、正式相当の `canonicalMode` (CART/PAYMENT/CASH_RECEIVED/CHANGE/COMPLETE) を追加。新CDのみ canonicalMode に基づき描画。
- 入金時の `ACCOUNTING` snapshot には確定前の `changeAmount` を含めず、0を送る。過剰預りや複合支払でも釣銭の確定額を表示しない。入金済み現金ありなら `CASH_RECEIVED`、それ以外は `PAYMENT`。
- 売上確定・SQLite記録後の `COMPLETE` snapshot は、お釣り >0 の場合 canonical `CHANGE` として通知し、設定 changeSeconds 初期5秒後、表示釣銭を消した canonical `COMPLETE` へ移る。その後 completeSeconds 秒後に待機する。釣銭0の場合は直接 `COMPLETE`。
- 販売再開時には進行中のCHANGE/COMPLETEのタイマーを解除して、新しいCARTを優先する。
- 旧 `mode` の送信を完全に正式名へ変更する作業は受信端末のバージョン交渉が必要なため別件。完全な §30.6適合には、schemaVersion文字列発行・デバイス／店舗識別子、その他の契約試験が残る。
- 実機Wi-Fi瞬断/2台同期/1000商品更新および時間精度の実機計測は未確認。
