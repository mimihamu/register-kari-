# v1.39 BKP-AUTO-001 自動バックアップ

## 正式仕様 v2.5との対応

`backup.autoSchedule` の初版対象として、以下をつぐレジに実装する。

- 毎日
- 日計（Z）精算後
- 指定曜日

`settlement.autoBackup` はON/OFF可能とし、初期値はONとする。

## 実装

製品統合コミット: `803918cef9fc68b14fefb80420e5173080f92902`

- `AutoBackupSettings.kt`
  - 毎日 / 指定曜日を明示的に保持。
  - 指定曜日はISO-8601の1=月曜〜7=日曜で永続化。
  - 指定曜日の次回実行時刻を端末タイムゾーンで決定。
  - Z精算後自動バックアップON/OFFを永続化し、既定ON。
- `AutoBackupSettingsActivity.kt`
  - 指定曜日UI。
  - Z精算後自動バックアップON/OFF UI。
  - 設定変更を監査ログへ記録。
- `AutoBackup.kt`
  - Z精算後バックアップのenqueue直前に設定を再読込し、OFFならジョブを作らない。
  - ON時は従来のsettlementId単位unique workを維持し、同一精算の二重バックアップを防止。
- 既存WorkManager制約（battery-not-low / storage-not-low）、失敗通知、保持制御は維持。

## 自動確認

`V139AutoBackupScheduleTest` で以下を固定する。

- 指定曜日の次回時刻。
- 同一指定曜日で時刻通過後は翌週になること。
- 毎日の既存時刻計算が退行しないこと。
- settlement auto backupの初期値ON。
- scheduler/UIへの設定配線。

focused integration gateでは上記テストと `:app:compileDebugKotlin` を成功確認済み。最終判定はtemporary helperを除去したclean HEADの累積CIを用いる。

## 実機未確認

以下はAndroid実端末で最終確認する。

- 毎日の実行。
- 指定曜日の実行。
- Z精算確定直後の自動バックアップ。
- Z精算後自動バックアップOFF時に作成されないこと。
- Doze / アプリ停止 / 再起動 / battery-not-low / storage-not-low条件でWorkManagerが安全に遅延・再開すること。
