# v1.94 CD 再同期待ちの上限と接続復旧

## 問題
顧客表示WebSocketで `STATE_UPDATE` の欠番/不明セッションを検知すると、CDは金額表示を隠し `SNAPSHOT_REQUEST` を1回だけ送る。応答が失われた一方でping/pongや別の更新が届き続けると、`awaitingSnapshot` が解除されないまま、再接続も発生しない可能性があった。

## 対応
- `CustomerDisplayResyncDeadlineV194`: 再同期要求から15秒以内に正規のフルSNAPSHOTが届かない場合、WebSocketを切断して既存の再接続ループへ戻す。単調時計 `System.nanoTime()` を利用し、端末時刻変更に依存しない。
- CDの `readFrames()`: リーダーループとSocketTimeoutの両方で期限切れを検査。受信トラフィックが続いても無期限待機しない。
- 最初のSNAPSHOT要求時だけ計時を開始し、正式なSNAPSHOT適用後に期限を解除する。既存の `notifyResyncRequired()` による旧金額非表示、epoch/セッション/sequence検証は維持する。
- `V194SnapshotResyncDeadlineTest` で期限境界、正常解除、継続更新・アイドル両ケース、表示非公開を回帰検証。

本修正はPOS側のWebSocket仕様や端末の認証方法を変更しない。実機LAN断・端末スリープ・顧客表示の復元通し試験は別途必要。
