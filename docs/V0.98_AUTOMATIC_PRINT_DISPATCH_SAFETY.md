# v0.98 自動印刷キュー順序・フェイルファスト強化

## 目的

実プリンター投入前に、自動印刷Workerの送信順序・送信件数・失敗時動作を安全側へ統一する。

既存のTCP 9100、ESC/POS、EPSON DLE EOT、送信フェーズ判定、送信結果不明時の自動再送禁止は変更しない。

## v0.97までの課題

従来の`AutomaticPrintWorker`は、売上レシートと業務帳票を別ループで処理していた。

- 売上レシートで失敗しても、その後に業務帳票ループへ進む
- 業務帳票は1件失敗しても後続帳票を送信し続ける
- `MAX_JOBS_PER_RUN=20`が各ループへ個別適用され、1回のWorkerで最大40件を試行し得る
- 業務帳票一覧は新しい順で取得されるため、そのままでは古い帳票より新しい帳票を先に送信する
- periodicとimmediateが別のunique work名で、自動Worker同士をアプリ内で単一実行にするゲートがなかった

## v0.98の動作

### 共通送信順序

`AutomaticPrintQueuePolicy.oldestCandidate`で以下を1本の候補列として扱う。

- 売上レシート
- 返品・取消レシート
- X点検票 / Z精算票
- 領収書

`PENDING`または`RETRY`だけを対象とし、売上／業務帳票を横断して`createdAt`の古いものから1件ずつ選択する。同一時刻の場合は安定した種別・ID順で決定する。

### 1回最大20件

`AutomaticPrintQueuePolicy.MAX_JOBS_PER_RUN = 20`をWorker全体へ1回だけ適用する。

売上20件＋業務帳票20件のような40件処理は行わない。20件処理後にまだ自動送信対象が残る場合は`Result.retry()`として継続対象にする。

### フェイルファスト

1件でも送信に失敗した場合、そのrunでは後続ジョブを送信しない。

- 接続開始前など安全に再試行できる失敗: 既存ルールどおり`RETRY`
- `WRITE_STARTED` / `FLUSHED`以降の送信結果不明: 既存ルールどおり`FAILED`、紙確認後の手動対応

別帳票を続けて送らないことで、障害発生時の紙とキュー状態の突合を容易にする。

### 自動Worker単一実行

`AutomaticPrintWorkerRunGate`を追加し、同一アプリプロセス内で自動印刷Workerを1本だけ実行する。

periodicとimmediateが重なった場合、後から入ったWorkerは送信を開始せず`Result.retry()`とする。

このゲートは自動Worker同士の重複実行防止を目的とする。責任者による手動再印字・強制印刷の既存確認手順は変更しない。

## 維持する安全仕様

- 売上保存と印刷ジョブ登録はSQLiteトランザクションで確定
- TCP 9100 / ESC/POS
- 58mm / 80mm
- カット設定
- 現金会計時ドロア制御
- EPSON DLE EOT n=1～4状態確認
- STAR / 汎用ESC/POSの自動状態確認は未検証として禁止
- `CONNECTING` / `CONNECTED` / `WRITE_STARTED` / `FLUSHED`送信フェーズ
- `WRITE_STARTED`以降の失敗は自動再送禁止
- 起動時に残った`PRINTING`は`FAILED`へ安全回収
- 手動安全印刷、責任者PIN付き強制印刷、監査ログ

## 変更しない領域

- 売上計算
- 税計算 / インボイス表記
- 保留伝票
- Google Drive同期
- つぐレジ CD通信
- 売上DB、Sales Journal、バックアップ、ロールバック等のデータ保護仕様

本対応で売上データを削除・上書きする処理は追加しない。

## 実機確認

CIでは実プリンターの紙排出を確認できないため、以下は**最終総合実機試験へ繰越**する。

- EPSON実機TCP 9100印刷
- 58mm / 80mm日本語印字
- 部分カット / フルカット
- DK1 / DK2および現金会計時ドロア
- DLE EOT状態応答
- 紙切れ / カバー開 / カッター異常
- LAN切断前後のRETRY / FAILED遷移
- `WRITE_STARTED`以降の障害時に二重印刷しないこと
- periodic / immediate重複条件で自動送信が直列化されること
- 20件超バックログが複数runで順序を維持して解消されること

CI成功を実プリンター確認済みとは扱わない。
