# v1.95 CD 初回表示データ受信期限

## 不具合
WebSocketのHTTP 101 handshake完了後、POSが最初のSNAPSHOTを送らず、ping/pongだけを継続した場合に、CDの表示がいつまでも「最新の表示データを受信中」のままになる可能性があった。v1.94の15秒再同期ガードは`SNAPSHOT_REQUEST`が送られたときにのみ開始するため、この経路は対象外だった。

## 修正
- `CustomerDisplayInitialSnapshotDeadlineV195`を追加。接続確立後から正式な初回SNAPSHOTを受信するまでを**15秒**に制限し、期限超過時は切断して既存の再接続ループへ戻す。端末の時刻変更に影響されない`System.nanoTime()`を使用。
- `CustomerDisplayWebSocketClient.readFrames()`の受信ループ先頭と`SocketTimeoutException`の両方で期限を検査。ping/pongや無効なSTATE_UPDATEで接続が活動していても、正規SNAPSHOT不在時は切断・再試行する。
- `previousSnapshot != null`になるのは既存`CustomerDisplayDeliveryPolicy`が正式な表示データを受け入れた後のみ。初回SNAPSHOT受信後は通常の長時間接続を維持する。
- `V195InitialSnapshotDeadlineTest`で境界時刻、正常解除、ループ/タイムアウト経路、既存ガードの併存を検証する。

POS端末側の通信形式・認証・会計処理は変更なし。実機Wi-Fi切断/復帰や1時間以上の連続表示試験は未受入。
