# v1.35 COR-007 / COR-009 / COR-010 訂正データ安全性

## 目的

詳細仕様書 v2.5 の次の要件について、既存実装の成立箇所を監査し、今後の変更で壊せない回帰ゲートを追加する。

- `COR-007` 売上取消: 確定売上を消さず反対取引を作成し、元取引と取消取引を参照可能にする。
- `COR-009` 日計後訂正: 過去営業日の元売上を訂正しても、訂正金額は訂正実行日の営業セッションへ計上し、過去Z精算を改変しない。
- `COR-010` 削除禁止: 確定した売上・返品・取消・入出金を通常UI/APIから物理削除しない。

## COR-007 現在の実装

`OperationsStore.createReversal` は元売上を更新・削除せず、`reversal_transactions.original_sale_id` で反対取引を追記する。

- 反対取引に `original_sale_id` を保存。
- `reversal_type` に RETURN / CANCEL を保存。
- `reversal_items` / `reversal_payments` を別保存。
- `reversedSaleIds()` で全量返品・取消済みの元売上を導出。
- 返品・取消画面では全量処理済みを「完了」と表示し、再選択不可。
- `recentReversals()` は反対取引IDと元売上IDを読み出す。

### COR-007 残作業

通常の売上照会 (`BusinessDateSalesLookupActivity`) では、元売上に「取消済 / VOIDED相当」を表示し、反対取引No.へ辿れるUIがまだ結線されていない。反対方向（取消履歴→元売上）と合わせてv1.35の残差分とする。

この未実装を忘れないよう、`V135CorrectionAccountingSafetyTest.normalSalesLookupStillNeedsVoidedStatusIntegration` は現時点では**ギャップ検出テスト**として未結線状態を固定する。COR-007を閉じるコミットで、このテストを正の受入テストへ置換する。

## COR-009 現在の実装

返品・取消の書込トランザクション開始時に `queryActiveSession(this)` で**訂正実行時の営業セッション**を取得し、反対取引へ次を保存する。

- `business_session_id = session.id`
- `business_date = session.businessDate`
- `original_sale_id = originalSaleId`

したがって、元売上が過去営業日のものであっても反対金額は実行中営業日の集計へ入る。一方、元売上および過去の `settlement_reports` をこの処理からUPDATE/DELETEしない。

`V135CorrectionAccountingSafetyTest` で、この4点と旧精算非改変をソース回帰ゲート化する。

## COR-010 現在の実装

通常アプリのKotlinソース全体 (`app/src/main/java/**/*.kt`) を走査し、次の確定業務テーブルに対するSQL `DELETE FROM` またはAndroid SQLite `delete(table, ...)` を禁止する。

- `sales`
- `reversal_transactions`
- `cash_movements`

DBマイグレーションやバックアップ/リストア仕様を将来追加・変更する場合でも、通常実行経路へ物理削除を入れるとユニットテストが失敗する。

## 実機確認へ繰り越す項目

- 過去営業日の売上を翌営業日に返品/取消し、翌営業日の売上集計だけが減額されること。
- 過去営業日のZ精算票・履歴が書き換わらないこと。
- 返品/取消履歴から元売上を特定できること。
- 全量処理済み元売上を再度返品/取消できないこと。
- COR-007完成後、通常売上照会で元売上に取消済/VOIDED相当が表示され、反対取引へ辿れること。
