# v1.84 売上確定後の完了画面到達・後処理の安全性

## 発見した問題
`RegisterDatabase.saveSale` は、売上・印刷ジョブ・作業中カートの削除をSQLite同一トランザクションで確定している。しかし、その後の `onSuccess` で顧客表示更新・ドロア予約・印刷/クラウド同期起動・`replaceCart(emptyList())` のどれかに例外があると、**売上は確定済みでも完了画面に到達しない**可能性があった。操作者に二重会計の誤解を与える。

## 修正
- `saveSale` がsaleIdを返した直後、売上番号と画面を `AppScreen.COMPLETE` に確定。表示/周辺機器の例外は売上成功そのものを否定しない。
- DB側はすでにカートを消去しているため、成功後の `replaceCart(emptyList())`（DBに二度書き込む処理）を撤廃。Compose上のcartとcorrectionsのみ消去。
- `PaymentDraftStore.clear()` だけは個別に試行。失敗時は売上確定済みと明示し、新規会計をブロック。次の取引ボタン/Android戻るの両方で安全な削除の再試行が可能。
- 顧客表示・ドロア・印刷/同期起動の例外は保護し、会計画面へ巻き戻さず売上番号を表示したまま周辺機器確認案内を出す。
- 売上履歴、会計冪等キー、決済・釣銭、保存済み印刷ジョブの既存仕様は変更しない。

## 自動検査
`V184PostCommitCompletionSafetyTest.kt` によって、画面切替と売上番号設定がDB再処理より先にあること、戻る/次の取引で後処理不完全を安全に扱うこと、売上SQLite原子処理が維持されていることを検証。

## 実機確認時
プリンタ・ドロア・顧客表示それぞれ切断した状態で会計し、売上番号と完了画面が消えず、次の取引に二重入力されないこと。現場での決済端末との照合も必要。
