# v1.36 PRN-PROF-002 PrinterProfile 印字可能性確認

## 正式仕様基準

`REGISTER（仮）_Androidレジ_詳細仕様書_v2.5.docx` §16.2 / §16.10 を基準とする。

- 印刷設定は 58mm / 80mm、印字可能dot幅、接続先、文字コード、カット、ドロアを組み合わせて検証する。
- テスト印刷は保存前に実行可能とする。
- テスト印刷には全角、半角、英数字、記号、最大桁金額、8%・10%・非課税、値引、負数、QR、カットを含める。
- 紙幅変更時は販売レシート、領収書、仮締め票、精算票の4文書を確認する。
- PrinterProfile snapshot は `printerId / connectionType / printableDotWidth / logicalColumns / encoding / supportsCut / feedLines / drawerPort / statusCapability` 等を保持する。

## v1.36 実装

### 1. 既存の実接続経路を使用

`AdminSettingsStore.testPrinter()` は選択中の `PrinterConfiguration` を使用し、

1. host / port / PrinterProfile / paperWidth / printableDotWidth / feedLines / cutMode を確定
2. `PrinterCommandEncoder` でESC/POS payloadを生成
3. 通常印刷と同じ `TcpEscPosPrinterGateway` からTCP 9100へ送信
4. 成否を `PRINTER_TEST_SUCCEEDED` / `PRINTER_TEST_FAILED` として監査記録

する。テスト専用の別通信実装には分岐しない。

### 2. 正式テストマトリクス

`PrinterProfilePrintabilityV136` を追加し、テストpayloadへ以下を含めた。

- 全角日本語
- 半角 / 英字大文字小文字 / 数字
- 記号
- 最大桁金額 `¥9,999,999,999`
- 10%対象
- 8%対象・軽減記号
- 非課税
- 値引
- 負数
- QRコード
- 設定された `feedLines`
- 設定されたcut mode

QRは文字列表示だけではなく、ESC/POS `GS ( k` QR Code Model 2 の実コマンドをpayloadへ埋め込む。

### 3. 4文書テストを維持

既存 `PrinterPaperWidthTestV136` の

- 販売レシート
- 領収書
- 仮締め票
- 精算票

を維持し、その前段へ正式テストマトリクスを追加した。58mm=32論理桁、80mm=48論理桁のルーラーも従来通り出力する。

### 4. ソフトウェア事前検証

`PrinterProfilePrintabilityV136.validateSoftwarePreflight()` で、実機送信前に

- host
- port
- timeout
- paperWidth / printableDotWidth / feedLines整合
- profile charsetがAndroid/JVMで利用可能か
- drawerを有効にした場合のprofile capability

を検査可能にした。

## 実機確認待ち

ソフトウェア上のTCP送信成功だけでは「実際に印字できた」と断定しない。次は実プリンターで以下を確認する。

- 選択PrinterProfileで全角/半角/記号が文字化けしない
- 最大桁金額が欠落しない
- 8% / 10% / 非課税 / 値引 / 負数が読める
- QRを実機で印字し、読み取れる
- 58mm / 80mmと実紙幅が一致する
- feedLinesの紙送り量
- partial / full cutの実動作
- statusCapabilityに基づく紙切れ・カバー等の実状態取得
- Drawer1 / Drawer2の実キック
- 4文書の実レイアウト

従って `PRN-PROF-002` は「ソフトウェア実装・自動検証済み / 実機受入待ち」として管理する。
