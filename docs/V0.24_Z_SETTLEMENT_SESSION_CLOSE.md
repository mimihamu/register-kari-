# v0.24 Z精算による営業セッション終了・同日複数営業

## 1. 目的

v0.23までは、Z精算後に営業セッションを`Z_SETTLED`へ移し、別画面の「営業終了」を実行して`CLOSED`にする二段階方式だった。また、`business_sessions.business_date`が一意だったため、同じ営業日を再度開始できなかった。

v0.24では次の業務規則へ変更する。

- Z精算が正常に確定した時点で、対象の営業セッションを営業終了とする。
- Z精算レポート保存と営業終了状態更新は、同じSQLiteトランザクションで確定する。
- 同じ営業日でも、終了済みセッションとは別の新しい営業セッションを開始できる。
- 集計、冪等性、自動バックアップの識別は営業日だけでなく営業セッションIDを基準にする。

## 2. 状態遷移

### X点検

`OPEN -> OPEN`

X点検は現在値を記録するだけで、営業を終了しない。

### Z精算

`OPEN -> CLOSED`

Z精算レポート、現金実査額、過不足、終了担当者、終了日時を同一トランザクションで保存する。途中で失敗した場合はレポート保存と営業終了の双方をロールバックする。

旧`Z_SETTLED`状態は新規処理では作成しない。既存DBに残る旧状態は、起動時のスキーマ移行で`CLOSED`へ正規化する。

## 3. 同日複数営業

`business_date`は営業セッションを分類する属性として保持するが、一意制約は持たせない。

例：

- 2026-08-03 / セッションNo.100 / 10:00開始 / 15:00 Z精算・終了
- 2026-08-03 / セッションNo.101 / 17:00開始 / 23:00 Z精算・終了

両セッションは同じ営業日でも、売上、入出金、返品・取消、X点検、Z精算を別々に集計する。

同時に営業できるセッションは1件だけとし、部分一意インデックスで`OPEN`の重複を防止する。

## 4. DB移行

`BusinessSessionMultiplicityMigration`が以下を行う。

1. `business_date`単独の旧UNIQUE制約を検出する。
2. IDと全データを保持したまま`business_sessions`を再構築する。
3. 旧インデックス・トリガーを復元する。
4. 旧`Z_SETTLED`を`CLOSED`へ正規化する。
5. 営業日・開始日時の検索インデックスと、OPENセッション単一化インデックスを作成する。

既存の売上等に`business_session_id`がない場合は、作成日時がセッション期間内にあるものを優先して関連付け、同営業日内での誤帰属を減らす。

## 5. 冪等性

Z精算の永続操作キーを営業日単位から営業セッション単位へ変更する。

- 旧：`Z_SETTLEMENT:2026-08-03`
- 新：`Z_SETTLEMENT:SESSION:100`

同じセッションへのZ精算重複は拒否する。同じ営業日で新しく開始したセッションNo.101には、別のZ精算を実行できる。

## 6. 自動バックアップ

v0.23のZ精算後自動バックアップは維持する。

- Z精算と営業終了のDBコミット完了後にのみWorkManagerへ要求する。
- バックアップの関連情報には営業日、営業セッションID、Z精算IDを保存する。
- 自動バックアップ失敗で、完了済みのZ精算・営業終了を巻き戻さない。
- Google Drive等への自動アップロードは行わず、外部保存は引き続きユーザー操作とする。

## 7. 画面変更

- 「営業開始・終了」を「営業開始・状態」へ変更する。
- 別操作の「営業終了」ボタンを廃止する。
- Z精算ボタンを「Z精算して営業終了」と表示する。
- 営業状態、売上、精算、履歴に営業セッション番号を表示する。
- 営業終了後は、同じ営業日を指定して再度営業開始できることを案内する。
- 返品・取消画面の確定ボタンは、Z精算の表示変更の影響を受けず従来どおり処理種別を表示する。

## 8. 自動テスト

- X点検後はOPENのままになる。
- Z精算後はCLOSEDになる。
- Z精算キーは営業セッションID単位になる。
- 同じ営業日の異なるセッションは異なるZ精算キーになる。
- 新スキーマに`business_date`のUNIQUE制約がない。
- OPEN中は新規営業を開始できず、CLOSED後は開始できる。
- v0.14以降およびv0.21～v0.23のデータ保全・バックアップ試験を継続して通す。

## 9. 実機確認項目

- Z精算成功直後に販売が停止し、営業セッションがCLOSEDになること。
- Z精算途中失敗時に、Z精算レポートだけまたは営業終了だけが残らないこと。
- 同じ営業日で2回目の営業を開始し、売上が別セッションに記録されること。
- 1回目と2回目のZ精算票・履歴・自動バックアップが別セッションとして表示されること。
- v0.23以前のDB更新時に、旧データと旧Z精算済み状態が安全に移行されること。
