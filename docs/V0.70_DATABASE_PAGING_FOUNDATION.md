# v0.70 通常レシート再印字台帳 SQLite直接検索・ページング

## 目的

v0.69の運用台帳は直近最大1,000件をメモリへ読み込み、その範囲だけを画面内検索していました。長期運用で再印字要求が1,000件を超えると、古い履歴を検索できなくなるため、v0.70では検索条件をSQLiteへ直接渡す方式へ変更します。

## 基本方針

- 検索対象は `sale_receipt_reprint_requests` 全履歴。
- `print_jobs` / `sales` とJOINしたまま読み取り専用で検索する。
- 1ページ200件。
- SQLは `LIMIT ? OFFSET ?` を使用する。
- `pageSize + 1` 件を先読みし、次ページ有無を判断する。
- 検索文字列、状態、LIMIT、OFFSETはバインド値を使用する。
- LIKE検索では `\\` / `%` / `_` をエスケープする。
- 全体集計は別のSQL集計で行い、1,000件上限を設けない。
- 再試行・破棄・強制印刷は引き続き統合印刷キューだけで行う。
- 売上、税、支払、監査履歴を更新・削除しない。

## 検索対象

- 監査ID
- request UUID
- 売上No.
- 印刷job No.
- 再印字担当者
- 用紙幅
- 売上金額
- 印刷状態
- 最終エラー

## 状態フィルタ

- すべて
- 要対応: `RETRY` / `FAILED`
- 処理中: `PENDING` / `RETRY` / `FAILED` / `PRINTING`
- 完了: `COMPLETED`
- 破棄済み: `DISCARDED`

## データ保護

本変更は読み取り経路のみを変更します。`sale_receipt_reprint_requests`、`print_jobs`、`sales` に対するDELETE/UPDATEは追加しません。

## 実機確認

200件を超える履歴、1,000件を超える履歴、FAILED/RETRYが大量にある履歴での実機レスポンスは未確認です。
