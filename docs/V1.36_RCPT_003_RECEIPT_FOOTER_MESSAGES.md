# v1.36 RCPT-003 レシート店舗固定文

## 対象

Issue #137 #26 `RCPT-003 店舗固定文 最大12行・中央寄せ` を、正式仕様書 v2.5 と現行コードへ突合した結果を記録する。

## 正式仕様との補正

Issue #137 の「最大12行」は正式仕様書 v2.5 と一致しない。

- §8.2 店舗基本設定: `store.footerMessage1..5` はレシート末尾文、各 0～64文字、1行目の初期値はありがとう文、次回印刷から適用。
- §16.2 印刷設定: レシートのフッタメッセージは最大10行、空欄可、紙幅別プレビュー。
- §16.4 販売レシート印字順序: フッタは任意メッセージ・QR・再発行表示。再発行時は末尾にも再発行表示が必須。

印刷出力の具体的上限である §16.2 を優先し、v1.36では **最大10論理行** とする。各論理行は §8.2 に合わせて **最大64 Unicodeコードポイント** とする。

中央寄せは Issue #137 の既存意図および従来の「ありがとうございました」表示との互換のため維持するが、v2.5に新たなMUSTとして追加したものではない。

Issue #137 は対応アプリを「つぐレジ / つぐレジ＋」としているが、v2.5の売上管理アプリ責務には物理レシートプリンター設定の所有は確認できない。初版では印刷設定の正をつぐレジ本体に置き、つぐレジ＋へ重複したローカルプリンター設定を追加しない。

## 実装

`ReceiptFooterMessagePolicyV136` を `DocumentPrintSettingsV136.kt` に追加した。

- 最大10論理行。
- 1論理行最大64 Unicodeコードポイント。
- 空欄を許可し、空欄時は店舗固定文を印字しない。
- CRLF/CRをLFへ正規化。
- タブは空白へ変換し、その他の制御文字は除去。
- SALE_RECEIPT の未設定初期値は `ありがとうございました`。
- v1.36導入前のRCP-016で保存された最大200文字の旧フッタは、内容を落とさず64文字単位へ再配置して読み込む。
- 58mm / 80mmの双方で `ReceiptLineWrapV136` を使用し、紙幅を超える固定文を切り捨てず折り返す。
- 各物理行を紙幅内で中央寄せする。
- 設定画面に58mm / 80mmプレビューを表示する。プレビューと実印字は同じ折返し・中央寄せ処理を使用する。
- 保存時に10行/64文字制約違反を拒否し、画面へ理由を表示する。

`ReceiptRenderer` は従来の固定 `ありがとうございました` と `fit()` によるフッタ切り捨てを廃止し、`ReceiptFooterMessagePolicyV136.renderLines()` の出力を使用する。

後レシートでは店舗固定文の後に `【再発行】` を置くため、RCP-004で実装した「再発行表示が最終行」の契約を維持する。

`PrintQueueProcessor` のテスト/既定経路にも初期ありがとう文を設定し、RCP-016設定を明示的に渡さない既存経路でも従来表示を維持する。本番の自動印刷は `DocumentPrintSettingsStoreV136` の SALE_RECEIPT 設定を読み込む。
