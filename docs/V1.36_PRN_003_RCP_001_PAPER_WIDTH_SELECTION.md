# v1.36 PRN-003 / 正式仕様 RCP-001 ロール紙選択

## 対応関係

Issue #137 #21 の旧表記 `PRN-003 58mm / 80mm選択` は、正式仕様 v2.5 の **RCP-001 ロール紙選択** として実装・監査する。

## 正式仕様との突合

- 用紙幅は 58mm / 80mm の選択式とし、自由入力にはしない。
- 保存値は `paperWidthMm` / DB `printer_settings.paper_width_mm`。
- 58mm は論理32桁、80mm は論理48桁としてレシート描画へ渡す。
- 印刷ジョブ生成時に紙幅をsnapshotし、キュー処理時に後から変更されたライブ設定で上書きしない。
- 設定変更後のテスト印刷では、選択幅に応じたレイアウトを確認できること。
- 紙幅テストでは販売レシート、領収書、仮締め票、精算票の代表4文書を確認できるようにする。

## v1.36 実装

### 既存実装を正式仕様として固定

- `PrinterConfiguration.paperWidthMm` の既定値は80mm。
- 保存時に `58 || 80` を厳格検証する。
- 管理画面は `58mm` / `80mm` の選択ボタンのみを提供する。
- `ReceiptPaper.MM58` は32桁、`MM80` は48桁。
- 売上印刷ジョブ `sale_print_jobs.paper_width_mm` に生成時の幅を保存する。
- `PrintQueueProcessor` は `job.paperWidthMm` を有効設定へコピーして描画するため、キュー投入後に設定幅を変更しても既存ジョブの幅は変わらない。
- 業務帳票側の `document_print_jobs` も生成時の紙幅を保存する。

### v1.36 追加補修

従来のプリンターテストは区切り線が固定32文字だったため、80mmを選択しても48桁レイアウトを確認できなかった。

`PrinterPaperWidthTestV136` を追加し、保存済み設定から `ReceiptPaper` を決定して以下を印字する。

- 選択用紙幅（58mm / 80mm）
- 論理桁数（32 / 48）
- 選択幅と同じ長さの区切り線・桁ルーラー
- 販売レシート
- 領収書
- 仮締め票
- 精算票

これにより接続確認だけではなく、設定変更後の紙幅レイアウト確認を同じテスト印刷から行える。

紙幅連動テスト印刷の本体差し替えは一時GitHub Actionsで実施し、実装コミット `824ca215bd68427db1fbf57c410c3d8c8d10d463` 内で一時workflow自身を削除した。最終ブランチに一時workflowは残さない。

## 再印字時の扱い

既にキューへ投入済みのジョブは生成時の紙幅snapshotを維持する。一方、後から明示的に再印字を作成した場合は「新しい印刷ジョブ」として現在のプリンター紙幅をsnapshotする。これは紙幅変更後の再発行を扱う RCP-005 と整合させる。

## つぐレジ＋の責務

現行構成では物理プリンター接続・ESC/POS送信・紙幅設定の実行主体はつぐレジ本体であり、つぐレジ＋には独立した物理プリンターtransportを持たせていない。実際に消費されない重複 `paperWidthMm` 状態をつぐレジ＋へ追加せず、レジ端末側を物理印刷設定の正とする。将来の複数プリンター／プロファイル管理は別要件として扱う。

## 自動検証

`V136PrinterPaperWidthSelectionTest.kt` で以下を固定する。

- 58mm = 32桁 / 80mm = 48桁
- 正式4文書が紙幅テストへ含まれること
- 区切り線・ルーラーが選択幅と同じ論理桁数であること
- 保存値が58/80に限定され `paper_width_mm` へ保存されること
- 売上ジョブが紙幅snapshotを持ち、workerが `job.paperWidthMm` を使用すること
- 管理画面に58mm / 80mmの選択肢があること

## 実機確認へ残す項目

以下はコード・APK検証では確認済みとしない。

- 58mm実紙で32桁相当の印字幅・折返し
- 80mm実紙で48桁相当の印字幅・折返し
- 販売レシート / 領収書 / 仮締め票 / 精算票の実印字
- カット位置、余白、フォント幅
- 58↔80変更直後のテスト印刷

最終統合実機受入で確認する。
