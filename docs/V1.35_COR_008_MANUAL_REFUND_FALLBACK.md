# v1.35 COR-008 支払返金 — 手動返金方法フォールバック

## 目的

詳細仕様書 v2.5 `COR-008` のうち、元取引の支払内訳から返金方法を自動復元できない場合に、責任者が返金方法を明示選択し、その選択履歴を残す経路を追加する。

本差分は**決済端末そのものへの自動返金API実行を実装するものではない**。カード等の実返金が別端末操作を要する場合は、端末側で返金を完了したうえで本画面に返金方法を記録する。実決済端末との統合は実機・周辺機器工程で別途確認する。

## 既存動作

- 元売上の `sale_payments` に正の支払内訳がある場合、返金額を元支払方法へ比例配賦する。
- v1.34以前は支払内訳が空の場合、売上の支払表示から `CASH` または `OTHER` を推定して自動保存していた。

後者は `COR-008` の「自動返金できない場合は責任者が返金方法を選択」と一致しないため、v1.35で変更する。

## v1.35動作

1. 返品・取消の既存画面で担当者権限と責任者PINを検証する。
2. 元売上の正の支払内訳が取得できれば、従来どおり元支払方法へ自動配賦する。
3. 支払内訳が取得できなければ、現在の返品DBトランザクションを確定せず終了し、`ManualRefundMethodActivityV135` を開く。
4. 責任者が返金方法を選択する。
5. 選択時に `operation_audit` へ `REFUND_METHOD_OVERRIDE_SELECTED` を記録する。
6. 元の返品・取消画面へ戻り、同じ要求を再実行する。
7. 同一 `requestId`・同一返金額の選択だけを利用して返品/取消を確定する。
8. 確定後は一時選択を削除する。

## 安全策

- 返金方法選択画面は `android:exported="false"`。
- 選択要求は、`SecureOperationsCoordinator` が返品権限と責任者PINを検証した後にだけ生成される。
- 選択は `requestId` と返金額へバインドする。数量変更等で返金額が変われば再選択する。
- 選択の有効期限は10分。
- 監査履歴保存に失敗した場合は返金方法選択を確定しない。
- 返品/取消のDBトランザクションが成功するまでは一時選択を保持し、成功後にのみ削除する。
- 元支払内訳が正常な場合は新画面を挟まず、既存の自動配賦経路を変更しない。

## 選択可能な返金方法

- 現金
- カード（端末返金）
- 商品券
- 掛売
- その他

## 自動テスト

`V135ManualRefundFallbackTest` で以下を固定する。

- 正の元支払内訳があれば手動選択不要。
- 元支払内訳が空/0なら手動選択対象。
- 選択は返金額一致かつ対応方法でなければ無効。
- manager-approved runtime外の純粋計算では、既存テスト互換のfallbackを維持。
- SecureOperationsCoordinator / PartialReturn / Activity / audit / manifestの結線をソースゲートで確認。

## 実機確認へ繰り越す項目

- 元支払内訳欠落データで、返品/取消が一度ロールバックされ選択画面が開くこと。
- 責任者PINが不正な場合は選択画面が開かないこと。
- 選択後、同じ返品/取消を再実行すると選択方法で `reversal_payments` が保存されること。
- 返金額変更後は古い選択を使用せず再選択になること。
- 10分超過選択を再利用しないこと。
- `operation_audit` に元売上No・返金額・選択方法・従来推定・承認者が残ること。
- カード等の実返金運用とPOS記録が一致すること。
