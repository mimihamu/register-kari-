# v1.14 Outbox外部配送 lease所有権喪失フェンシング

## 背景
v1.13でSTAGED外部配送にworker token / leaseを導入しました。状態遷移は所有token一致時だけ許可されるため、古いWorkerが所有権を失った場合は `OutboxExternalDeliveryLeaseLostExceptionV113` が発生します。

v1.13ではこの例外も汎用配送失敗catchへ入り、さらに `markDeliveryFailure()` または `markDeliveryPaused()` を旧tokenで実行する経路がありました。二重更新自体はtoken条件で拒否されますが、二度目の所有権例外がWorker外へ抜けるため、異常終了扱いになり得ます。

## v1.14
- lease所有権喪失を汎用配送失敗より先に専用catchする。
- 通常配送失敗のDB状態遷移中に所有権を失った場合も専用処理へ切り替える。
- 所有権を失ったWorkerは `markSent` / `markDeliveryFailure` / `markDeliveryPaused` / `moveBackToPending` を再実行しない。
- 所有権喪失時はOutbox行・外部確定JSON・partialを削除／上書きせず、監査ログ `SYNC_OUTBOX_EXTERNAL_LEASE_LOST` を残して撤退する。
- local JSON存在確認から配送・SENT遷移までを同じ所有権例外ガード内へ入れる。
- v1.13のclaim/leaseとv1.06〜v1.12の外部JSON安全策は維持する。

## 正本
SQLite売上・Sales Journalおよび現在の所有Workerを正とします。所有権を失った旧WorkerはOutbox状態を訂正しようとせず、現所有Workerの処理を妨げません。
