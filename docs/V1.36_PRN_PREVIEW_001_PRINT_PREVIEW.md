# v1.36 #31 印刷プレビュー（正式仕様 v2.5 SCR-640 / §16.2）

## 正式仕様との突合

Issue #137 の旧ラベル `PRN-PREVIEW-001` は正式仕様 v2.5 の独立IDではないため、名称だけを根拠に実装を増やさない。

正式仕様で確認できる要件は以下。

- SCR-640 レシート設定は店舗情報、登録番号、メッセージ、ロゴ、文書別表示項目と **58mm / 80mmプレビュー**を持つ。
- §16.2 の共通「プレビュー／テスト印刷」は **58mm / 80mm切替**で、**設定保存前に実行可能**。
- レシートのフッタメッセージは紙幅別プレビュー対象。
- SCR-720画像スタンプは選択プリンタの実dot幅（初版標準58mm=384dot / 80mm=576dot）でプレビューする。

## 監査結果

v1.36開始時点で以下の部分プレビューは既に存在した。

- `ReceiptFooterMessagePolicyV136.preview()` による58mm / 80mm店舗固定文
- `ReceiptStampSettingsPanelV136` による58mm=384dot / 80mm=576dot画像スタンプ

一方、文書別設定の編集中内容を含めた文書全体の58/80切替プレビューは存在しなかった。

## 実装

### `DocumentPrintPreviewV136`

文書別設定から保存前プレビューを生成する共通層を追加。

- レシート
  - 本番印刷と同じ `ReceiptRenderer.render()` を使用
  - 別のレシートレイアウト実装を作らず、58/80の差を本番rendererと共有
  - サンプル取引に10%内税、8%軽減内税を含める
  - 編集中のheader / footer / copiesを反映
- 領収書 / 仮締め票 / 精算票
  - 既存 `PrinterPaperWidthTestV136` の同文書サンプルと58/80論理幅を再利用
- 点検票
  - 点検用サンプルを58/80論理幅で生成

### 設定UI

`DocumentPrintSettingsPanelV136` に以下を追加。

- 「印刷プレビュー（SCR-640・保存前）」
- 58mm / 80mm独立切替
- 58mm=32論理桁 / 384dot標準、80mm=48論理桁 / 576dot標準の表示
- 保存ボタンを押す前の編集中header / footerを即時反映
- 不正なレシート店舗固定文は保存と同じvalidationでプレビュー生成を拒否し理由を表示

## 自動テスト

`V136DocumentPrintPreviewTest.kt`

- 58mm=384dot / 32論理桁、80mm=576dot / 48論理桁
- レシートプレビューが本番 `ReceiptRenderer` の税シンボル・番号・header/footerを含むこと
- 58mm / 80mmで全行が論理幅内に収まること
- 保存していないheader変更が即座にプレビューへ反映されること
- レシート / 領収書 / 仮締め票 / 点検票 / 精算票の全種類で58/80プレビュー生成可能
- UIに保存前表示と58/80切替が存在すること

## 実機確認

画面プレビュー生成はソフトウェア検証可能だが、画面上の見え方と実プリンタ出力の最終一致は実機受入対象として残す。

- 58mm実印字と32論理桁 / 384dotプレビューの見た目一致
- 80mm実印字と48論理桁 / 576dotプレビューの見た目一致
- 採用機種固有の印字可能dot幅を設定する場合の画面幅一致
- フォント、濃度、画像スタンプ、カット位置等の物理差

従って #31 はソフトウェア実装・自動検証後も、実機一致確認は別途「実機受入待ち」とする。
