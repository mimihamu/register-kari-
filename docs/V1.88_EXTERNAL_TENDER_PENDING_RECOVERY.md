# v1.88 外部決済：確認待ちの永続化と二重決済防止

## 前提
カード／電子マネー／QRの支払入力は、現状では決済端末とのAPI連動ではなく手動の結果確認方式。本改修は外部端末の決済を開始・実行・取消するものではない。操作者の確認を売上入力へ反映する際の二重入力を防止する。

## 処理
1. 非現金決済の金額を指定すると、レジは支払済み扱いにせず、まず `payment_external_pending_v188` に会計キー・カート指紋・支払方法・金額・時刻をSQLite保存し、監査ログ `PAYMENT_EXTERNAL_HANDOFF_STARTED` も同一トランザクションで保存。
2. 保存完了後のみ端末での操作を案内。レジには結果確認用のダイアログを表示。
3. 端末で成功が確認できた場合は、確認済み操作として支払配分に追加。未実行・取消済みの確認が取れた場合は支払を加えず確認待ち記録を終了。どちらも監査ログとデータ更新を同一トランザクションで実行。
4. 結果不明ならダイアログを閉じられず、再決済・販売変更・会計確定は停止。端末・加盟店の取引履歴を照合する必要がある。端末やアプリが再起動しても保留中の記録は復元。
5. `PaymentDraftStore.save/cancelAllocation/clear` と `RegisterDatabase.saveSale` は確認待ちが存在する場合に処理を拒否。未確定データを直接消せない。

## 安全性と制約
- クレジット・電子マネー・QRのみ外部端末の対象。現金や掛売・商品券は従来の入力経路を維持。
- 決済済みの自動検出・真正性確認はできない。確認ボタンは担当者が端末履歴を照合した旨の**自己申告**。端末取引番号・カード会社照会・端末側の取消実行は別途実装が必要。
- SQLiteへの書込が失敗すると、操作結果を画面へ反映しない。
- 実機検証：端末決済直後のプロセス強制終了、無通信、端末二重処理防止、旧版APK更新、外部決済端末側履歴との照合。正式受入未完了。
- 自動テスト：`V188ExternalTenderPendingRecoveryTest.kt`（種別分類・整合性・監査順序・フェイルクローズ）と累積ユニットテスト。


## 追加：直接保存経路の封鎖
`PaymentDraftStore.save()` は新たに追加されるCARD/ELECTRONIC_MONEY/QRの支払配分を拒否。未確定データを外部決済待ち台帳に保存した上で、監査付き `resolveExternalTender()` だけが支払を確定できる。旧版由来の既存カード配分は保持し、現金の追加など通常の続きは妨げない。
