# Google連携が「キャンセル」に見える場合の調査と表示修正

現行のPOS/Plus両アプリでGoogle AuthorizationClientの認可画面がActivity.RESULT_CANCELEDまたは不完全なIntentを返すと、以前は実際の操作に関係なく「アカウントの選択がキャンセルされました」と表示していた。

## 対応
- 認証処理から結果が返らなかったときは「連携を完了できませんでした」と表示し、resultCodeを案内する。
- IntentにGoogle Play開発者サービスのApiExceptionがある場合は先に復元し、DEVELOPER_ERROR（通常コード10）をAndroid OAuth設定不一致として扱う。その他のコードも識別する。
- かんたん接続およびPOSアカウント画面で認可が完了しなかったときのみ「Google Cloudの初期設定」導線を表示する。既存の詳細設定・診断機能は維持する。
- UIへのエラー詳細にアクセストークン、完全なメールアドレス、認可Intent情報を含めない。
- Google側OAuthクライアントの登録やテストユーザー追加は、アプリでは代行できない。Google Cloud Consoleにて管理者が実施する。

## 実機用（開発版APK）
| アプリ | OAuth Androidクライアント パッケージ名 |
| --- | --- |
| つぐレジ | `jp.co.tenposinfo.register.dev` |
| つぐレジ＋ | `jp.co.tenposinfo.register.plus.dev` |

共通開発APK署名SHA-1：`5C:CC:D8:26:5E:BF:69:FF:36:EC:9D:37:6E:8C:AC:2A:DE:DB:89:44`。
これは前回のビルド済み実APK内のv2署名証明書を読取り算出した値。新APKでも同じ署名を独立確認する。

設定手順：Google Auth PlatformのクライアントでAndroidを2件作成。ブランディング、対象ユーザー（外部・テスト運用なら対象Googleアカウントをテストユーザーへ追加）、データアクセス（`https://www.googleapis.com/auth/drive.file`）、Google Drive APIを設定。

**実機未確認**：Google同意画面、Google Cloud実設定、アカウント選択、端末のGoogle Play開発者サービス、実際の認証原因。結果コード0だけでOAuth設定ミスと断定しない。
